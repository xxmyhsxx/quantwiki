# raw 保存规范

raw 保存来源原件和必要的来源记录；知识解释、推导、更正与评价放在 Wiki 或研究记录。

## 目录

```text
raw/papers/<入库日期>/<简称>/
raw/articles/<入库日期>/<简称>/
raw/repositories/<入库日期>/<仓库名>/
```

入库日用 `YYYY-MM-DD`，未知时用 `unknown-date`；获取时间另记。改名或修复不改变来源身份与入库日。

## 每份资料只存一份正文

- 论文保存作者 PDF；取得作者 TeX 源包、公开评议或独立附件时按实际版本保存。
- 网页保存实际取得的正文及必要原图；多页文档每页存一份。原本是 PDF 的讲义直接保存 PDF。
- 代码保存固定 commit 的源码；子模块按父仓库 pin，LFS 指针和实体分别说明。用于核对的原始归档、Git 对象与展开源码可以同存，注明关系。
- 不生成全文读本、公式册、图片清单、整套 PDF 页图或重复导航。需要解释的公式、图片和原文疑点在知识页或现有研究记录承接。
- 不保存本地运行缓存、构建产物或重复备份。上游原有文件与有实际用途的不同版本不按重复项删除。

## 条目 README

只回答：哪份来源、保存了哪些文件、核验范围与缺失是什么。

YAML 保留 `source_id`、`kind`、`title`、`url`、`acquired_at`、`added_on`、`version`、`tags`；未知信息写 `null`，不猜测。代码版本用完整 commit，网页用明确版本或快照；tags 用 1–4 个已有主题词。

正文列必要文件、原件校验值和实际限制，不重写摘要、方法介绍、通用规范或逐次操作记录。源码保存、构建成功和运行验证分别说明。

## 无链接存储

仅根目录 README、LOG 和条目 README 保留 Markdown；地址、文件位置用代码文本，不放可点击链接或图片、附件嵌入。

作者 Markdown 按原文件名追加 `.txt`，正文、字节与权限保持原样；Markdown 符号链接按原名追加 `.symlink.txt` 保存目标文字。需要恢复上游树时，在临时副本还原名称与链接。其他原件保持原样；目录符号链接必须指向 raw 内实际目录。

## 去重与检查

按来源身份与确定版本去重，同版材料复用已有条目。删除前保留独有原件、版本依据与必要记录，同步 Wiki `sources` 的实际路径；不得用新版静默替代旧版证据。

收录或清理后运行 `python3 -B .agents/skills/wiki-review/scripts/check_wiki.py --root . --raw-links-only`；涉及来源删除或改名时再检查 Wiki 来源登记。lint 检查存储、链接和已知派生文件，不证明原件完整或科学结论正确。

批次变动简记于 `LOG.md`。原件留在本地，不随 Git 分发；本规范纳入 Git。
