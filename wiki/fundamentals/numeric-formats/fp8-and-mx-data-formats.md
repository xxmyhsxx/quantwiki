# FP8 与 Microscaling 数值格式

整数网格不是低精度表示的唯一形式。浮点格式用指数补充动态范围，块内共享尺度（Microscaling）进一步把有限位宽分配到一组元素上。哪些数值可表示、缩放放在哪一层、元数据占多少空间，直接决定量化器能否复用以及后端能否真正加速。

本页依据 FP8 Formats for Deep Learning（arXiv:2209.05433，下称 F，全文研读；抽取文本缺表格，已回查作者 TeX 源码核对）与 Microscaling Data Formats（arXiv:2310.10537，下称 M，格式定义、值语义、转换算法与计算流局部研读），并定向核对 llama.cpp 固定快照 b820cc8e 的块结构定义。OCP FP8 与 Microscaling 规范原件未获取，涉及规范细节处只按论文转述，不冒充规范原文。仿射整数网格、分组与元数据的基本定义见 [均匀量化与分组](../quantization/uniform-quantization-and-groups.md)。

## 1. 为什么需要浮点低比特表示

仿射整数格式用均匀网格覆盖一个范围，范围由 min–max 或校准决定。它的动态范围问题在于：一个 tensor 内的极值会把步长拉大，常见值附近随之变稀。浮点格式把数值写成 $\pm m\cdot 2^{e}$，指数部分随数值大小移动，因此同样 8 bit 可以覆盖比 int8 更宽的动态范围。

F 与 M 都强调低比特浮点仍需要缩放，区别是缩放发生在更高精度一侧：先把张量乘上因子移入可表示范围，转换成低比特格式，运算后再除回。F §2 指出这与 FP16 混合精度训练的 loss scaling 类似，但溢出处理相反：FP16 自动混合精度在溢出时跳过权重更新并缩小因子，FP8 因动态范围窄、溢出更常见，采用饱和到最大值。

| 缩放手段 | 可调范围 | 粒度 |
|---|---|---|
| 可编程指数偏置 | 只能是 2 的幂 | 每种类型或张量 |
| 逐张量缩放因子 | 任意实数（以更高精度存储） | 每个张量 |

F §3.2 选择不偏离 IEEE 偏置约定，把逐张量缩放留给软件实现，理由是任意实数因子比只有 2 的幂的偏置更灵活。这一取舍划定了格式与实现的分工：格式规定可表示点，缩放策略由量化流程决定。

## 2. E4M3 与 E5M2 的位模式

FP8 由两种编码组成，名称标明指数位 $E$ 与尾数位 $M$。以下为 F 表 1 的原始内容，$S$ 为符号位。

| 项目 | E4M3 | E5M2 |
|---|---|---|
| 指数偏置 | 7 | 15 |
| 无穷 | 不表示 | $S.11111.00_2$ |
| NaN | $S.1111.111_2$ | $S.11111.$ 后接 01、10 或 11 |
| 零 | $S.0000.000_2$ | $S.00000.00_2$ |
| 最大规格数 | $1.75\times 2^{8}=448$ | $1.75\times 2^{15}=57{,}344$ |
| 最小规格数 | $2^{-6}$ | $2^{-14}$ |
| 最大次规格数 | $0.875\times 2^{-6}$ | $0.75\times 2^{-14}$ |
| 最小次规格数 | $2^{-9}$ | $2^{-16}$ |

E5M2 完全遵循 IEEE 754 的特殊值约定，可视为尾数更少的 IEEE 半精度，因此与 FP16 互转简单。E4M3 放弃了无穷，并把 NaN 压缩到单一尾数模式，收回的位模式用于正规数值：动态范围从 17 个 binade 扩到 18 个，新增 $1111_2$ 指数下的七个量级（256、288、320、352、384、416、448）；若不这样改，最大值只能到 240。

F §3.1 解释了为何不再多收一个量级：如果零和 NaN 各只保留一个编码，可以获得 480，但会破坏正负表示对称性，使依赖该性质的实现失效，例如用整数指令比较和排序浮点数。作者的判断是 448 到 480 的收益不值得破坏 IEEE 约定，不是 480 不可表示。

**教学对照。** 同一个实数 $2^{10}=1024$：E4M3 的最大规格数为 448，超过后必须靠缩放因子下压；E5M2 的最大规格数为 57,344，无需缩放即可表示，但要付出尾数位少一位、相对精度更差的代价。哪个更合适取决于张量的动态范围与所需有效位数。

## 3. 训练与推理中的证据

F 的实验统一使用**模拟 FP8**：把张量裁剪到 FP8 可表示值（含缩放与饱和），算术仍在 FP16 或 bfloat16 中完成。作者给出两条理由：论文关注交换格式本身，且当时对大模型模拟不支持运算代价过高。因此下表说明的是数值格式的影响，不是 FP8 硬件内核的性能证据。

训练侧只把 GEMM 类运算（卷积、矩阵乘）的输入张量与激活梯度裁到 FP8，输出保留高精度，其余超参与 FP16/bfloat16 基线一致（F §4.1）。图像分类（ILSVRC12 top-1）与语言翻译（WMT 2016 en–de，BLEU）结果：

**缩放粒度的影响。** F 图 2（1.3B 模型）比较不同指数偏置且不做校准时的困惑度：只量化 GEMM 输入时，偏置落在 $[7,10]$ 内有多组接近 bfloat16 基线 10.19；若把残差加法输入也量化到 FP8，则没有任何单一偏置可用，偏置 7 也只有 12.59。改用逐张量缩放因子后，GEMM-only 与 GEMM+残差分别为 10.29 与 10.44。也就是说，同一类型的所有张量共用一个固定偏置，在扩大量化范围后不再够用。

## 4. Microscaling：块内共享尺度

M §2 把 MX 的基本单元定义为“一个共享尺度加 $k$ 个元素”：数据单元称为 MX block，由块大小 $k$、尺度数据格式和元素数据格式共同定义；$k$ 个元素共享同一个元素格式，块内每个数满足 $v_i = X P_i$。布局不被规范强制，尺度可以与元素连续存放，也可以分开存放。

值语义（M §2.1）：若 $X$ 为 NaN，则块内 $k$ 个值全为 NaN，与元素的编码无关；否则每个元素可以各自编码 NaN；$X$ 本身不编码无穷，元素可以。若 $|XP_i|$ 超过 FP32 的最大量级，结果由实现定义。

具体格式（M 表 1）统一使用 E8M0 作为共享尺度。E8M0 只有 8 位指数、没有尾数，因此尺度是 2 的幂：块内数值的适配完全由元素格式承担，尺度解码也很便宜。

| 格式 | 块大小 | 尺度格式 | 尺度位宽 | 元素格式 | 元素位宽 |
|---|---:|---|---:|---|---:|
| MXFP8 | 32 | E8M0 | 8 | FP8（E4M3 / E5M2） | 8 |
| MXFP6 | 32 | E8M0 | 8 | FP6（E2M3 / E3M2） | 6 |
| MXFP4 | 32 | E8M0 | 8 | FP4（E2M1） | 4 |
| MXINT8 | 32 | E8M0 | 8 | INT8 | 8 |

**转换算法（M 算法 1）。** 记 $\mathrm{emax}_{elem}$ 为元素格式中最大规格数的指数，则

$$shared\_exp=\left\lfloor \log_2\left(\max_i|V_i|\right)\right\rfloor-\mathrm{emax}_{elem},\qquad X=2^{shared\_exp},\qquad P_i=\mathrm{quantize}(V_i/X).$$

减去 $\mathrm{emax}_{elem}$ 的作用是把输入的指数上界对齐到元素格式最大的 binade，从而用满元素格式的指数范围。M §3 补充三处实现细节：量化 $V_i/X$ 时，超出元素范围的正规数按符号饱和，无穷与 NaN 不裁剪；该实现把 FP32 次规格数对应的 $P_i$ 置零，这一步不在 OCP 规范中，只是为简化算法；规范允许实现定义其他转换流程，算法 1 只是可用示例。

**转置与量化的顺序不可交换。** 多维张量必须为共享尺度选择主轴，通常取矩阵乘的归约维；对 2D 矩阵，尺度可以按行或按列共享。先转置再量化与先量化再转置会得到不同结果（M §3），因此量化的 $W$ 与其转置必须分别存储为两个张量。训练的正反两向都需要它，这个存储代价是该格式的直接后果；两个张量不必同时在常驻内存中，除非前向与反向被极细地交错执行。

**计算流（M 图 2）。** 点积类运算（matmul、convolution）的两侧输入转成 MX 格式后计算；向量类运算（LayerNorm、Softmax、GELU、残差加法）用 bfloat16 或 FP32；点积输出回到标量浮点格式；权重保留一份 FP32 主副本用于更新。这与 [三类执行路径](../../implementation/quantized-matmul-scaling-execution.md#3-三类执行路径) 中“压缩存储、高精度计算”的形态一致，区别在于压缩与解码作用在块级尺度上。

M 的作者报告（结果表未逐项核对）：MXINT8 在若干推理基准上可直接替代 FP32 且差异落在标准差内；MXFP6 在量化感知微调后接近 FP32；MXFP6 支持 6 bit 权重、激活与梯度的生成式语言模型训练与 FP32 持平；MXFP4 权重配 MXFP6 激活与梯度只有小幅损失。这些是作者在自建模拟库上的报告，不是本项目复现，也不代表具体硬件吞吐。

## 5. 从标准到实际存储格式

MX 已经进入推理栈的存储格式。llama.cpp 固定快照 b820cc8e 的 ggml/src/ggml-common.h 中：

```c
#define QK_MXFP4 32
typedef struct {
    uint8_t e;              // E8M0
    uint8_t qs[QK_MXFP4/2]; // 4-bit E2M1
} block_mxfp4;

#define QK_NVFP4 64
#define QK_NVFP4_SUB 16       // per-group scales
typedef struct {
    uint8_t d[QK_NVFP4/QK_NVFP4_SUB]; // UE4M3 scales, one per 16-element sub-block
    uint8_t qs[QK_NVFP4/2];           // packed 4-bit E2M1
} block_nvfp4;
```

两者都是“块级尺度加 E2M1 元素”：MXFP4 用 32 元素块配一个 E8M0 尺度，共 $8+128$ bit，即 4.25 bit/weight；NVFP4 把块缩到 64 元素并把尺度改为四个 UE4M3 子块尺度（16 元素一个），换取更细的范围适配，代价是更多元数据。读取与打包路径属于 [GGUF 块量化存储格式](../../implementation/gguf-block-quantization-formats.md) 的范围。

## 6. 与整数网格的适用边界

| 问题 | 仿射整数网格 | FP8 / MX |
|---|---|---|
| 可表示点 | 等间距，范围由校准确定 | 每个 binade 内等间距，指数随量级移动 |
| 零的表示 | 可由 zero-point 精确表示 | 有符号零位模式 |
| 动态范围 | 受范围选择限制 | 宽，E5M2 有 32 binade |
| 元数据 | scale/zero-point，可分组 | 逐张量缩放；MX 另有块级尺度 |
| 硬件路径 | INT8/INT4 张量核心与整数累加 | 依赖支持 FP8/FP4 的硬件 |

浮点格式的优势是动态范围，以及与训练共用类型；代价是有效尾数位更少、需要硬件支持。把 FP8 的结论直接搬到 INT4 不成立，把 MX 块尺度当作分组仿射量化也不成立：前者位宽不同，后者的尺度是 2 的幂且只调指数。

## 7. 局限与未验证

- **模拟与硬件分离。** F 的训练与推理结果来自模拟 FP8，算术在宽精度完成；真实 FP8 张量核心的数值行为、吞吐与累加精度没有在本轮材料中验证。
- **规范原件缺失。** OCP FP8 与 Microscaling 规范未获取，特殊值、舍入模式与转换语义以两篇论文为准；论文明确允许实现定义，实际后端行为需另查。
- **表格核验范围。** F 的全部表格已回查作者 TeX 源码；M 的推理与训练结果表未逐项核对，本页只记录作者的定性结论。
- **未运行。** 本轮没有运行模型、量化工具或硬件性能测试，也没有验证 llama.cpp 中 MXFP4/NVFP4 的读写路径是否完整可用。
