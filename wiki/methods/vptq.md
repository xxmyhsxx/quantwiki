# VPTQ：同列向量量化、二阶反馈与码本成本

VPTQ 把同一输入列内的多个输出权重组成一个向量，用索引选择可学习码本中的中心，再把当前列的误差反馈到后续列。这个方向让当前向量的候选共用一个二阶系数，因此选码可用欧氏最近距离；列间输入相关性仍通过反馈起作用。它还用 Hessian 对角项加权初始化码本，并按配置加入残差码本、离群列码本与微调。

本页依据 arXiv:2409.17066v2（`https://arxiv.org/abs/2409.17066v2`） 正文、算法1–2及必要附录 A–D，回查关键 PDF 公式与表2–3、8–11。数值为作者报告，规范推导与教学算例另行标明。本地已收录材料中没有匹配的 VPTQ 作者仓库，本轮未核实际打包或运行模型/GPU。前置见[码本与位预算](../theory/codebook-quantization-and-bit-budget.md)、[层输出重构与二阶补偿](../theory/layer-reconstruction-second-order-compensation.md)。

## 1. 向量方向决定当前要比较的误差

采用 $W\in\mathbb R^{M\times N}$，行对应输出、列对应输入通道。VPTQ 的长度 $v$ 向量是 $W_{m:m+v,q}$：固定输入列 $q$，沿输出行分组。每个向量存一个码本索引，一列量化完后向未量化列传播误差。算法1把输入列分成宽度 $B$ 的处理块；块内依次选列和反馈，块结束再批量更新后续列。$v$ 是一次码字的输出维度，$B$ 是反馈调度的输入列块宽，二者不能互换。（§3.1、算法1。）

“Channel-Independent”指这种选码分解，**不表示各输入列统计独立，也不表示可以省去列间反馈**。论文将它与 GPTVQ 同时处理多个输入列的方向作比较；这个结构差别本身并不能证明长向量 GPTVQ 必然更差，仍要看具体搜索、码本、更新与评测条件。

下面按标准层输出二次重构作整理者展开。令 $F$ 是当前仍可调整的输入列，$H_F$ 为正定的局部重构 Hessian，$A=H_F^{-1}$；当前自由权重已处于先前量化约束下的连续最优点。把列 $q$ 固定为候选，增量 $a=\widehat W_{:,q}-W_{:,q}$，则

$$
\min_{\Delta W_F}\frac12\operatorname{tr}(\Delta W_F H_F\Delta W_F^\top),
\quad \Delta W_{:,q}=a
\quad\Longrightarrow\quad
\Delta W_F^*=\frac{aA_{q,:}}{A_{qq}},\qquad
\Delta L^*=\frac{\|a\|_2^2}{2A_{qq}}.
$$

一列内各输出段共用同一个正数 $A_{qq}$。固定码本、各段独立选码时，只需对反馈调整后的向量选择欧氏最近中心。二阶信息决定补偿方向和列的代价，却不改变这个固定列内的最近中心排序。公共页[同列向量推导](../theory/layer-reconstruction-second-order-compensation.md#3.1%20%E5%90%8C%E5%88%97%E5%90%91%E9%87%8F%E4%B8%BA%E4%BB%80%E4%B9%88%E4%BB%8D%E5%8F%AF%E4%BD%BF%E7%94%A8%E6%AC%A7%E6%B0%8F%E6%9C%80%E8%BF%91%E4%B8%AD%E5%BF%83)说明该结论依赖各输出行共享输入 Gram；它不是任意网络损失 Hessian 的普遍性质。

原文有几个不能直接当作可执行公式的地方：式1约束写成 $\Delta W=0$，按字面只允许零变化；§3.1 的反馈式乘 $H_{q,:}$，算法1却使用 $H^{-1}_{q,:}$；拉格朗日式的系数和矩阵归约也未保持一致。本页上式是明确约束下的规范推导，保留这些原文差异。算法1还未写清条件逆矩阵的更新约定；不能把始终不变的原始逆矩阵、更新后的条件逆及 Cholesky 因子混用，更不能据此声称已核作者实现。

## 2. 加权初始化与欧氏选码为什么不矛盾

§3.2.1 把重构二次型分为对角项与列间交叉项，用前者初始化共享码本。若 $u_t$ 来自输入列 $q(t)$，初始化目标可规范写成

$$
\min_{C,z}\sum_t H_{q(t)q(t)}\|u_t-C[z_t]\|_2^2.
$$

这是整理者对论文加权 K-means 思路的标量展开。来自不同列的样本有不同权重；固定分配后，中心是加权均值，所以高敏感列能更强地影响中心位置。为一个固定向量选择中心时，其正权重又对所有候选相同，仍不改变最近中心排序。**初始化在多个样本之间分配重要性，选码在一个样本的候选之间比较，两者的比较对象不同。**

论文用 Hessian 近似对角占优作为初始化动机，没有给出所有模型/校准分布都满足的保证。初始化忽略的交叉项并未凭空消失；后续列间反馈正是另一阶段。加权聚类也不保证找到完整离散重构目标的全局最优。展开与教学例见[公共页 §3.2](../theory/layer-reconstruction-second-order-compensation.md#3.2%20%E5%85%B1%E4%BA%AB%E7%A0%81%E6%9C%AC%E7%9A%84%E5%8A%A0%E6%9D%83%E5%88%9D%E5%A7%8B%E5%8C%96%E4%B8%8E%E9%80%89%E7%A0%81%E6%98%AF%E4%B8%A4%E7%A7%8D%E6%AF%94%E8%BE%83)。（§3.2.1。）

## 3. 残差与离群列怎样改变表示

残差量化先选基础中心 $C_1[z_1]$，再对 $u-C_1[z_1]$ 选第二个中心；解码必须取和：

$$
\widehat u=C_1[z_1]+C_2[z_2].
$$

它增加一个索引、一个码本及解码加法。算法2的 residual 分支只写了对残差运行 VPTQ 的赋值，没有显式写回基础项相加；本页按 §3.2.2 的“组合多个中心重构”解释，不能将最终权重替换成只有残差的结果。顺序残差编码与联合优化全部加性索引的区别见[公共码本页 §3](../theory/codebook-quantization-and-bit-budget.md#3.%20%E6%AE%8B%E5%B7%AE%E9%87%8F%E5%8C%96%E4%B8%8E%E5%8A%A0%E6%80%A7%E9%87%8F%E5%8C%96%E7%9A%84%E5%8C%BA%E5%88%AB)。

离群值路径依据高敏感输入通道分出少量列/矩阵块，使用独立中心表和不同的向量长度、中心数量。它是另一个量化表示，并非直接保留 FP16 的稀疏旁路。正文关联激活离群值与较大的 $H_{qq}$，但没有细化完整选择分数和阈值算法；不能自行补成一个已核的 top-k 规则。（§3.2.3、§4。）

更大的矩阵还可分成多个组，各组拥有独立码本。组数增加会扩大存表成本；原文 group 切片混用 $M$ 与列下标，当前材料不足以据此确认完整分组轴、尾组 padding、索引打包与重排布局。

## 4. 微调是质量结果的一部分

算法2先处理各线性算子的离群列、主体与可选残差，再按配置作 layer-wise fine-tuning；所有层完成后还可作 end-to-end fine-tuning。层级微调以原模型和量化模型的层计算 MSE 为目标，论文只列出更新归一化算子参数与中心，没有把离散索引列为该阶段可训练参数。（§4。）

校准采用128个随机 C4 片段。附录 B 的层级微调使用128个 C4 训练样本对应的全精度层输入/输出，每层100次迭代；表9给出8×H100环境与各模型学习率、batch size。校准片段长度及完整端到端微调配方不能由评测 context length 或这100次层级迭代补齐。

表10的 LLaMA-2-13B 消融使用4096长度的 WikiText-2/C4，三行都为 $v=6,k=4096$、2.02 bit，无离群列和残差码本：

| 配置 | WikiText-2 PPL | C4 PPL |
| --- | ---: | ---: |
| 不微调，行4 | 6.29 | 8.29 |
| 加层级微调，行11 | 6.07 | 7.64 |
| 再加端到端微调，行12 | 5.32 | 7.15 |

主表2同一模型的2.02 bit、5.32/7.15结果对应含端到端微调的配置，不能全部归因于基础 VPTQ 选码。另一方面，表10行4与行5在所列参数相同、均不微调时，启用/关闭 channel-independent 的 WikiText-2 PPL 为6.29/7.25；这是该消融支持的局部收益，不能替代所有向量量化算法的公平比较。

## 5. 两位索引不等于相同的总存储

只有一个 $k$ 项、$v$ 维码本时，理想主体索引为 $\log_2(k)/v$ bit/weight；每张 FP16 中心表另占 $16vk$ 位。论文 §2.2 的 $4096\times4096$ 矩阵、$v=8,k=256$ 算例，索引与码本合计为1.001953125 bit/weight，约1.002；原 FP16 与它的比值约15.97。

主体、残差和离群列的覆盖不同，应先按各自权重比例计索引，再加每组实际中心表。通用式与例外覆盖条件见[公共位预算 §5.1](../theory/codebook-quantization-and-bit-budget.md#5.1%20%E7%A6%BB%E7%BE%A4%E5%80%BC%E3%80%81%E6%AE%8B%E5%B7%AE%E5%92%8C%E5%88%86%E7%BB%84%E6%80%8E%E6%A0%B7%E5%85%B1%E5%90%8C%E8%AE%A1%E8%B4%B9)。附录 C.2 把离群索引写成 $\log_2(k_0/v_0)$，正确的逐权重计数应为 $\log_2(k_0)/v_0$；该节另有 $\log_2(k_1/v_1)=2$ 的同类括号问题。表中 $k_2=-1$ 只是关闭残差的标记，不能代入对数或当作负数量中心。

以下都为2 bit/weight的理想主体索引，但 FP16 中心表差别很大：

| 向量配置 | 中心表总大小，每一组 |
| --- | ---: |
| $v=6,k=4096$，单表 | 48 KiB |
| $v=12,k_1=k_2=4096$，基础加残差 | 192 KiB |
| $v=8,k=65536$，单表 | 1 MiB |

表10的 total bitwidth 按一个 transformer block 计入4个 attention linear 与3个 FFN linear。它不是完整 checkpoint 字节或运行峰值内存。表8的组数、离群比例与模型矩阵尺寸也会改变总体开销，不能从“2-bit”标签恢复唯一存储布局。（附录 B、C.1–C.2。）

## 6. 质量结论依赖具体配置和比较范围

论文报告 LLaMA-2/3 与 Mistral 的 weight-only 量化，以 WikiText-2/C4 PPL 和五项零样本常识任务平均分衡量质量。下表选取表2–3的原数值，不把不同位预算、微调配置和基线来源视为完全相同条件。

| 模型与配置 | 位宽 | WikiText-2 PPL | 五项 QA 平均分 |
| --- | ---: | ---: | ---: |
| LLaMA-2-7B，QuIP# / VPTQ | 2.00 / 2.02 | 6.19 / 6.13 | 58.2 / 58.2 |
| LLaMA-2-70B，AQLM / VPTQ | 2.07 / 2.07 | 3.94 / 3.93 | 68.8 / 68.6 |
| LLaMA-3-8B，FP16 / VPTQ | 16 / 2.08 | 6.14 / 9.29 | 68.6 / 60.2 |
| Mistral-7B，AQLM / VPTQ | 2.01 / 2.04 | 6.32 / 5.64 | 62.2 / 63.2 |

表3的 LLaMA-3 PPL context 为2048，Mistral 为8192；不能与其他 context 的附表或外部数字直接混排。结果支持所列配置的低位宽质量，但并非所有指标都胜出：70B 示例的 PPL 略低、QA 略低；Mistral 4 bit 时，GPTQ/VPTQ 的 QA 为68.4/68.2。§5 的7B“降低0.5”表述也不等于表2 QuIP# 6.19→VPTQ 6.13的差值，本页保留可定位的表内数字。

附录 A.1说明基线有作者 checkpoint、公开代码重跑和原论文转引等不同来源。LLaMA-3 未列 QuIP#/AQLM，不能把缺项解释为它们性能较差；GPTVQ 吞吐/内存缺项是论文作者未能加载相应量化器，不能解释为算法无法执行。完整微调/后端/评测协议一致性仍是方法比较的必要条件。

## 7. 运行路径与测量边界

附录 D.2 描述两条路径：较长 prompt 先把索引与中心恢复为 FP16 权重，再调用 `torch.matmul`；decode 将反量化与 GEMV 融合为 QGemv，避免反复写出并读回 FP16 权重。因此压缩表示与实际乘法 dtype、运行时临时权重并非同一对象。当前是论文实现描述，没有匹配源码足以确认 kernel 布局、累加精度或分派条件。

附录 D.1 的吞吐协议为1-token prompt、生成256个 token，按输出 token 的时间计算 tok/s；表2明确使用 naive Torch/Triton，没有 CUDA graphs、FlashAttention 或 Torch compile，并指出 QuIP#/AQLM 在完整优化下可以更快。该处没有完整标明推理 batch/GPU 配置，不能用量化成本的GPU数或“1个prompt token”补成推理 batch=1。

表2的可定位比较包括：LLaMA-2-13B 同为2.18 bit，VPTQ/AQLM 为18.5/16.5 tok/s，约1.12倍；70B 同为2.07 bit，为9.7/6.9，约1.41倍。因此论文的“1.6–1.8倍”概括不能套到全部配置。表11另列13B、2.02 bit为32.09 tok/s，而主表2为26.9；这里保留为两组报告，不合并成同一 checkpoint 的确定性能。

正文把 QuIP# 的 Hadamard 开销概括为 $O(n^2)$，这只对应显式稠密乘法，不能代表[快速 Hadamard 的 $O(n\log n)$](../theory/orthogonal-rotation-and-hadamard-quantization.md#2.%20%E4%B8%BA%E4%BB%80%E4%B9%88%E4%BD%BF%E7%94%A8%E5%BF%AB%E9%80%9F%E5%93%88%E8%BE%BE%E7%8E%9B%E5%8F%98%E6%8D%A2)。受限 backend 的速度差也不足以单独归因为旋转算法。

`cost(h)` 默认称为4×80GB A100上的量化时间，但附录 A.1 的 GPTQ/GPTVQ 使用单张 A100，QuIP# 70B为转引估计；层级微调表9又采用8×H100。70B VPTQ/AQLM 的19/183小时约为10.4%，这是所列时间之比，不能据此宣布全部配置具有同一硬件、相同阶段覆盖的 GPU-hour 优势。总位数、运行显存、吞吐和离线量化成本应分别报告。

## 8. 与已有路线怎样衔接

[GPTQ](gptq.md)提供逐列二阶反馈的基础；VPTQ 通过跨输出行的向量表示共享索引，并在初始化时使用输入敏感度。[GPTVQ v2](gptvq.md)另解释多输入列向量与移动CPU小码本的取舍；本页前述基线数字仍属于VPTQ自身论文的实验，不能直接替代GPTVQ v2的协议。[AQLM](aqlm.md)的加性码本与联合更新、[QuIP#](quip-sharp.md)的旋转/结构码本，以及 [QTIP](qtip.md) 的路径表示，分别改变可选集合与优化方法。比较时应一起看向量方向、码本学习、索引更新、微调范围、完整位预算和消费路径，不能只按向量维度或名义 bit 排序。
