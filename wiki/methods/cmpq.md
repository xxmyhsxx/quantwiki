# CMPQ：按输入通道分配精度与双类离群保护

CMPQ 用校准激活的通道L2范数分配权重精度：先把通道精度初始化为3 bit，再按目标预算把一部分改成2或4 bit；各通道独立学习标量K-means中心，另保存少量FP16保护值。它改变通道编码容量，区别于只改变量化误差的加权系数，也区别于逐层统一位宽。

本页依据 `arXiv:2410.13056v4` 的正文、算法1、关键实验与必要附录A–D，回查原始PDF算法、分数位曲线及部署表。当前限论文研读，没有核读作者代码或运行模型/GPU。前置解释见[混合精度分配](../theory/mixed-precision-allocation.md)、[标量码本与预算](../theory/codebook-quantization-and-bit-budget.md)、[激活感知量化](awq.md)。

## 1. 被分配的是输入通道对应的权重向量

论文采用 $X\in\mathbb R^{n\times d_{\rm in}}$、$W\in\mathbb R^{d_{\rm in}\times d_{\rm out}}$ 和 $Y=XW$。第 $i$ 个输入通道关联 $W_{i,:}$，其分数为

$$a_i=\|X_{:,i}\|_2=\sqrt{\sum_{t=1}^nX_{ti}^2}.$$

如果代码使用PyTorch常见 $W_{\rm torch}\in\mathbb R^{d_{\rm out}\times d_{\rm in}}$，同一个对象对应列，不能因“channel-wise”一词就改成输出行。统计汇集校准输入位置；它不是最终任务梯度，也没有对每个候选位宽直接测量任务损失。

对误差 $E=W-\widehat W$，输出扰动为 $XE$。仅在忽略输入通道交叉项时，平方重构目标近似为 $\sum_i a_i^2\|E_{i,:}\|_2^2$；完整形式为 $\operatorname{tr}(E^\top X^\top XE)$，见[二阶重构](../theory/layer-reconstruction-second-order-compensation.md)。即使对角近似成立，范数排序也没有包含不同通道从2升3或3升4所减少的误差，因此属于分配启发式，不是预算下最优敏感度求解。附录B.3比较L1/L2/L∞支持其所测选择；不能由驻点处平均梯度小断言所有Fisher或梯度方法都失效。

## 2. 算法1怎样得到名义平均位宽

先令每个通道 $c_i=3$。设目标标签为 $b\in[2,4]$：

| 目标 | 原文分配规则 | 名义解释 |
| --- | --- | --- |
| $b>3$ | 取 $q=1-(b-3)$ 分位点 $l$，将 $a_i>l$ 改为4 | 约有 $b-3$ 的通道升一位，例如3.4对应约40%升级 |
| $b<3$ | 取 $q=3-b$ 分位点 $s$，将 $a_i<s$ 改为2 | 约有 $3-b$ 的通道降一位，例如2.2对应约80%降级、20%保持3 |
| $b=3$ | 低于1%分位点改2、高于99%分位点改4 | 约1%各升/降一位以保持名义3，源于小比例保护消融 |

每个通道是整数精度，平均值才可能为分数。有限通道数、分位数插值、严格比较与并列值会改变实际数量；算法伪代码自身未保证精确达到任意实数预算，也未展开端点特判。例如四个分数全相同，目标3.5仍无通道满足严格“大于”，实际全为3；若分数各异、目标2按最大分位点严格“小于”，最大者仍留3。实际计数与修复需作者实现核对，不能把论文连续措辞当作已经证明的精确分配。通用计数解释见[分位阈值与实际预算](../theory/mixed-precision-allocation.md#9-分位阈值不自动满足精确预算)。

每个通道使用 $K_i=2^{c_i}$ 个中心，按标量K-means聚类并保存中心索引。它是非均匀标量量化，不是跨多个权重的向量码本；本版没有引入SqueezeLLM的梯度加权聚类。背景公式把 $\min_j|w-q_j|$ 写成量化值，字面是距离；本页依据方法明确的“nearest centroid”描述，将恢复值记作所选中心，不把该式误抄成权重误差。

## 3. 两类保护为何要先提取再重聚类

论文主配置保护约0.5%的FP16值，分两种依据：

1. **激活保护 $O_{\rm act}$**：将激活范数最高约0.45%的输入通道权重保留为FP16。保护的是整条权重向量，不是把激活离群值另存一份。
2. **量化误差保护 $O_q$**：在去掉第一类后的 $W'=W-O_{\rm act}$ 上临时做通道聚类，从 $|W'-W'_q|$ 最大的约0.05%元素选FP16保护值；它按暂时重构误差选点，不只是按权重绝对幅值。
3. 从主体移出两类保护值，再对剩余权重重新聚类；最终论文写成 $\widehat W=W_q+O_{\rm act}+O_q$。

大残差值可能拉动中心，提取后重聚类可使中心更贴近其余值；是否改善整网质量仍由实验支持。原文未完整给出已提取位置的mask、两集合交叠、零占位和中心更新细节。如果保护项存原值，主体在该位置必须不再贡献错误的非零中心；如果主体仍贡献量化值，稀疏项就需存残差。上述求和记法不能单独证明实际实现已经满足这个契约，相关区别见[覆盖与残差的计费条件](../theory/codebook-quantization-and-bit-budget.md#51-离群值残差和分组怎样共同计费)。

附录A.1的稀疏比例段称量化误差保护固定0.5%，与正文0.05%不同，保留各段条件，不能用该段替换主配置。离群消融在拿掉一种保护时把另一种增至0.5%；这是等保护总量对照，不能解释成简单去掉一项且其他比例不动。表5中OPT-6.7B W3 C4去掉激活保护为12.23，完整CMPQ为12.26，也不支持两类组合每项指标都最佳。

## 4. 分数位宽不等于完整存储

同一矩阵内通道长度相同，主体编码平均为 $\bar c=d_{\rm in}^{-1}\sum_i c_i$。还需中心、位宽标记、保护FP16值、CSR索引/行指针、对齐及未量化模块。§5.1以4096长度、8个FP16中心和4 bit位宽字段估算 $(4+8\cdot16)/4096\approx0.0322$ bpw；“一个integer”在该估式中按4 **bit**计，不是已核实际32-bit整数序列化。4-bit中心版本估为 $(4+8\cdot4)/4096\approx0.0088$ bpw，但中心量化本身的额外尺度/编码接口未完整展开。

这个8中心估式对应3-bit主体；混合通道分别可能有4/8/16中心，应按实际表大小加权计费。0.5%保护值即使只算FP16载荷也是约0.08 bpw；若它替代主体则要扣掉被移出的码，若主体仍保留占位则不能扣，位置开销另算。作者以G128组元数据和0.5%保护作为近似预算对齐，不能当作所有基线逐字节文件大小已经相等。

因此2→2.2的“10%额外存储”首先是名义主体位宽增加10%，不是完整模型文件或推理峰值严格增加10%。论文表7的FP16/4-bit中心对照中，LLaMA2-7B WikiText2 PPL6.14→6.23，说明中心精度也有质量成本；实际后端还需支持各输入子矩阵的索引宽度与中心精度。

## 5. 实验支持的收益和成本

主质量实验为OPT-2.7B/6.7B与LLaMA2-7B/13B，C4随机128段、每段2048 token校准；两张A6000、PyTorch。附录扩至另五个模型，表头LLaMA3-8B与附近文字“7B”不一致，身份以明确表头保留但不补造checkpoint。PIQA/HellaSwag为zero-shot，MMLU为five-shot。以下是作者报告。

| 对照 | 可以得出的结论 |
| --- | --- |
| 主表LLaMA2-7B W3，Wiki/C4：CMPQ6.14/7.66、GPTQ6.25/7.97 | 所列3-bit配置有改善；不表示所有模型/位宽都胜过其他方法 |
| 主表同模型W2：CMPQ14.37/15.97、QuIP#12.30/14.80 | 专门的2-bit方法仍可更好，不能只挑CMPQ获胜项排序 |
| 图3同模型C4，名义2→2.2：15.97→11.11 | PPL约下降30.4%，体现额外主体容量的价值；还需保留完整预算口径 |
| 表3组件消融，LLaMA2-7B Wiki：加非均匀后6.45，加混合后6.21，完整6.14 | 非均匀、保护与分配共同起作用；完整收益不能全部归因于通道混合 |
| 表6同模型W3：HellaSwag53.85、PIQA75.70、MMLU39.27；FP16为57.10/78.07/46.46 | 相比所列W3基线改善，但没有恢复浮点质量 |
| 附录C.2同位宽SqueezeLLM对照，LLaMA2-7B W2 Wiki：10.79 vs CMPQ14.37 | 梯度加权基线可更强；CMPQ2.2的9.32是另一存储预算，不是同位宽胜出 |

校准表比较Wiki/C4和OPT模型，CMPQ变化较小；附录A.3中LLaMA2-7B W3少量样本也接近128样本结果。这些不是分布漂移免疫或普遍“一条就够”的证明。附录A.2存在均匀版本更好的设置，例如OPT-13B W3 Wiki10.42低于非均匀10.67，不能用总体倾向抹去反例。

量化成本表8：LLaMA2-7B激活收集0.6分钟、K-means11分钟、峰值24.2GB；13B为0.8/17分钟、42.6GB。附录C.2的“前向/反向内存两倍”由Hugging Face计算估计，不能写成所有实际量化实现都占两倍或总计算量翻倍。

部署图4将输入和权重按输入通道精度拆成子矩阵，各路矩阵乘求和，保护矩阵用FP16 CSR路径，输出FP16。表9是单batch、A6000、生成128 token，SqueezeLLM基础kernel派生的作者实现：7B SqueezeLLM/CMPQ为3.90/3.96秒与3.20/3.59GB，13B为6.20/6.91秒与5.80/6.44GB。13B延迟约增11.5%、峰值约增11.0%；7B峰值也约增12.2%，不能把“相近延迟”理解为所有内存开销可忽略。这没有比较现代所有后端或实际服务并发；本项目没有运行这些kernel。
