# CoRePrune：深度与删除集合条件下的视觉 token 可删除性

CoRePrune v1 先在视觉编码器的多个深度重算局部删除扰动，再在语言层经过图文交互后，以当前删除集合为条件，逐批恢复最有价值的候选。它压缩序列长度，不改变数值位宽；与量化可组合不等于已经验证组合收益。

前置图文数据流见 [视觉 token 与量化对象](../fundamentals/model/vision-language-model-tokens-and-quantization.md)。本页研读正文和预算、消融、集合诊断、深度控制等必要附录，未逐项复算所有完整任务表；无可核验作者代码，未运行模型。

## 1. 删除不仅去掉一项，也重归一化剩余注意力

固定某层某头、一个保留 Query $q$ 的状态，令 $a_j$ 为其注意力概率、$v_j$ 为 Value，$y=\sum_ja_jv_j$。删除集合 $S$ 的注意力总量为 $M(S)=\sum_{i\in S}a_i$，在剩余 logits 和 Value 不变且 $M(S)<1$ 时，

$$y^{-S}=\frac{y-\sum_{i\in S}a_iv_i}{1-M(S)},\qquad
y^{-S}-y=-\frac{\sum_{i\in S}a_i(v_i-y)}{1-M(S)}.$$

这是原文式 1–4 的单次 attention 恒等式。它要求 Query 仍存在、至少有可见 Key 保留，且不同时改变位置编码导致幸存 logits 变化。它不是删除 token 后重新运行全部后续层的精确公式，也没有包含输出投影 $W_O$、残差与 MLP 的传播。

定义 $r_{hqi}=a_{hqi}(v_{hi}-y_{hq})$，对指定 Query 集合 $Q$ 和 heads 平均：

$$D_l(S;Q)=E_{h,q\in Q}\frac{\|\sum_{i\in S}r_{hqi}\|_2}{1-M_{hq}(S)}.$$

这里是**二范数而非平方二范数**，先每个 Query/head 算范数和分母，再取平均。单 token 时

$$d_l(i;Q)=E_{h,q\in Q}\frac{a_{hqi}}{1-a_{hqi}}\|v_{hi}-y_{hq}\|_2.$$

小 attention 不一定意味着可删除；Value 偏差大时仍可能产生大误差。另一方面大 attention 的 Value 若非常接近当前输出，删除影响也可以很小。

## 2. 为什么不能将单 token 分数相加

集合分子先把有方向的残差相加，存在抵消或增强；分母又共享 $1-M(S)$。单独删除时最不重要的若干 token，未必组成联合删除扰动最小的集合。

**整理者反例。** 一个头、三个等概率 token，标量 Value 为 $(1,-1,0)$，原输出为 0。删除前两个 token 后仍输出 0，所以 $D(\{1,2\})=0$；只删除其中一个时 $D=0.5$。若从删除集合中恢复 token 1，失真反而增大，恢复收益为 $-0.5$。因此恢复收益可以为负，目标也不天然单调，不能套用单调次模贪心的保证。

论文定义条件恢复收益

$$\Delta_i(S)=D(S)-D(S\setminus\{i\}).$$

它衡量“在其他删除保持不变时，救回 i 能减少多少当前局部失真”，不是 token 的固有重要性。高全局相关也不保证边界不变：固定第 7 层、候选表示和 anchors，仅扩大周围删除集合，LLaVA/Qwen3.5 的条件排名相关仍为 0.872/0.936，但优先恢复的 top-25% 成员分别替换 30.8%/19.6%。（正文 §IV-B。）

## 3. 深度条件的证据支持什么

作者先在完整模型深层按被其他视觉 token 关注的程度确定 Bottom-25% token ID，再在 Pre-LLM、L0、L2、L4、L8 各独立删除**相同 ID**，保留原位置编号。比较幸存 token 排名、最终隐藏态相对误差与 teacher-forced 答案 KL；LLaVA/Qwen3.5 × MME/TextVQA 四组中，Pre-LLM→L8 最终误差平均下降 31.4%。相邻深度并非严格单调。

这说明删除时机影响后果，但晚删同时改变表示成熟程度和误差剩余传播长度，尚未分别识别两个原因。参考深层排名使用完整前向，只是诊断实验的控制，不是实际选择器免费预知未来层。

persistent-low 控制取多层 Bottom-q 集合的交集。它保证候选在一段深度持续低显著度，但实际删除比例小于 q：例如视觉侧 Bottom-50% 交集仅覆盖 LLaVA 的 6.5%–6.9%。不能将其“晚删更稳”结论写成每层删除一半 token 的实验。（附录 E-C。）

## 4. 第一阶段：视觉侧逐层刷新局部失真

候选 $G_i$ 与架构的 merger/unshuffle 对齐：普通 patch 可单独选择，原生 $2\times2$ 合并需作为不可拆单位；保护性结构 token 不计入预算。每个候选经过原生接口后对应一个语言侧视觉 token，因此 $N_0,K_V,K_L$ 是候选/输出 token 数，不总是原始 patch 数。

在固定的 $T$ 个视觉深度逐步减少到 $K_V$，目标数量

$$N_t=N_0-\operatorname{round}\left(\frac{t(N_0-K_V)}T\right).$$

每一步用当前表示重新算单候选 $d_l$；接收者是除候选本身外的其他幸存视觉候选。删去最低分的 $N_{t-1}-N_t$ 个，保持原顺序。此阶段只做单候选评分，**没有**逐次重算同一步中的整个联合删除集合；深度刷新与集合优化是两个不同组件。

例如 LLaVA-1.5-7B：576→128，视觉层索引为 8、10、12、14、16、18、20；Qwen3.5-9B：1024→256，层索引 9、11、14、16、18、20、23。预算在同一骨干的不同任务间固定。论文规定了成组候选，但未充分展开组内 attention/Value 的全部实现细节，不能据此声称已具有可直接复现的所有算子规则。（附录 A 表 S1。）

## 5. 第二阶段：先虚拟删除，再按当前集合恢复

第一阶段留下 $C$，$|C|=K_V$。语言模型完成零起始第 7 层后，使用同一次 prefill 的 attention/Value，以 question token 为接收者：

1. 令 $S_0=C$，虚拟删除所有视觉候选；文本 Key 仍存在，并不是删除全部可见 token。
2. 在当前 $S_t$ 下计算所有候选 $\Delta_i(S_t)$，恢复最高的至多 $B=4$ 个。
3. 联合更新被删除质量 $M$ 与残差和 $R$，再重新评分；直到恢复 $K_L$ 个。
4. 将恢复的视觉 token 按原顺序 gather，后续第 8 层起处理缩短序列。

恢复一批 $B_t$ 后可增量更新

$$M_{t+1}=M_t-\sum_{i\in B_t}a_i,\qquad
R_{t+1}=R_t-\sum_{i\in B_t}a_i(v_i-y).$$

这里 $a,v,y$ 在本轮选择过程中固定；重算的是集合条件，不是反复重跑模型。初始视觉质量接近 1 时分母敏感，数值处理需实现核验；正文未完整公开保护规则。

$B=1$ 是逐个反向贪心，$B=4$ 是同一旧状态评分后批量恢复的近似。没有全局最优或次模近似比保证。按论文复杂度，上界为 $O(H|Q|d_hK_V\lceil K_L/B\rceil)$，比固定一次 TopK 更贵；无额外完整 forward 不等于没有选择成本。

物理剪枝发生在第 7 层完成之后，未重算已完成层的输出，所以这层的删除失真是后续选择的局部代理，不是物理操作在同层造成的实际差值。后续传播仍须用干预实验判断。位置编号的稀疏/连续策略也会改变 logits，见 [LayerPos](layerpos.md)，不能把位置变化的影响并入上述冻结 logits 恒等式。

## 6. 消融分离了哪些作用

在相同候选、接收者、层和最终预算下，Set-Greedy 对比静态 singleton TopK：LLaVA $K_L=32$ 的七任务相对均分 94.1→95.9，Qwen3.5 $K_L=128$ 为 89.6→90.3。这个 LLaVA 七任务口径与主表十任务 94.7 不同，不能混用。

将集合目标拆为方向交互、共享重归一化两因素，作者发现方向交互贡献了大部分局部目标下降：Qwen 的方向项单独下降 1.7%，完整目标下降 2.1%，只有重归一化下降 0.2%。这些是局部失真的样本级相对变化，不是任务准确率百分点。各目标定义和控制见附录 D-B/C。

逐层删优于一次早删，但未总优于晚删：Qwen3.5 的 Late 为 91.0，Progressive 为 90.3。候选池也不是越大越好：$K_L=64$ 时，$K_V=64/256/640$ 分别为 68.2/83.1/81.6；较大池增加选择弹性，也增加成本并可能改变启发式选择。

## 7. 质量保留、prefill 与内存不能互换

主指标 Avg. Rel. 是逐任务得分除以各自 dense 得分后等权平均。它不等于答对了相同比例的样本，更不能与其他论文不同任务集合的“保留率”直接排名。Qwen3.5 $K_L=128$ 得到 90.3%，但 OCRBench 593 对 dense 851，说明综合均分掩盖不同能力损失。CoRePrune 也不是所有预算与基线上最优；LLaVA 的准确率导向 QCPruner 在所列三档均更高。

RTX 5880 Ada 48GB，同一 1,500 个 TextVQA 输入、每条 16 个生成步、三次运行，$K_V=256,K_L=128$：

| 测量项 | Dense | CoRePrune |
| --- | --- | --- |
| 汇总 prefill | 323.4±2.5 s | 158.3±1.8 s |
| 汇总 decode | 23.8±0.1 s | 24.3±0.2 s |
| 峰值 GPU 内存 | 18,318.0 MB | 18,214.4 MB |

prefill 包含剪枝/选择开销，下降约 51.0%；这是数据集汇总时间，不是单请求 158 秒或服务 TTFT 分位数。decode 没有改善，峰值 GPU 内存下降很小，因为模型权重占主导。Set-Greedy 相对静态 TopK 每样本另增加约 6.91 ms，属于选择器比较；不能再次从已含开销的总时间扣除。

匹配最终 $K_L$ 不等于匹配各层 token 数或计算量。两阶段与其他剪枝方法保留不同深度安排，速度—质量应成对比较，不能仅凭“都保留 128”声称等成本。
