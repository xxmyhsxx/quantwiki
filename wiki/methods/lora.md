# LoRA：低秩任务适配、训练目标与参数预算

LoRA 冻结预训练权重，以两个较小的可训练矩阵表示加到权重上的任务增量。它降低每个任务需要训练和保存的参数量，保留完整基座；低秩约束的是增量，不是基座或最终权重。原始 LoRA 本身不执行量化，也不以恢复量化前输出为默认目标。

本页依据 LoRA: Low-Rank Adaptation of Large Language Models，arXiv:2106.09685v2（26页固定PDF），核读正文及与预算、配置和秩分析直接相关的附录；比较复用 LRQ v2 已核机制。实验数字为作者报告，未核 LoRA 官方代码或运行训练。量化基座上的初始化和执行条件分别由[LoftQ](loftq.md)及[低秩分支成本](../implementation/quantized-matmul-scaling-execution.md#12.%20%E4%BD%8E%E7%A7%A9%E8%BE%85%E5%8A%A9%E5%88%86%E6%94%AF%E4%B8%8D%E6%98%AF%E5%85%8D%E8%B4%B9%E6%88%96%E7%BB%9F%E4%B8%80%E4%BD%8D%E5%AE%BD)承接。

## 1. 直接学习增量，不分解预训练权重

采用论文的列向量布局：输入 $x\in\mathbb R^k$，$W_0\in\mathbb R^{d\times k}$，输出 $h\in\mathbb R^d$。令 $A\in\mathbb R^{r\times k}$、$B\in\mathbb R^{d\times r}$，本页把式3之后的固定缩放明确写入：

$$
c=\alpha/r,\qquad \Delta W=cBA,\qquad
h=W_0x+cB(Ax).
$$

$W_0$固定，$A,B$经任务训练更新；$r$是因子宽度，$\alpha$是超参数，不是学习的量化步长。线性旁路与基座使用同一输入，输出逐坐标相加；没有在两因子间插入非线性，才可在推理时合并为同形权重。（LoRA §4.1、式3、图1。）

$\operatorname{rank}(\Delta W)\le r$，但 $W_0+\Delta W$一般仍可满秩。LoRA 不是对 $W_0$做截断SVD，也不是先完成全参数微调再压缩其更新；因子直接在受限参数化中学习。作者以低“内在维度”研究为动机，提出任务增量低“内在秩”的假设；两者不是相同定义，前者不自动证明后者。

如果每个需要调整的矩阵都获得足够的秩容量，例如 $r\ge\min(d,k)$，则任意该矩阵增量都可表示；其他需要更新的偏置等也要开放训练，才能讨论全参数微调的表达能力。这是表示范围的整理者说明，不表示因子优化轨迹、优化器状态或最终解与全参数微调等价，也不再保证节省参数。

## 2. 优化的是任务表现

LoRA §2式1–2用条件文本生成说明目标。数据为上下文—答案对 $\mathcal D=\{(u,y)\}$，$\Phi_0$为冻结的预训练模型，$\Theta$收集所选矩阵的因子；以下写为等价的负对数似然最小化：

$$
\min_\Theta\ \mathcal L_{\rm task}
=-\sum_{(u,y)\in\mathcal D}\sum_{t=1}^{|y|}
\log P_{\Phi_0+\Delta\Phi(\Theta)}(y_t\mid u,y_{<t}).
$$

这里 $u$区别于第1节的层输入 $x$，求和对象是目标答案的token。该例通过整网输出训练适配器，不匹配某一浮点块的参考输出，也不最小化 $\|W_0-Q-BA\|_F^2$。论文声明参数化不绑定特定损失，并在GLUE分类/回归任务上实验；不能将语言模型负对数似然当作所有LoRA任务唯一目标。

**初始化与反传。** §4.1令$A$取随机高斯值、$B=0$，从$\Delta W=0$和原始基座函数开始。以确定性线性分支为例，设$G=\partial\mathcal L/\partial(W_0+cBA)$，整理者链式展开为

$$\nabla_B\mathcal L=cGA^{\mathsf T},\qquad
\nabla_A\mathcal L=cB^{\mathsf T}G.$$

初始$A$梯度为零，$B$仍可能收到非零梯度；若两个因子都为零，两侧的一阶梯度都为零。冻结$W_0$只免去它的参数更新，不切断对层输入或更早适配器的反传。普通LoRA的这条连续分支不涉及round，也无需STE；量化基座适配的梯度节点另见[PTQ、QAT与代理梯度](../fundamentals/quantization/post-training-and-quantization-aware-training.md)。

论文将$\alpha/r$用于减少变秩时重调超参数的需要；§4.1描述扫描$r$时保持$\alpha$固定、设为首先尝试的$r$，不随每次$r$一起改动。“调$\alpha$近似调学习率”带有Adam及适当初始化缩放的条件，并非任意优化器下的严格等价。实际任务设置也不同：附录D.3表11的GPT-2取$r_q=r_v=4,\alpha=32$，D.2表10的DeBERTa XXL取$r_q=r_v=8,\alpha=8$，不能写成统一默认$\alpha=r$。

## 3. 参数预算由目标矩阵和秩共同决定

单个$d\times k$矩阵新增的实存可训练元素为

$$N_{\rm factor}=r(d+k),\qquad
N_{\rm task}=\sum_{j\in\mathcal I}r_j(d_j+k_j)+N_{\rm extra}.$$

$\mathcal I$是接入适配器的矩阵集合，$N_{\rm extra}$单列开放训练的任务头、bias、norm等参数；固定$\alpha$不计为可训练参数。这是形状计账，不能把平方attention投影公式直接用于不同形状的FFN或其他结构。LoRA §5.1的$2\widehat L_{\rm LoRA}d_{model}r$对应同宽平方矩阵，$\widehat L_{\rm LoRA}$数的是矩阵个数，不是Transformer层数或attention head数。本轮未核分类任务头的实际训练与计数配置，不能据表2直接断言其参数已全部包含或冻结。

对单个矩阵增量，因子比一个同形自由增量少参数需满足

$$r<\frac{dk}{d+k}.$$

因此仅有$r<\min(d,k)$仍不足以保证节省；方阵要求$r<d/2$。这些计数是实际因子元素，不是秩$r$矩阵的内在自由度$r(d+k-r)$；因子存在等价重参数化，优化器仍保存相应元素。

从形状记账进入应用时，[Qwen-VL微调调用](../implementation/qwen-vl-input-preparation-and-finetuning.md)提供目标模块、参数开关和优化器分组的核对入口；实际可训练矩阵集合应按匹配模型确认，再代入上面的预算。

### GPT-3例子：相同预算有多种分配

依据§1的宽度12,288、§7.1的96层，若每层仅适配$W_q,W_v$且$r=4$，整理者重算为

$$N=96\times2\times2\times12288\times4=18,874,368.$$

单存FP16因子需37,748,736字节，即36 MiB；这不含基座、配置、优化状态或其他参数。原文§4.2/表5的“18M、35MB”是近似口径，附录F.2表15将同一组记为18.8M，不能据约数声称核过实际checkpoint文件大小。

同一预算可以给一种投影rank 8、两种rank 4或四种rank 2（表5）。GPT-3的$W_q,W_k,W_v$按整个$d_{model}\times d_{model}$矩阵处理，即使输出随后分head，也不默认每head再乘一份因子预算。固定预算下选择改哪些矩阵，与固定目标矩阵下增加$r$，是两个实验问题。

**v2的配置分歧。** 附录D.4把37.7M写成$q/v$各rank 8，或$q/k/v/o$各rank 2；后者按形状仅为18,874,368，表15也记18.8M。四种各rank 4才为37,748,736、约37.7M。保留原件差异，不据该句生成配置。表4的4.7M行也不能一律绑定$q/v$各rank 1：表15区分了该方案与只适配$v$、rank 2，两者预算相同，MNLI-m分别91.3%与91.7%。

## 4. 与LRQ的因子形状相似，作用不同

以下采用同一$m\times n$权重布局比较，LRQ的详细广播和有限范围条件见[LRQ](lrq.md)。

| 问题 | 原始LoRA | LRQ v2 |
| --- | --- | --- |
| 因子控制什么 | 加法增量$\Delta W=(\alpha/r)BA$ | 对数选码除数$Z=LU+a\mathbf1^{\mathsf T}+\mathbf1c$ |
| 前向作用 | $W_0x+\Delta Wx$，直接改变模型函数 | $\widehat W=s_1\odot\operatorname{round}(W\oslash[s_1\odot\exp(Z)])$ |
| 优化目标 | 下游任务损失，冻结基座 | 校准块输出重构，冻结原权重 |
| 实存因子数 | $r(m+n)$，另计任务头等 | $r(m+n)$，另计$m+n$广播参数与网格步长 |
| 秩约束落点 | $\operatorname{rank}(\Delta W)\le r$ | $\operatorname{rank}(LU)\le r$；加广播后$Z$至多$r+2$，逐元素指数不保持此秩界 |
| 推理如何保存 | 保留因子旁路，或将增量合并进有效权重 | 固化整数码后丢弃选码因子/偏置，保留码与恢复元数据 |

相同的因子元素数不表示相同优化自由度、损失或部署表示。LoRA中的$\alpha/r$控制加法分支幅度；LRQ的$\exp(Z)$改变逐权重舍入坐标，$s_1$控制恢复网格，不能将三者都叫“LoRA缩放参数”。LRQ的离线选码结果固化后可丢弃相应因子；LoRA不能在未合并增量时直接删除因子而保持任务适配结果。（LoRA §2/4；LRQ §2.3、附录G/J/M。）

[LoftQ](loftq.md)则先以权重误差交替求量化主体和低秩残差，再冻结主体、训练任务适配器；[QERA](qera.md)用激活二阶矩求固定量化主体的输出误差修正。它们的初始化/重构目标都不能代替后续任务目标。QLoRA将LoRA接到固定量化基座，NF4加载和适配器训练仍是两个动作；现有[范式说明](../fundamentals/quantization/post-training-and-quantization-aware-training.md#1.%20%E5%8C%BA%E5%88%86%E8%8C%83%E5%BC%8F%E4%B8%8E%E5%8F%AF%E8%B0%83%E6%95%B4%E5%8F%98%E9%87%8F)承接该区别，本轮不扩大为QLoRA原文或实现的完整核读。

## 5. 秩和目标模块的证据边界

LoRA v2主要在attention权重上实验，多数设置仅接$W_q,W_v$；MLP冻结，§4.2将MLP、LayerNorm、bias的适配实证留作后续研究。可用于一般稠密矩阵的参数化，不等于论文已经验证所有模块组合。

- **预算分配。** §7.1表5在GPT-3 175B、96层、约18M预算下，$q$单独rank 8的WikiSQL/MultiNLI为70.4%/91.0%，$q/v$各rank 4为73.7%/91.3%，四种各rank 2为73.7%/91.7%。表注虽称$q/v$总体最佳，但不能抹掉四种投影的相同或更高单项结果；支持的是该任务中分散到更多目标矩阵可优于只增单一投影秩。
- **小秩可用，不是通用充分。** §7.2表6的$q/v$在$r=1$时WikiSQL/MultiNLI为73.4%/91.3%，$r=8$为73.8%/91.6%，$r=64$为73.5%/91.4%。表5–6给出的典型种子波动为WikiSQL约±0.5个百分点、MultiNLI约±0.1个百分点，不能把所有小差值都写成明确提升。附录H.2表18的GPT-2 medium、E2E在26,000步后，最低验证损失1.16由$r=16$及多个更高秩并列，最高BLEU在$r=4$；部分超参数按$r=4$调过，不能据此给出跨模型最佳秩。作者也明确不预期每个任务都能用极小$r$。
- **任务表现并非每项严格领先。** 表2的DeBERTa XXL GLUE平均为LoRA 91.3、全参数微调91.1，SST-2却为96.9%对97.2%；原文平均分组合了accuracy、相关系数等任务指标，并复用部分既有基线。不能写成LoRA在每个单项都胜过全参数微调。

§7.2的不同秩/种子子空间比较，以及§7.3第48层的投影范数，提供了“共享少数任务方向、放大基座中未突出方向”的解释线索；它们针对已训练因子和指定模型，不证明任意全参数更新都低秩，也不证明LoRA必然等于基座的前$r$个奇异方向。大秩可能提高表示容量，未必单调提高任务指标。

## 6. 合并、训练显存和任务保存分开计

推理关闭训练态随机操作后，在线性旁路和同一缩放约定下可计算

$$W_\star=W_0+(\alpha/r)BA,\qquad h=W_\star x.$$

这在精确算术下与两路相加等价。合并后仍使用一个$d\times k$权重矩阵，所以论文的“无额外推理延迟”指此构造相对普通同形微调模型，不代表分支未合并时也免费。有限精度下的舍入、反复合并/撤回和具体后端兼容性需实现验证；原文合并段省写缩放，实际合并必须匹配训练前向的$\alpha/r$。

保留未合并因子便于共享基座和切换任务，但需要两次较小矩阵乘及中间激活；批内不同任务也需分别选择因子。合并成单一任务权重后，多任务混批不再直接共用这一份$W_\star$。如果主体已量化，先合并浮点有效权重再重新量化会引入新误差，不能沿用浮点恒等式声称保留原格式与精度，详见[低秩辅助分支的执行预算](../implementation/quantized-matmul-scaling-execution.md#12.%20%E4%BD%8E%E7%A7%A9%E8%BE%85%E5%8A%A9%E5%88%86%E6%94%AF%E4%B8%8D%E6%98%AF%E5%85%8D%E8%B4%B9%E6%88%96%E7%BB%9F%E4%B8%80%E4%BD%8D%E5%AE%BD)。

训练时减少的是大部分基座参数的梯度与优化器状态；基座数值、激活、反传和工作缓冲仍有成本。§4.2报告GPT-3 175B的训练VRAM从1.2TB降至350GB，未分项披露所有张量驻留，不能由因子比例推导任意训练栈的峰值显存。作者以同样模型并行权重分片在V100上报告每GPU吞吐32.5→43.1 tokens/s，同时概括为25%加速；按所列吞吐计算约提高32.6%，固定工作量的时间约减少24.6%，两种口径需区分，不作为本轮实测。

每任务只存因子可大幅减小增量checkpoint，但部署仍需基座；独立保存每个已合并完整模型也就失去共享文件的节省。论文“350GB→35MB、约10,000倍”讲的是每任务保存口径，不表示单个模型总权重或推理显存缩小10,000倍。
