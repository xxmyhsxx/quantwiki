# ZeroQuant：逐组权重、逐 token 激活与逐层蒸馏

8 bit 量化到十亿参数规模时，精度损失主要来自两个数值事实：不同 token 的激活范围相差很大，不同输出行的权重范围也相差很大。ZeroQuant 用逐 token 动态激活应对 token 间范围差异，用逐组权重应对权重行间差异，再用逐层知识蒸馏补偿更低位宽的量化误差，并把量化与反量化的开销压进相邻算子。它的一条主线是：精度恢复不应依赖原始训练数据与全模型重训。

本页依据 ZeroQuant: Efficient and Affordable Post-Training Quantization for Large-Scale Transformers（arXiv:2206.01861，下称论文，全文研读；抽取文本缺表格，已回查作者 TeX 源码核对消融与延迟表）。所有精度、速度与成本数字均为作者报告，本轮未运行模型，也未使用 DeepSpeed 实现。

## 1. 对象与动机

论文针对两类模型：BERT 一类编码器与 GPT-3 风格的自回归模型，范围从 350M、1.3B 一直到开源的 GPT-J 6B 与 GPT-NeoX 20B。目标是**后训练量化**：不重训、不依赖原始训练数据，直接得到可部署的 INT8（以及权重更低的混合）模型。

作者对既有路线的判断是：量化感知训练需要完整训练流水线，代价高且常需原始数据；此前的后训练工作在 GPT-3 风格的大模型、更低比特与真实推理后端三个方面都不充分。结论中特别提到两点：多数工作不报告真实延迟改善，也不讨论不同量化方案带来的量化与反量化开销——这直接指向后面的系统设计。

论文的记号需要先说明：W8A8 表示权重与激活都用 8 bit；记为 W4/8 时指 MHSA 的权重用 INT8、FFC 的权重用 INT4；记为 A8/16 时指自注意力相关矩阵乘（Q/K/V）的激活保持 FP16，其余部分用 INT8。

## 2. 两个数值挑战

论文 §3 用两张统计图给出量化困难的来源，这也是后续两项粒度设计的直接依据。

**激活范围随 token 变化。** 同一层内不同 token 的隐藏状态范围差异显著。作者给出的例子是末层最大范围约 35，最小接近 8。用固定的 min–max 范围覆盖所有 token，会让小范围 token 的可用表示宽度被压缩，因而损害精度。这说明共享静态范围在该设置下可能损失精度，不等于所有经过平滑或适当分组的静态方案均不可用。

**权重范围随输出行变化。** 以注意力输出矩阵为例，不同行的最大幅值相差约 10 倍。权重按整矩阵共享范围时，小范围行被粗量化；到 INT4 只有 16 个等级时，这种差距意味着小范围行可能只剩 2 到 3 个可表示值。

论文同时报告了该现象带来的任务差异（表 1）：350M 模型上 INT8 激活量化是主要精度损失来源，进一步把权重压到 INT8 不改零样本表现，但会使 Wikitext-2 的困惑度变差；W4/8A16 在部分准确率任务（如 OpenBookQA）尚可，多数任务掉点，而 Wikitext-2 已经无法生成有意义的文本。生成任务比准确率任务对量化更敏感，是本文多处反复出现的结论。

## 3. 方法一：逐组权重与逐 token 激活

**逐组权重量化。** 把权重矩阵划分成若干组、每组单独量化，这一想法此前已有（作者引用 Shen 等的 QAT 工作），但论文强调两点不同：按 Ampere 架构的张量核心分块（WMMA tiling）选择分组，使其保持硬件加速性质；以及配套的系统后端。粒度越细精度越好，但元数据与访存代价上升，分组大小因此是硬件约束下的取舍——这与 [均匀量化与分组](../fundamentals/quantization/uniform-quantization-and-groups.md) 中「组越小越贴合局部分布、元数据越多」的关系一致。

**逐 token 激活量化。** 对每个 token 动态计算 min–max 范围，而不是用离线校准得到的静态范围。因为范围是实时算出来的，这一方案**不需要激活校准阶段**；论文因此把 INT8 方案的成本记为 0，并称其比标准 PTQ 更便宜。代价是需要额外的归约操作，论文用第 5 节的算子融合把它压掉，并指出：用现成框架直接做逐 token 量化会因数据在计算单元与主存之间来回搬运而变慢。

## 4. 方法二：逐层知识蒸馏

通用的隐藏状态蒸馏要同时驻留教师与学生、保存优化器状态，并要求原始训练数据。ZeroQuant 的 LKD 把这三项代价逐一消掉（论文 §4.2）：

设目标模型有 $N$ 个 Transformer 块 $L_1,\dots,L_N$，手头可用的数据为 $\mathbf X$。量化第 $k$ 块时，教师是**该块未量化的原件** $L_k$，学生是量化版本 $\widehat L_k$，两者接收同一个输入，即前 $k-1$ 层在 $\mathbf X$ 上的输出：

$$\mathcal L_{\mathrm{LKD},k}=\mathrm{MSE}\left(L_k\cdots L_1(\mathbf X)-\widehat L_k\cdots L_1(\mathbf X)\right).$$

论文说明损失也可换成 KL 等其它形式。三条直接推论：

1. 不需要单独的教师模型，教师用的就是同一批前层，额外显存只有当前这一层；
2. 优化器状态只覆盖 $L_k$ 的参数，因此十亿级模型的蒸馏在有限 GPU 预算内可行；
3. 目标只对齐中间层输出、不含标签，因此训练数据可以不是原始训练集。

第 3 条的边界在第 7 节用实验检验。LKD 属于逐块校准路线，但它与 [层输出重构](../theory/layer-reconstruction-second-order-compensation.md) 中其它逐块方法的目标函数不同：这里比较的是同一层原件与量化件在相同输入下的输出，并且会更新该层参数，而不是只做解析补偿。

## 5. 方法三：把量化开销融进算子

论文 §4.3 的两个融合点针对逐 token 量化引入的额外访存：

**量化与前驱算子融合。** 激活量化可以与之前的逐元素或归约算子（bias-add、GeLU、LayerNorm）合并成一个算子，避免为量化单独读写一遍。

**反量化与 GEMM 融合。** 整数 GEMM 的输出是 INT32，反量化时用权重与激活两个尺度缩放，再写出 FP16 结果供后续 FP16 算子（如 GeLU）使用；论文把这步融进自定义 GEMM 调度，避免额外的全局内存读写。

实现上使用 CUTLASS 的 INT8 GEMM 并按 batch 调参，理由是相比 cuDNN 一类库更容易在 GEMM 前后插入自定义算子。这与 [执行路径](../implementation/quantized-matmul-scaling-execution.md) 中「外维缩放可在累加后施加」的结构对应：这里的外维缩放正是「权重尺度乘激活尺度」。

## 6. 精度与成本证据

**BERT 编码器。** BERT-base 的 W8A8 下，纯 PTQ 平均精度掉超过 10 个点，ZeroQuant 达到 83.75，仅比基线低 0.2，且因为不需要激活校准，成本记为 0；作者报告比同期 Bondarenko 的结果高 1.29，并指出后者还混合使用了 FP16 激活。更激进的 W4/8A16 下，纯 PTQ 完全失去精度（随机预测），ZeroQuant 为 81.65，再加 LKD 提升到 82.35，代价是每任务 31 秒、单卡，作者称比 INT8 的 QAT 便宜 93.5 倍。BERT-large 上 W4/8A8 的 LKD 约需每任务 550 秒，比 QAT 便宜 13 倍；调参后可到 83.22。

**GPT-3 风格模型。** 350M 模型上 W8A8：PTQ 在 19 个准确率任务上平均掉 1.1%，在 Wikitext-2 上困惑度损失 4.7；ZeroQuant 把两者分别压到 0.2% 与 0.2，同样不需要激活校准。W4/8A16 下 ZeroQuant 的生成质量显著退化，LKD 把准确率从 33.5 提到 37.0、困惑度从 88.6 降到 30.6，原文成本存在冲突：正文写单卡 A100 3.1 小时，350M 主结果表写 1.1 小时，同时正文称为预训练成本（128 卡 × 32 小时）的 0.027%。按相同 GPU 小时口径复算，1.1/4096 约为 0.0269%，3.1/4096 则约为 0.0757%；百分比与表格相符，但本页无法判定哪处是笔误，不把三者作为一致测量引用。1.3B 模型上 LKD 约 0.02% 预训练成本（128 卡 × 120 小时）。

**组件消融（BERT-large，W4/8A8，论文的组件消融表）。**

| 逐组权重 | 逐 token 激活 | LKD | 平均分 |
|---|---|---|---:|
| 否 | 否 | 否 | 35.85 |
| 是 | 否 | 否 | 66.52 |
| 是 | 是 | 否 | 81.06 |
| 是 | 是 | 是 | 81.62 |

从接近随机到可用的主要贡献来自逐组权重与逐 token 激活（后者单项 +14.54），LKD 在已经很接近基线的基础上再加 0.56。这组数字说明 LKD 的定位是「把更低位宽的剩余误差补回来」，而不是替代细粒度量化。

## 7. 数据依赖与超大规模上的边界

**能否不用原始数据。** 作者在 350M、W4/8A8 下比较三种数据来源：随机整数 token、Hugging Face 的 Wikipedia、原始 PILE。用随机数据即可把准确率提升 1.1%、困惑度从 92.1 降到 40.6；Wikipedia 数据把准确率提到 36.2、困惑度降到 30.4，与使用原始数据相当。作者的解释是 LKD 只学习层内依赖、不优化端到端流程，因此数据只需要提供可用的内部激活统计。这条结论限定了适用条件：无标签只说明不需要人工标签，不能推出输入分布无关；随机 token、Wikipedia 与 PILE 的可用性来自这组实验，而不是目标形式本身的保证——[校准数据与量化范围选择](../theory/calibration-and-range-selection.md) 中依赖分布形状与范围的方案仍然需要数据覆盖。

**20B 规模上的失败与修正。** 对 GPT-NeoX 20B，把所有权重矩阵与激活都降到 8 bit 会显著掉精度。作者逐一定位后归因于自注意力计算的输入激活量化，于是保留该处激活为 FP16、其余用 INT8，精度恢复到与基线接近，同时把推理所需 GPU 从 2 张 A100 减到 1 张、延迟从 65 ms 降到 25 ms，合计约 5.2 倍效率提升。作者称由于缺少同规模开源模型与完整评测，无法验证该归因是否适用于其它模型。这一点与 [LLM.int8()](llm-int8.md) 把注意力投影列为退化来源、[SmoothQuant](smoothquant.md) 报告部分配置需保留注意力输入精度，指向同一个薄弱位置。

## 8. 延迟证据

论文在单张 40G A100 上比较 BERT 的 FP16 与 INT8 版本（论文的 BERT 加速表，单位毫秒）：

| 模型 | 序列长度 128 的加速范围 | 序列长度 256 的加速范围 |
|---|---|---|
| BERT-base | 2.27× 到 5.19× | 2.57× 到 4.98× |
| BERT-large | 2.62× 到 5.01× | 2.51× 到 4.81× |

加速比随 batch 增大而提高（例如 BERT-base、长度 128，batch 1 为 2.27×，batch 128 为 5.19×），说明收益与计算强度有关，不能把最大值当作任意场景的常数。GPT-3 风格模型上，作者用生成前 50 个 token 的平均延迟衡量，350M 与 1.3B 分别为 4.16× 与 4.06×。

**6B 与 20B 规模。** GPT-J 6B 的 W8A8 在 PTB、Wikitext-2、Wikitext-103 三个生成任务上报到与 FP16 接近的困惑度，延迟最高 3.67×。GPT-NeoX 20B 用上述「保留自注意力输入激活为 FP16」的方案，报告约 5.2 倍的系统效率提升。这些都是作者在特定硬件与实现下的测量，硬件型号、batch 与计时口径不足以支撑把这些倍数外推到其它后端。

## 9. Strong / Weak

**Strong：**把量化粒度与硬件分块绑定，同时用动态激活范围去掉校准阶段；LKD 用「原件即教师、只优化当前层」把蒸馏成本降到可与 PTQ 相提并论；把反量化融进 GEMM epilogue，使细粒度量化的开销不必然吃掉收益，并给出端到端延迟而非只有理论分析。对后来工作最有用的两项认识是：生成任务比准确率任务更早暴露量化退化；注意力输入激活是多数量化方案最先失败的位置。

**Weak：**LKD 需要逐层前向与一次局部反向，仍属有训练成本的方法，「无成本」的说法只适用于纯 INT8 配置；INT4 场景的精度恢复依赖蒸馏质量与超参，论文的固定超参设置本身也说明结论对调参敏感；延迟数据集中在 A100 上的 BERT 与少量 GPT-3 风格模型，缺少与同期其它系统的统一对照；20B 模型的归因基于单个模型，作者自己标注为未验证。

## 10. 与相邻方法的关系

与 [LLM.int8()](llm-int8.md) 同期且目标相同，但机制互补：LLM.int8() 通过把离群维度拆到 16 bit 来保住 8 bit 计算，ZeroQuant 通过更细的量化粒度与可选逐层蒸馏恢复精度，并用后端融合减少细粒度量化的执行开销。其 W4/8 与 20B 保留部分 FP16 激活的配置也属于混合精度，不能把它概括为从不混合精度。两者都要区分激活统计、整数矩阵乘和保留的浮点计算；LLM.int8() 的对象是 FFN 与注意力投影的线性层，并不把注意力函数本身全改成 INT8。

与 [SmoothQuant](smoothquant.md) 的关系有直接的历史联系：SmoothQuant 论文的基线表列出了 ZeroQuant，并说明其自身实现为该基线保留了自注意力输入的 FP16——本页第 7 节的 GPT-NeoX 归因正好解释了这类保留为什么必要。两者的差别在于 SmoothQuant 用等价缩放改变量化难度、不需要额外训练，而 ZeroQuant 用蒸馏更新层参数。

与 [GPTQ](gptq.md)、[AWQ](awq.md) 相比，ZeroQuant 的主要量化对象包含激活，因此要处理动态范围与整数 GEMM 的输出再量化；后两者以权重量化为主，主要处理权重误差的补偿。执行侧的分类见 [执行路径](../implementation/quantized-matmul-scaling-execution.md)，位宽组合在部署框架里的表达见 [部署框架与后端支持](../implementation/quantized-llm-deployment-backends.md)。
