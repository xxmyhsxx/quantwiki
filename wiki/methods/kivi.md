# KIVI：键按通道、值按 token 的 2 bit KV cache 量化

KV cache 让推理避免重算历史，代价是显存随批量与上下文线性增长。它与权重不同：缓存是逐 token 追加的流式数据，无法像权重那样离线反复优化。KIVI 的问题是，在这种流式结构里，键和值应当沿哪个方向量化——它的答案是两者不同，而且这个差别来自它们在注意力里扮演的角色。

本页依据 KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache（arXiv:2402.02750，ICML 2024，下称论文，全文研读；抽取文本缺表格，已回查作者 TeX 源码核对初步研究表、误差统计表、LM-Eval 表、LongBench 表与消融表），并定向核对官方仓库固定快照 `876b4d2d08e3b1d5f70d0969c299d8c7c42ddfb6` 的模型侧实现。本轮补读模型侧窗口更新和 `quant/new_pack.py` 的量化包装；未构建、运行或逐行核验设备端内核。KV cache 量化的对象与粒度框架见 [KV cache 量化的对象与粒度](../theory/kv-cache-quantization-objects-and-granularity.md)。

## 1. 对象与动机

论文 §1 的背景是批量服务：KV cache 不仅占用显存，还要在每个生成步从显存搬到片上，搬运期间计算核心闲置。作者引用的量级是，PaLM 540B 在 batch 512、上下文 2048 时 KV cache 达 3 TB，约为模型参数的 3 倍；OPT-175B 在 batch 512、prompt 512、生成长度 32 时为 1.2 TB，约为权重的 3.8 倍。

既有路线被归纳为三类：减少 KV head 数（MQA/GQA，需要重训或微调）、按重要性淘汰 token（如 H2O）、系统侧优化（卸载或分页）。本文走第四条路：降低每个缓存元素占用的字节数。作者强调这是最直接的手段，但要面对流式追加与精度两个约束。

论文把优化对象限定在 KV cache 的取值本身：量化方式为逐组舍入到最近网格（round-to-nearest），不做类似 [GPTQ](gptq.md) 的迭代补偿，理由是缓存逐 token 到达、优化式方法开销不可接受。

## 2. 分布观察与粒度结论

论文先在 Llama-2-13B 上做了一组模拟量化对照（逐组、group size 32、CoQA 与 TruthfulQA）：

| 配置 | CoQA | TruthfulQA |
|---|---:|---:|
| 16 bit | 66.37 | 29.53 |
| 4 bit，K 逐 token，V 逐 token | 66.48 | 29.51 |
| 2 bit，K 逐 token，V 逐 token | 52.93 | 24.98 |
| 2 bit，K 逐通道，V 逐通道 | 2.88 | 0.74 |
| 2 bit，K 逐 token，V 逐通道 | 2.80 | 0.26 |
| 2 bit，K 逐通道，V 逐 token | 63.53 | 28.60 |

三条结论（论文记为 OB1–OB3）：常用的「键值都按 token」在 4 bit 可用、2 bit 明显退化；值一旦改成逐通道，无论键怎么量化都崩溃；在这组 2 bit、G=32、模型与任务设置下，键逐通道、值逐 token 的组合最好；这不是其他分布、变换或量化方案均不可能有效的证明。最后一行的 63.53 与 16 bit 的 66.37 仍有差距，说明这与全精度并不等价。

**为什么键要逐通道。** 键缓存中少数固定通道幅值远大于其他通道——这与激活离群值属于同一类现象（见 [LLM.int8()](llm-int8.md) 与 [SmoothQuant](smoothquant.md)）。逐通道量化把误差限制在各通道内部，不牵连同组的正常通道。

**为什么值要逐 token。** 值缓存没有明显的通道离群模式，单看分布无法解释它为何不能逐通道。论文给出的原因是注意力输出的构造方式：输出是值按注意力权重的加权和，

$$[\mathbf A\mathbf X_V]_{i*}=\sum_j \mathbf A_{ij}[\mathbf X_V]_{j*},$$

而注意力权重高度稀疏（论文测得 84.3% 的稀疏度），输出实际上只由少数重要 token 的值决定。逐 token 量化把误差限制在单个 token 内部，因此量化不重要的 token 不会污染重要 token；逐通道量化则会跨 token 混合误差。

论文用误差统计支持这两条解释（Llama-2-13B，全层全 head 平均）。原表采用逐元素相对误差再取 Frobenius 范数；不是常见的范数之比，也没有标成百分数。表中 attention score 使用 softmax 后的 A，须与第 3 节的原始 logits 区分：

| 指标 | 键逐 token | 键逐通道 |
|---|---:|---:|
| 键的相对重构误差 | 13.67 | 4.55 |
| 注意力分数相对误差 | 47.00 | 9.60 |

| 指标 | 值逐 token | 值逐通道 |
|---|---:|---:|
| 值的相对重构误差 | 4.57 | 3.73 |
| 输出相对误差 | 3.55 | 49.89 |

两处都值得读出细节：值的重构误差在两种粒度下接近（4.57 对 3.73），但传播到输出后相差约 14 倍（3.55 对 49.89）。也就是说，**决定粒度的不是重构误差本身，而是误差经过 attention 后的传播方式**。这是一条比「离群值在哪就按哪个方向分组」更基本的判据，也是本方法区别于纯分布驱动选择的地方。

## 3. 算法：分组键缓存与残差窗口

逐 token 量化天然适配流式追加：新 token 量化后直接按 token 维拼接。逐通道量化跨越 token，无法直接流式执行。KIVI 的做法是把缓存拆成两部分（论文 §3.3）：

- **分组部分** $\mathbf X_{K_g}=\mathbf X_K[:l-r]$，按每 $G$ 个 token 一组做逐通道量化并保存整数码、尺度与最小值偏移；
- **残差部分** $\mathbf X_{K_r}=\mathbf X_K[l-r:]$，尚未达到刷新阈值 $R$ 的尾部，**保持全精度**；它可能已包含多个完整的 $G$ 大小组。

新到 token 先进入残差部分，当残差达到 $R$ 个 token 时量化并并入分组部分，残差清空。$R$ 必须能被 $G$ 整除；论文用 $G=32$、$R=128$（附录也给出 $R=32$ 的结果）。注意力分数由两部分拼接：

$$\mathbf A_g=\vec q\,Q(\mathbf X_{K_g}^{\mathsf T}),\qquad \mathbf A_r=\vec q\,\mathbf X_{K_r}^{\mathsf T},\qquad \mathbf A=\mathrm{Concat}([\mathbf A_g,\mathbf A_r]).$$

这里 $Q(\mathbf X)$ 表示整数码和元数据参与反量化乘法，不是把整数码直接当作实数。论文把 $m=\min X$ 称作 zero-point，实际网格为 $c=\operatorname{round}((x-m)/s)$、$\hat x=sc+m$，$s=(\max X-m)/(2^b-1)$；m 是实值偏移，不是另一种常见写法 $s(c-z)$ 中的整数零点 z。官方 `quant/new_pack.py` 的包装返回 code、scale、mn，与此一致。

拼接结果是 **softmax 前的 logits**。代码对两部分拼接后统一除以 $\sqrt d$、加 mask，再做一次 softmax；不能分别归一化量化段与全精度段。得到权重 $P$ 后，按 V 的分界分成 $P_g,P_r$，输出为 $P_g\widehat X_{V_g}+P_rX_{V_r}$。K 与 V 的分界不必相同，但每个位置仍对应同一个历史 token。

值缓存也分两段，但保留最近 R 个 token 的 FIFO 队列：新值入队后若超过 R，就把最早的一个按 token 量化并移出。K 则达到 R 后整段量化清空。因而稳定解码时，保存下来的 K 全精度尾长在 0 到 R−1 循环，V 尾长保持 R；它们不是两个固定长度相同的滑窗。

两点实现事实：普通 attention 路径在预填充时用未量化 K/V 计算当前注意力输出，同时为后续解码保存量化前缀和全精度尾部；残差窗口的存在意味着 KIVI 实际上是「极低比特 + 少量全精度」的混合结构，其规模上界为 $R$ 个 token，论文论证在长上下文下可忽略。

**这解释了一个容易被忽略的对照。** 论文的模拟表里「2 bit 键逐通道、值逐 token」在 GSM8K 上仍显著低于全精度，而 KIVI 的差距缩小到约 2%。作者把差异归因于残差窗口：全精度的最近 token 对数学推理一类困难任务很关键。因此阅读这类结果时，必须区分「全部 token 都被量化」与「保留一个全精度滑窗」两种设置。

## 4. 实现与系统支持

仓库实现与论文一致（快照 `876b4d2d` 的 `models/llama_kivi.py`）：配置项为 `group_size` 与 `residual_length`；键在量化前转置，使分组落在最后一维，从而按通道共享参数；值按 token 量化后沿 token 维拼接；残差长度与分组大小的整除关系以断言形式写在代码里（`assert self.residual_length % self.group_size == 0`）。

论文报告的系统侧工作是把反量化与矩阵乘融合（图中的 Q_MatMul），用 CUDA 实现，并用 Triton 实现分组量化内核。作者明确：与 weight-only 量化兼容，两者可以叠加。这与 [执行路径](../implementation/quantized-matmul-scaling-execution.md) 中「反量化必须与计算融合，否则低比特只是省存储」的判断一致，也与 [混合精度分配](../theory/mixed-precision-allocation.md) 中「KV cache 是独立预算项」的划分一致。

## 5. 质量证据

**生成任务（论文的 LM-Eval 表；CoQA 为精确匹配、TruthfulQA 为 BLEU、GSM8K 为精确匹配）。**

| 模型 | 配置 | CoQA | TruthfulQA | GSM8K |
|---|---|---:|---:|---:|
| Llama-2-7B | 16 bit | 63.88 | 30.76 | 13.50 |
| | 4 bit（K、V 皆逐 token） | 64.82 | 29.85 | 12.28 |
| | 2 bit（K 逐通道，V 逐 token，全部量化） | 59.08 | 33.10 | 5.76 |
| | KIVI-4 | 63.78 | 30.80 | 13.80 |
| | KIVI-2 | 63.05 | 33.95 | 12.74 |
| Llama-2-13B | 16 bit | 66.37 | 29.53 | 22.67 |
| | KIVI-4 | 66.38 | 29.49 | 23.65 |
| | KIVI-2 | 66.23 | 29.84 | 20.77 |
| Falcon-7B | 16 bit | 59.83 | 23.20 | 4.55 |
| | KIVI-4 | 59.67 | 22.58 | 4.47 |
| | KIVI-2 | 57.48 | 24.98 | 3.41 |
| Mistral-7B | 16 bit | 67.40 | 30.45 | 38.36 |
| | KIVI-4 | 66.95 | 30.49 | 37.30 |
| | KIVI-2 | 66.35 | 32.17 | 36.01 |

三处需要保留的解释边界：**MQA 模型与 4 bit** 的关系——作者指出 Falcon-7B 使用 multi-query attention，KV cache 只有一个 head，本身已高度压缩，因此需要 4 bit 才能维持精度，这与论文标题的「2 bit」并不矛盾但限定了适用范围；**TruthfulQA 上 KIVI-2 高于 16 bit**（33.95 对 30.76）属于该指标下的波动，不能读成量化提升能力；**GSM8K 是区分度最高的任务**，也是残差窗口价值最明显的地方。

**长上下文。** LongBench 上论文报告 KIVI-2 与 16 bit 的平均分接近（例如 Llama2-7B 为 44.27 对 44.52、Llama2-13B 为 44.69 对 44.85、Mistral-7B 为 45.85 对 46.58），Falcon-7B 的 KIVI-2 平均分从 8.71 降到 7.95，与上面 MQA 的解释一致。NIAH 检索测试中 2 bit 仍保持检索能力（以图给出）。

**消融（Llama2-13B，GSM8K）。**

| 变量 | 取值 | GSM8K |
|---|---|---|
| group size（$R=128$） | 32 | 20.77 |
| | 64 | 21.00 |
| | 128 | 17.29 |
| 残差长度（$G=32$） | 32 | 20.62 |
| | 64 | 19.86 |
| | 96 | 20.55 |
| | 128 | 20.77 |

分组大小到 128 时明显退化，作者提示分组大小同时决定尺度与零点的数量，会直接影响长输入下的压缩率。残差长度没有单调规律（64 最差），但作者强调「有一个合理大的残差长度」对困难任务重要——这与第 3 节的机制解释一致：R 同时改变浮点尾部占用、K 的刷新周期和最近 token 的误差；这一组消融只能说明任务得分没有随 R 单调增长，不能把 R 简化成有无滑窗的开关。

## 6. 效率证据

论文在单张 A100 80GB 上按 ShareGPT 合成负载（平均输入 161、输出 338 token）逐步增大批量直到显存耗尽，比较 Llama-2-7B 的峰值显存与吞吐：KIVI 报告在包含模型权重的口径下把峰值显存降到约 $1/2.6$，从而支持最多 4 倍批量、带来 2.35 到 3.47 倍吞吐。作者明确说明这一加速在更长上下文与更长输出下会更大，并指出若把量化过程进一步与前序算子融合，收益还会提高。

两点阅读提示：**「2.6 倍」是含权重的整机峰值口径**，不是 KV cache 本身的压缩比，后者由位宽与残差窗口共同决定；**加速来自批量变大**，而不是单序列延迟下降——这与 [SAW-INT4](saw-int4.md) 用系统吞吐而非单请求速度作结论的理由相同。

## 7. Strong / Weak

**Strong：**把粒度选择建立在对注意力结构的分析上，而不是只对分布做统计；用一组对照把「在该实验设置下不同粒度更有效」的观察与「为什么」分开说明，并用注意力分数误差与输出误差两个传播指标支撑；算法改动小、不需要微调，残差窗口使方法能在流式追加下成立；与权重量化正交，可与既有系统叠加。

**Weak：**残差窗口是全精度混合结构，意味着压缩率不是干净的 2 bit，且它支撑困难任务的作用依赖超参数；所测 Falcon-7B 的 2 bit 结果退化更大，4 bit 更接近原精度，不能据此排除所有 MQA 模型的 2 bit 方案；分组大小与残差长度缺少可迁移的选取规则，论文的消融显示残差长度的效果不单调；评测侧重生成与长上下文，未覆盖训练或微调场景；内核为作者特定实现，与分页注意力等系统级方案的结合在本文只做了兼容性说明，未给出与 [SAW-INT4](saw-int4.md) 同类的分页与融合内核证据。

## 8. 与相邻方法的关系

与 [QuaRot](quarot.md)、[FlatQuant](flatquant.md) 的关系是互补的：那些方法通过旋转或等价变换改善权重的量化难度，并把 KV cache 作为附带对象；KIVI 只改 KV cache 的量化粒度与流式结构，不改变权重的表示。与 [QServe](qserve.md) 的差别在粒度与布局：QServe 用逐 head 动态量化配合分页布局，KIVI 用逐通道键加逐 token 值与残差窗口，两者的元数据组织与融合方式不同。

与 [KV cache 量化的对象与粒度](../theory/kv-cache-quantization-objects-and-granularity.md) 的关系是实例与框架：那一页整理的是对象、粒度、流式约束与系统约束的共同结构，本页是其中「粒度差异来自误差传播路径」这条判据的原始证据；[SAW-INT4](saw-int4.md) 则从系统约束出发，对同一对象给出一套更严格的可行性与代价判断。
