# QTIP：trellis 高维量化、并行解码与尾咬合

QTIP 用有限状态图上的路径表示一长串权重。路径共享局部状态，能够隐式表示高维码字而不保存指数大的任意向量表；bitshift trellis 又使每组权重仅依赖压缩流的一个短窗口，解决一般有状态解码难以并行的问题。它改变的是量化表示，实验中的二阶舍入仍使用 BlockLDLQ。

本页依据 arXiv:2406.11235v4，覆盖 §2–4、算法 1–5 和实现/消融附录。前置知识见 [码本量化](../theory/codebook-quantization-and-bit-budget.md) 与 [QuIP#](quip-sharp.md)。本次核对论文及一个小型枚举例子，没有运行作者 kernel 或模型实验；本地收录不含 QTIP 源码。

## 1. 三个维度不要混淆

传统任意向量码本对 $d$ 维向量使用 $k$ bit/weight，需要 $2^{kd}$ 个 d 维码字，直接存储/搜索随 d 指数增长。QTIP 的 $(L,k,V)$ trellis 有 $2^L$ 个状态，每状态输出一个 V 维向量，每步有 $2^{kV}$ 个候选转移。长度为 T 的权重序列分成 $T/V$ 步。

- V 是单个状态输出的维度，常用 1 或 2。
- T 是整条路径共同表示的有效向量维度，主实验为 256。
- BlockLDLQ 的输入反馈块宽为 $T_y$，主实验为 16；一次编码跨 $T_x=16$ 个输出行，所以 $T=T_xT_y=256$。

“小型 2D 输出表”与“256D 有效量化”没有矛盾。路径约束把相邻小输出组合成高维候选，但它不能表示任意同样大小的无结构高维码本；存储节省来自结构限制。

## 2. Viterbi 究竟精确求解什么

将序列写成 $s_t\in\mathbb R^V$，状态 y 的输出为 $C_y$，最小化合法路径上的可加失真 $\sum_t\|s_t-C_{y_t}\|^2$。动态规划为

$$D_t(y)=\|s_t-C_y\|^2+\min_{x:(x,y)\in G}D_{t-1}(x).$$

保存前驱并回溯可恢复最优路径。固定起止约束时，这对**给定图、码字和可加距离**是精确算法；它不直接精确最小化带所有输入相关项的 $\operatorname{tr}((\widehat W-W)H(\widehat W-W)^\top)$。

通用图按边遍历的代价含 $2^{kV}$ 入度。bitshift 结构中，共享前缀的多个后继拥有同一前驱组，先对各组求最小值、再加节点失真，可把主要时间做到 $O(2^LT)$（固定输出维度等实现条件下）。不要只从通用图的边数断言码率完全无成本；L 仍指数影响状态数，完整回溯也需要路径记录。（§2.3–3.1。）

**可核验例子。** 图 2 用 $L=2,k=V=1$，状态 00/01/10/11 对应 0.5/0.1/0.8/0.3。输入 $(.54,.03,.72,.19,.26,.89)$ 的最优路径为 00→01→10→01→11→10，重构 $(.5,.1,.8,.1,.3,.8)$，平方误差和 0.0307。本次用动态规划与全部 128 条合法开放路径枚举分别计算，结果一致；这是小型算法检查，不是 QTIP 实现复现。

## 3. 为什么 bitshift 允许并行读权重

状态 i 通过追加 $kV$ 个新位 c 转到

$$j=((i\ll kV)\bmod2^L)+c,\qquad 0\le c<2^{kV}.$$

j 的高 $L-kV$ 位等于 i 的低 $L-kV$ 位。第 t 组状态仅由压缩位流的窗口 $[(t-1)kV+1,(t-1)kV+L]$ 决定，不需要从第一组走到第 t 组。这同时消除了显式图存储与推理时序列依赖；编码时仍需搜索全路径。

普通路径含初始状态和后续新位，总位数为

$$L+(T/V-1)kV=kT+L-kV.$$

以 $L=16,k=2,V=2,T=256$ 为例，主体 512 bit、额外初始信息 12 bit，开放路径是 2.046875 bit/weight，还未计对齐和其他元数据。

尾咬合（tail-biting）要求终点与起点共享需要的重叠位，可将位流循环连接，只存 kT 位。图 2 的开放流 0010110 可省为 001011，末端读窗口时从开头补位。

## 4. 尾咬合省空间，但实际求解是近似

对所有可能起点精确求闭环最优，会把状态搜索放大到近似状态数平方。Algorithm 4 采用两次 Viterbi：先将序列循环移半长并求开放路径，从其中部取得重叠状态，再对原序列在这个固定首尾重叠下重编码。

选择的闭环条件来自启发式，**第二次在固定条件下最优，不代表对所有闭环条件全局最优**。表 2 在 4K 条 T=256 的 i.i.d. 高斯序列、L=12 下，1 bit 的 MSE 为 0.2803，对比精确 0.2798；2–4 bit 在报告精度下相同。相同四位小数也不能证明逐序列最优。

该实验支持分布匹配时近似有效。Hadamard 的高概率非相干界只约束最大坐标等性质，不逻辑蕴含所有权重独立高斯；本文把 Gaussian-like 当作设计近似，不能用于推出任意模型的尾咬合质量保证。

## 5. 为什么不用一张完整随机高斯表

邻近状态的二进制窗口大量重叠，直接按状态数值映射会导致强相关。QTIP 用散列或伪随机计算打乱这种关系，以有限指令生成近高斯值。（§3.1.1–3.1.2。）

| 编码 | 如何生成状态输出 | 存储与可调性 |
| --- | --- | --- |
| 1MAD | 32-bit LCG，再把四个 uint8 字节相加、中心化缩放 | 无 LUT；不是只需一条指令，论文实现合计约四条 |
| 3INST | LCG 后修改两个 FP16 模板的符号/部分指数/尾数，再相加 | 三条 ALU 指令之外，脚注明确还有拆分寄存器的数据移动 |
| HYB | $x^2+x$ 散列产生小表索引，查 2D FP16 表，再用另一位翻转第二维符号 | 表项可微调；每权重约两条相关 ALU 指令，不含全部访存/乘加 |

1MAD 将字节和减 510、除 147.8；有限字节组合只是近似高斯，不是连续高斯采样器。HYB 主实验 $L=16,V=2,Q=9$，基础表 $2^9\times2\times2$ bytes = 2 KiB；为规避 bank conflict 做 32 份复制可达 64 KiB，不能把单表大小当成 kernel 总共享存储。论文另提双符号翻转可扩大有效表，但全部已报告实验采用单符号翻转。

表 1 对标准 i.i.d. 高斯的 2 bit MSE：Lloyd–Max 标量 0.118、QuIP# E8P 0.089、1MAD/3INST 0.069、HYB 0.071；无限维高斯率失真下界 $2^{-2k}=0.0625$，表中写 0.063。它说明分布匹配下的编码效率，不等于语言任务损失的同幅下降。

## 6. 怎样接入二阶重构与微调

先对权重和输入 Gram 做两侧随机 Hadamard 非相干处理，再按输入块进行 LDL 反馈；对已补偿的 $T_x\times T_y$ 矩形展平，调用 trellis 量化，最后恢复矩阵形状。附录 Algorithm 5 使用下三角 LDL、从右向左处理；与上三角版本的正向记法等价，不能混用三角方向。

选择较小 $T_y$ 控制输入侧反馈块，跨 $T_x$ 行获得较大有效维度。这不把跨输出行误差变成有任务曲率的完整联合目标；BlockLDLQ 的理论误差界也依赖量化器矩界等假设，不能直接由有效维度256推出无条件最优。

纯计算码本实验不微调；HYB 主实验按 QuIP# 方式逐块调码本和尚未量化权重。索引的离散路径搜索与连续表项更新是两个阶段。Hessian 校准用 RedPajama：Llama-1/2 为 6144×2048，Llama-3/3.1 为 4096×8192，405B 为 2048×8192；不能把前篇 QuIP# 的 Llama-2 长度4096搬到这里。（附录 A.3。）

论文的质量微调设置不做矩阵融合、量化七个投影；吞吐实验明确使用矩阵融合。两者都要保留在协议中，不能声称某张质量表的具体 checkpoint 已直接取得同一吞吐。

## 7. 质量与速度证据应怎样组合

Llama-2-7B、WikiText-2、ctx4096，2 bit 的结果展示码本与微调的区别：

| 配置 | PPL |
| --- | ---: |
| FP16 | 5.12 |
| QuIP# 无微调 | 8.22 |
| QTIP 3INST 无微调 | 6.82 |
| QuIP# 含微调 | 6.19 |
| AQLM 含微调 | 6.14 |
| QTIP HYB 含微调 | 5.86 |

表 3 的“无微调优于含微调”概述有范围限制：上表的 2 bit 7B 就不成立；HYB 优势也不能全部归因于同一变量，因为编码与可训练参数均不同。表 10–11 更直接说明 L 增大通常提升质量，V 增大在固定 L 时可能变差，二者是设计取舍。

表 4 在 RTX 6000 Ada、batch1、矩阵融合下，Llama-2-7B 的 FP16 / AQLM2 / QuIP#2 / QTIP2 为 55.9 / 81.5 / 186 / 188 tok/s；70B 分别为 OOM / 8.78 / 22.2 / 23.5。QTIP 与 QuIP# 吞吐接近，支持在该配置下以较少吞吐代价取得更好编码质量，不证明所有硬件和大 batch 的相同关系。CPU NEON 例子只给量化质量/实现设想，没有对应 CPU 端到端速度测量。

Llama-3-70B 的 layer0 V 投影量化与提示前缀引发异常是表 7 明示的条件；表 8 instruct 模型使用 chat template。不能把这种任务质量崩溃简单归因于整体位宽，或跨模板拼接结果。Llama-3.2 小模型的未量化 embedding 占比大，W4 全模型压缩约 2.5–3 倍，也提醒“主权重位宽”不是文件总压缩率。
