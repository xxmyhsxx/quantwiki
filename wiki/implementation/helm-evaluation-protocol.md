# HELM：场景、提示协议与多指标评测

HELM v2把一次评测定义为场景、模型及其adaptation、指标的共同选择。它用统一提示尽量增加不同模型的共同覆盖，并保留场景×指标矩阵。量化对照可复用这套协议思想，但本文没有复跑HELM，也不把其历史排名当成压缩模型的成绩。

## 1. 覆盖有两个不同的分母

场景由任务、领域和语言界定；领域再分文本类型what、说话者/文本主体who、时间when。实际实例含input及带正确性等属性的references，划分训练/测试；训练实例在本研究中用于few-shot提示，不等于微调权重。模型是接收prompt/解码参数、返回completion及log probabilities的文字黑箱，不假定能访问内部激活或预训练数据。（§2，图5–8。）

v2评测30模型、16核心场景及26专项场景，共42；核心覆盖问答、检索、摘要、情感、毒性检测及其他文字分类六类任务。设计分别覆盖任务/领域/语言，没有穷尽它们的笛卡尔积；所列多语模型也主要按英语评测，模态、语言和交互缺口仍存在。（摘要、§3.1–3.2。）

表4的87.5%是16场景×7顶层指标中的98/112对；摘要17.9%→96.0%是所选模型的平均核心场景覆盖。两者均不表示得分或全部潜在能力已覆盖。缺失指标不能填成0：没有自由completion的选项打分不能直接测生成毒性；长摘要的扰动有效性也限制鲁棒/公平指标。

## 2. “五样本提示”还须固定哪些决定

§7/J默认至多5个in-context例子。分类按类别频率优先覆盖类别；**同一run的所有测试输入共享一组选例**，3次run改变的是选例随机性，不是穷尽所有解码/抽样变化。长例子会因模型窗口减shot，评测至多1000实例，不能将标称5-shot/3-run等同于每个请求完全同长或全量测试。

LM对文档用模型自己的tokenizer和窗口分块，并尽量保留上一块的上下文；其他过长实例截断到窗口，不能把截断任务当成长上下文推理。一般以stop sequence为主、最长reference决定的max tokens为兜底；相同token上限对不同tokenizer未必表示相同文字预算。

多选的joint在同一个prompt展示全部选择、预测选项索引；separate逐项评分“问题+候选续写”，还可按候选独立概率作校正。它们与生成文本后解析答案是不同算法，不能只因任务名相同混比。§J.1以既有偏好或候选是否自然续写决定策略，但表14明确未给HellaSwag/OpenBookQA默认，且separate-calibrated行为空；保留这一登记差异，不补成两任务已统一确定的配置。

## 3. 七类指标各自回答什么

Accuracy是任务主指标的总称，包括EM、问答词重叠F1、检索MRR/nDCG和摘要ROUGE，不是全都同单位的正确率。LM的BPB用字节而非token作分母，解释与共同文本条件见[模型质量评测](model-quality-evaluation.md#1.1%20%E6%8C%89%E5%AD%97%E8%8A%82%E8%AE%A1%E5%88%86%E4%BB%8D%E9%A1%BB%E5%9B%BA%E5%AE%9A%E6%96%87%E6%9C%AC%E5%92%8C%E4%B8%8A%E4%B8%8B%E6%96%87)。跨任务平均必须另声明权重；摘要ROUGE也不能替代事实正确性或人类偏好。

鲁棒性对每实例取**预设有限扰动集中的最差分数**再平均，集合含原始输入，所以该指标不高于同口径原始质量。Invariance保留语义/标签，使用轻微拼写/大小写等扰动；equivariance改变语义时须同步目标，v2采用BoolQ/IMDB可用的Contrast Sets。C.3通式未显式写变换后的label，应按具体配对实例核对；它不是对全部可能对抗输入的最差保证。（§4.5、C.3。）

Fairness区分人工替换群体词/方言的反事实扰动与有群体元数据的实际分组表现；前者不能代表所有群体分布。Bias统计生成中的群体提及/职业关联与参考分布差异，词表计数受语言标记影响，不是上述质量差。Toxicity是completion被Perspective API以p≥.5判为有毒的比例，依赖检测器、上下文与生成协议；毒性检测任务准确率与生成毒性是两个对象。（§4.6–4.8、C.4/C.6。）

## 4. 置信度概率和可靠排序分别核对

C.2以类别概率向量p、预测标签argmax p和top probability max p定义校准。默认ECE为**10个等样本量箱**，图17仅以两个箱示意；它不是10个等宽概率区间。数量不能整除时箱样本数最多差1；并列置信度的分箱/排序仍须具体实现规则，不能按答案把同分样本挑开。

原件有两处公式差异，PDF与TeX一致：总体ECE式3有绝对值，图17也逐箱取绝对差；有限式12却写成有符号的平均差，会允许过/欠置信相消。本页按正文含义与公共[分箱定义](model-quality-evaluation.md#4.1%20%E7%AD%89%E9%87%8F%E5%88%86%E7%AE%B1%E4%B8%8E%E6%9C%89%E7%AC%A6%E5%8F%B7%E8%AF%AF%E5%B7%AE%E4%B8%8D%E8%83%BD%E6%B7%B7%E7%94%A8)解释，不修改原件，也不据此断言作者实现漏算绝对值。

n为评测样本数；按top probability降序，前r例的正确率a_r给出式15 $\widehat{\mathrm{SCAA}}=n^{-1}\sum_{r=1}^n a_r$，越大越好；式14的acc@C%取r=⌊nC/100⌋。有限样本不保证恰有覆盖C%的阈值，特别是并列分数或r=0；零接受的accuracy=1是总体式5的数学约定，不能报告成实际可靠性。

总体式6–7却按t从0到∞积分a(t)dc(t)，而c(t)随阈值非增，字面方向与正面积不一致。公共[面积方向与离散约定](model-quality-evaluation.md#5.1%20%E5%87%86%E7%A1%AE%E7%8E%87%E9%9D%A2%E7%A7%AF%E5%92%8C%E9%A3%8E%E9%99%A9%E9%9D%A2%E7%A7%AF%E8%A6%81%E4%BD%BF%E7%94%A8%E5%90%8C%E4%B8%80%E6%8E%92%E5%BA%8F%E7%BD%91%E6%A0%BC)解释正覆盖方向及与二值AURC的关系；风险损失/网格改变时不能简单相补。

## 5. 效率矩阵与量化比较的边界

§4.9的训练能耗优先采用报告值；资料足够时用GPU数量×平均kW×训练小时×PUE估计，PUE=1.1、缺地点时用美国碳强度。它不是逐卡测量，缺少AI21等资料时不补值；不同报告是否包含调参/测试也须区分。

API原始请求延迟含供应方硬件、软件和争用/排队。Denoised保留供应方执行栈、估计排除波动的最佳情况；idealized在统一A100/Megatron栈上估计，只适用于架构资料可得的模型。图22用 $F(n_{prompt})+g\,n_{output}$ 表示输入处理与逐步生成成本；不能把供应方去噪时间或统一栈估计当成原API的实测吞吐，更不能据此声称特定KV/权重量化已加速。[服务评测](serving-performance-evaluation.md)补共同负载与SLO条件。

§11保留污染未知、提示敏感、3种选例/1000实例的统计限制，并将统一总分聚合留待后续。实际选型先声明相关场景/指标，再比较同prompt、shot、上下文、parser、计分与聚合下的浮点/压缩结果；为压缩配置单独优化提示会改变比较问题。这是整理者对量化对照的应用，不是论文已验证的量化结论。
