# LongBench v2：实际上下文、推理调用与答案计分

LongBench v2用自然材料上的四选一问题考察长上下文理解和推理。使用它评估KV压缩时，需要同时固定实际送入的文字、截断、推理调用和计分；语料有2M words不表示每个基线都处理了完整2M上下文。

## 1. 六类任务与难度筛选分别定义

固定v2有503条英语问题、20个子任务。每条含长材料、问题、四个选择、答案与标注者的支持证据；模型提示展示材料/问题/选择，不直接展示答案证据。（§3、附录B。）

| 类别 | 条数 | 需要处理的关系 |
| --- | --- | --- |
| 单文档问答 | 175 | 学术/法律/财报等信息整合，小说因果或事件顺序 |
| 多文档问答 | 125 | 跨文档比较、联系和汇总；不靠插入无关文档制造长度 |
| 长in-context learning | 81 | 用户指南、陌生语言词汇规则或many-shot分类映射 |
| 长对话历史 | 39 | Agent工作历史及用户对话中的状态、偏好和事件 |
| 代码仓库 | 50 | 跨文件的功能、依赖和流程 |
| 长结构化数据 | 33 | 表格或知识图谱查询/推理；图谱实体匿名化 |

97名标注者提供用过的材料，转纯文本后拒收少于8192 words或高度重叠的文档。自动review用GPT-4o-mini、GLM-4-Air、GLM-4-Flash，超128k窗口从中间截断；三者全答对需修改。24名专家可下载原文并用文内搜索；3分钟内答对也需修改，15分钟后可答“不知道”。因此人类成绩是限时、允许搜索、参与筛选的协议结果，不是无限时间的能力上限。（§3.2。）

Hard要求至少两模型答错且专家10分钟内无法解答，得到311 hard、192 easy；它依赖所选模型与人员/时间规则，不是模型无关的难度标签。作者抽查70条，68条完全正确、67条在15分钟Google搜索内找不到答案；不能据此保证全503条正确或排除所有训练污染。（§3.3–3.4。）

## 2. Words、窗口和实际保留内容不能混称

语料8k–2M按**words**统计。Short <32k、Medium 32k–128k、Long >128k，分别180/215/108条；表1的Length和Expert Time是中位数，Expert Acc是平均正确率。答案A/B/C/D约19/25/30/26%，均匀随机猜测期望25%，固定猜C却约30%；两种基线不同。

§4/附录D的10个开源模型窗口128,000 tokens，闭源基线除Claude-3.5-Sonnet 200k外为128k。超窗口用middle truncation，完整语料长度不等于实际输入；词到token的比例、聊天模板、输出预留与具体裁切还需匹配实现。不同长度组的任务分布不同，不能把Short/Long成绩差直接当成延长同一输入的因果效果，见公共[上下文比较](model-quality-evaluation.md#2.1%20%E9%95%BF%E5%BA%A6%E5%88%86%E7%BB%84%E5%92%8C%E6%88%AA%E6%96%AD%E4%B8%8D%E8%83%BD%E6%9B%BF%E4%BB%A3%E9%85%8D%E5%AF%B9%E9%95%BF%E5%BA%A6%E8%AF%95%E9%AA%8C)。

主表Qwen2.5不启用YaRN；附表4另用factor=4.0。Qwen7B直接/CoT为27.0/29.8→30.0/35.6，72B为39.4/38.8→42.1/43.5。位置扩展设置已改变，且部分子组不升，不能混成同配置量化收益。（§4.1、附录E。）

## 3. CoT是两次调用，并且第二次没有原文

直接回答为zero-shot，temperature=.1、max_new_tokens=128，要求生成选项。CoT第一次带长材料，temperature=.1、最大1024 tokens；第二次带问题、选择及第一次生成的推理，最大128 tokens，但提示明确省略长原文。它通过生成的推理传递信息，也会传递遗漏/错误；不是只给同一次直接回答多一些输出空间。（附录D.2–D.3。）

十个开源模型主表CoT平均增加约3.4**百分点**，不代表每个模型改善：Qwen72B 39.4→38.8，o1-preview 57.7→56.2。摘要的“直接回答最高50.1”指不采用更长内部推理的GPT-4o比较；o1-preview虽列zero-shot，也进行内部CoT，图3明确该区别。与人类53.7相比，57.7高4个百分点，不是相对提高4%，也不表示同等时间/计算预算。（表2、图3。）

## 4. 无效输出有两个计分版本

主表2把未能解析为选项的拒答/格式错误按错误计；附表5另给这些invalid样本25%的期望分，并同样补偿人类“不知道”。若总样本n、有效正确C、无效I，整理者由表注写为 $S_{strict}=C/n$、$S_{comp}=(C+.25I)/n$；不是剔除无效后算C/(n−I)。公共[任务质量计数](model-quality-evaluation.md#3.1%20%E5%A4%B1%E8%B4%A5%E8%AE%A1%E9%9B%B6%E3%80%81%E9%9A%8F%E6%9C%BA%E8%A1%A5%E5%81%BF%E5%92%8C%E6%9C%89%E6%95%88%E6%A0%B7%E6%9C%AC%E8%AE%A1%E5%88%86%E6%9C%89%E4%B8%8D%E5%90%8C%E5%88%86%E6%AF%8D)说明三种分母的用途。

例如论文Qwen7B直接结果27.0、invalid 7.4%，补偿后28.9；人类53.7→55.7，invalid 8.2%。表值经四舍五入，不宜用显示的小数要求精确重算。结论段另写人类50.1，与摘要/主表53.7不同，本页保留差异；没有把它改成已核实的新成绩。Parser的具体正则、停止条件、seed与重复次数仍需代码核查。（表2/5、§5。）

六类条数不等。按175/125/81/39/50/33加权，表3的Qwen72B分组成绩近似复算39.4；六类等权则39.3。这是整理者对显示数值的核算，受舍入影响；实际对照应保存每例结果及聚合规则，不能默认所有“平均”同口径。

## 5. RAG和去上下文对照能说明多少

RAG以GLM-4-9B tokenizer切512-token块，Zhipu Embedding-3编码“问题+选择”和块，检索top-N后**按原文顺序**拼接，N=4/8/16/32/64/128/256。2k–128k是这些块的token预算，尚不等于加上提示/输出后的统一模型输入。图4的无RAG参照是128k窗口内的输入，不是每条完整2M-word原文。（§4.2。）

所选结果中Qwen72B在32k检索预算比无RAG高4.1个百分点，GPT-4o在128k仍低.6个百分点；这是改变输入选择后的任务结果，不能解释成KV压缩带来的质量/速度。图3则各任务按本任务最高成绩归一化，不能把雷达半径直接当原始准确率。

无上下文的GPT-4o仍有33.1%，高于均匀随机25%；部分模型的某些任务去掉上下文反而更高。原文成绩下降支持上下文有用，却不能独立辨别记忆、选择先验、检索或推理贡献，也不能证明完全无污染。（表3、§4.3。）

## 6. 接到量化比较时保留什么

对同一503条或明确子集，先固定参考模型版本、位置扩展、实际token序列与裁切、chat template、调用次数/输出预算、parser及strict/compensated规则，再配对比较浮点和压缩结果。保留每类/长度/难度的样本数、invalid率及双方独对集合；有限样本、采样随机性和不同任务混合仍限制结论。（整理者应用；基本协议见[HELM](helm-evaluation-protocol.md)，缓存生命周期见[KV量化](../theory/kv-cache-quantization-objects-and-granularity.md)。）
