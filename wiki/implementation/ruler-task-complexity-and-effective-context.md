# RULER：任务复杂度、召回与有效上下文

RULER用可生成的任务分开测试长文本检索、多跳追踪、频率聚合和问答。单针检索通过只说明那一配置的行为；“有效上下文”另依赖任务集合、计分和阈值，并不是模型声明窗口的另一种固定规格。

## 1. 十三配置怎样增加难度

固定v3的主试验包含四类、13个配置；长度与任务复杂度是不同变量。（§3、附录B/表5。）

| 任务 | 配置与要检查的行为 |
| --- | --- |
| 单针S-NIAH，3配置 | word→七位数，在重复噪声或Paul Graham文章中检索；另以UUID替换value，检查长字符串是否完整 |
| 多key MK-NIAH，3配置 | 四key只问其中一个；另把整段填满word-number或UUID-UUID键值，增加相似干扰 |
| 多value MV-NIAH，1配置 | 同一key有四value，需完整返回，不能只找一个 |
| 多query MQ-NIAH，1配置 | 四个不同key都要检索，目标不同于同key多value |
| 变量追踪VT，1配置 | 一条链、四次name-binding，从初始值追踪；**五个变量名**含起点，不是只返回四个 |
| 常见词CWE，1配置 | 十个常见词各30次，罕见词各3次；加长度主要增加罕见词数量 |
| 频繁词FWE，1配置 | 按Zeta分布α=2采样，最高频rank用作噪声，返回三个目标词；不能把噪声也当普通top-3 |
| QA，2配置 | SQuAD/HotpotQA的gold段落混入同源随机干扰段，分别覆盖单跳/多跳问答 |

FWE中降低α使频率更平、目标更难区分；增加输出目标或干扰也会改变复杂度，不能只看输入长度。附录C先在8个开放模型、18配置上按跨长度表现做相关聚类，再去冗余选13项；这支持该次选择，不能证明穷尽了未来任务或真实长文本需求。

附录B/表5把第三S-NIAH配置写为word→UUID，表7模板却写word→word；本页配置采用表5，保留原件差异，实际生成值类型仍待匹配实现核对。

## 2. 提示、长度与召回共同组成协议

主文评17个aligned模型，每个**任务×长度**500例，长度档为4/8/16/32/64/128K tokens。全部13×6档若都执行，是每模型39,000例的计划量，不是“全套500例”，也不说明每档都有成功输出。模型chat模板、任务instruction/context/query和answer prefix分开；VT/CWE含一个任务示范，不能统称zero-shot。（§4、附录D/表6–9。）

§4用目标是否出现在输出中的recall-based accuracy抑制拒答/解释影响。多目标被召回比例不等于整题全对，更不控制输出多余项；公共[多目标计分](model-quality-evaluation.md#3.3%20%E5%A4%9A%E7%9B%AE%E6%A0%87%E5%8F%AC%E5%9B%9E%E4%B8%8D%E7%AD%89%E4%BA%8E%E6%95%B4%E9%A2%98%E6%AD%A3%E7%A1%AE%E6%88%96%E8%BE%93%E5%87%BA%E7%B2%BE%E7%A1%AE)给出教学集合例子。具体字串归一化、去重和分母须核作者实现，本文没有把教学集合匹配当作其已验证parser。

§4称“all models”使用vLLM/BF16/8×A100，但附录A明确把GPT-4和Gemini列为API模型。保留这一范围表述冲突，不能据主文概括认定API权重在本地运行。

## 3. 有效长度是带阈值的离散读数

表3每档取13任务的等权平均S(L)，阈值是Llama2-7B在4K的**85.6%**，通过条件为超过阈值。整理者表示为 $L_{eff}=\max\{L\in\{4,8,16,32,64,128\}K:S(L)>85.6\%\}$。集合为空时最大值未定义，表中的`<4K`沿用报告约定。检索有8个配置，占8/13权重；它不是四类别等权。（§4/表3。）

GPT-4的64K为87.0、128K为81.2，表中有效64K；Qwen2-72B的32K为94.1、64K为79.8，有效32K。Gemini在最大测试128K仍94.4，论文写“>128K”；实际证据是128K通过，**更长未测**，不能据此证明1M。LWM在最低4K已82.3，表中“<4K”是报告约定，不是测出了4K以下的失效边界。最大通过档也不自动保证档间所有长度都通过。

声明长度也要保留原件版本：表3的Mixtral-8x22B/DBRX为64K/32K，附表4却为32K/1M。这里采用表3解释成绩，不替作者统一这处登记差异。

## 4. 长度权重会改变排名

论文wAvg(inc/dec)模拟长/短序列占比，但没有给出真实部署分布。用六档序号权重1…6或6…1可近似复算表3；GPT-4分别约89.0/94.1。这是对公开舍入分数的整理者核算，未核作者聚合代码，不能把“线性权重”直接写成与token数4/8/16/32/64/128成正比。

LWM/Mistral-v0.2在inc为69.9/55.6，dec却75.7/81.2，排名随权重翻转。部署比较应采用已声明的使用长度分布，同时保留各档分数；不能只选对某模型有利的汇总权重。公共[有效长度条件](model-quality-evaluation.md#2.2%20%E6%9C%89%E6%95%88%E9%95%BF%E5%BA%A6%E4%BE%9D%E8%B5%96%E4%BB%BB%E5%8A%A1%E9%98%88%E5%80%BC%E5%92%8C%E6%B1%87%E6%80%BB)区分任务、阈值与聚合。

## 5. 错误现象怎样用于压缩对照

§5针对Yi-34B的压力试验观察到UUID漏字、被相似value干扰、多value返回不全，以及CWE在128K超过80%输出复制示范答案等行为；频率变平和QA中的参数知识替代也分别分析。它们是指定模型/任务的观测，不能直接诊断为KV量化误差或所有长文本模型的共同原因。

§6的LWM窗口对照固定7B参数量，较长训练窗口总体更好，但LWM-1M在256K低于LWM-512K，优势并非在所有测试长度单调。Yi大小对照固定200K训练窗口和同一data blend，34B优于6B是该系列下的结果；所选RWKV/Mamba型号仍不能代表所有版本。§8另说明未控制key的位置/深度，也未验证与自然任务的相关性；只有所选模型在4K表现较好，不是全体短文本已完美。

量化对照应固定生成实例/证据位置、长度档、chat/answer prefix、示范、输出预算与parser，分任务报告浮点独对/压缩独对和多目标遗漏，再对齐[缓存生命周期](../theory/kv-cache-quantization-objects-and-granularity.md)判断是否发生转换/重读。与[LongBench v2](longbench-v2-context-and-scoring.md)的自然多任务互补；两套分数不能互换，也不能只靠单针成功声明长上下文压缩无损。（整理者应用。）
