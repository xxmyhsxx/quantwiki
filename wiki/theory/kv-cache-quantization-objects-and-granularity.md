# KV cache 量化的对象与粒度

权重可以离线反复优化，激活随输入即时产生，KV cache 与两者都不同：它在推理过程中逐 token 追加，具体取值依赖当前输入，在线重算或优化受延迟预算限制；量化策略、旋转等参数仍可离线校准。同一个「4 bit KV cache」的说法，可能指不同的量化方向、不同的元数据组织，以及不同的系统代价。本页整理这一对象的共同结构，作为各具体方法的比较框架。

本页的框架来自 [KIVI](../methods/kivi.md)（arXiv:2402.02750）对分布与误差传播的分析，以及 [SAW-INT4](../methods/saw-int4.md)（arXiv:2604.19157）对服务系统约束的梳理；两篇均为全文研读并有独立方法页，本页不重复它们的实验细节。涉及其它方法的条目按各自页面为准，本页只做归类。

## 1. 为什么 KV cache 要单独讨论

设解码阶段当前查询为 $\vec q$，历史键值分别为 $\mathbf X_K,\mathbf X_V$，注意力为

$$\vec o=\mathrm{softmax}\left(\frac{\vec q\,\mathbf X_K^{\mathsf T}}{\sqrt d}\right)\mathbf X_V .$$

与权重量化相比，KV cache 有三个特殊之处：

1. **流式到达。** 每生成一个 token，缓存追加一行；任何需要跨 token 统计的量化参数都必须处理「尾部不足一组」的问题。
2. **在线预算有限。** 缓存是推理产物，反复优化或重算历史会增加成本，因此通常采用便宜的在线量化。这里是成本约束，并非数学上不能重算，也不禁止离线选择参数。
3. **与注意力结构耦合。** 键和值进入注意力的方式不同（一个进 softmax 前的分数，一个进加权求和），因此它们的误差传播路径不同——这是粒度选择的根本依据。

缓存规模随批量与上下文线性增长，这也是它在长上下文与高并发下成为瓶颈的原因。KIVI 引用的量级是 PaLM 540B 在 batch 512、上下文 2048 时约 3 TB；SAW-INT4 引用 Llama 4 Scout 在 1000 万 token 上下文下单请求 KV 约 1.8 TiB。

## 2. 对象：键与值的误差传播不同

两篇论文对键值给出了不同结论，原因在误差如何进入输出。

**键的误差先进分数再进 softmax。** 键的量化误差 $\delta\mathbf k$ 改变的是注意力分数，再经过指数归一化，因此影响「谁被关注」。KIVI 在 Llama-2-13B 上测得，逐 token 量化键的相对重构误差为 13.67、逐通道为 4.55，而传到注意力分数后的相对误差为 47.00 与 9.60——差距被放大到约 5 倍。SAW-INT4 用同一思路构造了以分数误差为目标的校准量 $\delta\mathbf k^{\mathsf T}\mathbf M\delta\mathbf k$，其中 $\mathbf M$ 是查询二阶矩。

**值的误差线性进入输出。** 输出是值的加权和，$[\mathbf A\mathbf X_V]_{i*}=\sum_j\mathbf A_{ij}[\mathbf X_V]_{j*}$。KIVI 说明，由于注意力稀疏（该论文测得 84.3%），输出实际上由少数重要 token 决定，因此逐 token 量化把误差限制在单 token 内部，不会污染重要 token；逐通道量化则跨 token 混合误差。实测中值的重构误差在两种粒度下接近（4.57 对 3.73），但传到输出后相差约 14 倍（3.55 对 49.89）。

**更一般的判据是同时看分布与误差传播。** KIVI 的未旋转、2 bit 分组设置支持 K 逐通道、V 逐 token；不能把它提升为所有 KV 量化的唯一方案，SAW-INT4 的旋转与 4 bit 设置就是不同设计条件。

## 3. 粒度：四个可选方向

| 粒度 | 共享范围 | 流式兼容性 | 典型用法与代价 |
|---|---|---|---|
| 逐 token（按行） | 参数不跨 token 共享；一个 head 内可以整体共享，也可以沿通道进一步分组 | 天然兼容，可直接按 token 追加 | KIVI 用于值；SAW-INT4 用于键与值的统一布局 |
| 逐通道（按列） | 同一通道沿 token 轴共享，可限制在一个 token 组内 | 跨 token，需要分组与残差窗口 | KIVI 用于键，每 G=32 个 token 分组 |
| 沿任一轴分组 | 组内共享，组大小 $g$ | 取决于分组轴 | [QuaRot](../methods/quarot.md) 对 KV 用 group 128 非对称量化 |
| 逐 head | 每个 KV head 一组参数 | 兼容，但尺度需随 head 动态估计与存放 | [QServe](../methods/qserve.md) 的 KV4 用逐 head 动态量化 |

粒度之外还有两个常被混入同一标签的维度：**位宽**（每元素多少位）与**元数据组织**（尺度、零点存在哪里、是否随页存放）。QServe 把每个 head 的 fp16 尺度与零点紧跟在页内量化 KV 之后，以支持运行时更新；这说明「KV4」不只是位宽，还包含一套页内布局约定。

## 4. 流式约束与残差窗口

逐 token 动态量化可以直接追加；KIVI 所用的逐通道分组量化需先收集组内多个 token 的统计，因此不能以相同方式逐个追加。KIVI 的处理方式是把缓存拆成**分组部分**（每 $G$ 个 token 一组做逐通道量化）与**残差部分**（尚未达到 R 的尾部保持全精度，可以超过 G），残差达到 $R$ 个 token 时并入分组部分。值缓存的 FIFO 则保留最近 R 个 token，每次只将超出的最早一个量化。K 整段刷新、V 逐个移出，两者分界不同；计算 logits 时统一 softmax，再按 V 分界求两段加权和。KIVI 用 $G=32$、$R=128$，并断言 $R$ 能被 $G$ 整除。

残差窗口的后果需要如实计入：

- 它是**混合精度结构**，因此相对 16-bit 的字节比例不等于单纯的 $b/16$；残差窗口的大小上界为 $R$ 个 token，长上下文下占比可忽略，但在短序列或小批量下不一定。
- 它承担实质功能。KIVI 报告，全部 token 都被量化时 2 bit 在 GSM8K 上明显退化，保留全精度滑窗后差距缩小到约 2%；消融也显示残差长度虽然没有单调规律，但「存在一个合理大的残差」对困难任务重要。

因此比较不同方法时，必须区分「所有 token 都被量化」与「保留一个全精度窗口」两种设置——这正是 KIVI 论文表中同时列出模拟结果与自身结果的原因。

## 5. 系统约束：分页布局与融合内核

分页布局的实际形态见 [推理服务的内存管理与批处理](../implementation/serving-memory-and-batching.md)：请求的缓存被切成固定大小的物理块、由块表映射，块内类型统一，正因如此混合精度与跨块统计才会成为障碍。

SAW-INT4 把生产推理引擎的约束归纳为两条，并据此筛掉了若干压缩范式：

| 约束 | 具体表现 | 受影响的做法 |
|---|---|---|
| 分页内存布局 | 缓存被切成固定大小的块以支持动态批处理，块内类型统一 | token 淘汰（未清空整块时不真正减少占用，产生内部碎片）；混合精度残差窗口（需要碎片化布局或额外页表）；逐通道缩放（token 分布在非连续块上，跨块统计代价高） |
| 融合注意力内核 | 解码时反量化必须在内核内完成，访存需合并 | 码本查表（向量量化）引入全局内存查找；PCA/SVD 一类基变换增加在线矩阵向量乘与寄存器压力；逐通道量化常导致 channel-major 访存 |

在作者讨论的统一页池与融合内核假设下，逐 token 量化避免跨页统计，是集成成本较低的选择。这是 SAW-INT4 的工程论证，不是所有分页实现都不可能支持其他粒度的定理；额外缓冲、元数据和专门内核的成本需要另行测量。旋转用于在所选布局内改善分布。

这也解释了 KIVI 与 SAW-INT4 的分工差异：前者用逐通道键加残差窗口换取 2 bit 级别的压缩，后者指出混合精度残差会增加其分页布局的集成成本，转而在 4 bit 上追求零服务开销。两者的取舍对象不同，不能只比位宽。

## 6. 旋转：不改布局的精度补偿

对缓存施加正交变换再量化，是这两页讨论的一种精度补偿手段：

$$\widetilde{\mathbf K}=\mathrm{quant}(\mathbf K\mathbf H),\qquad \mathbf H\ \text{正交}.$$

正交性只保证未量化的配对变换保持结果：$Q'=QH$、$K'=KH$ 时，$Q'K'^T=QHH^TK^T=QK^T$；只旋转 K 会改变 logits。若 V 也变为 $VH$，还需将输出右乘 $H^T$，因为 $(P(VH))H^T=PV$。这里 P 是同一组注意力权重。加入量化后仍有舍入误差，不能由正交性推出无损。

四个需要区分的实现选择：

- **作用对象。** SAW-INT4 的消融显示只旋转键就足够，同时旋转键与值在各模型与各块大小下几乎无差别；只旋转键可省掉对输出的逆旋转。[QuaRot](../methods/quarot.md) 对 KV 的旋转则在 RoPE 之后按 head 施加。
- **变换结构。** 全局稠密旋转代价高，SAW-INT4 用块对角 Hadamard（块大小 $h$ 必须整除 head 维），QuaRot 用快速 Hadamard 与随机符号。
- **块大小。** 较大块混合更充分；SAW-INT4 报告较小的块提高内核并行度却不带来端到端收益，因为解码受带宽限制，而质量损失在小模型上可达 20 点以上。
- **与查询的配对。** 旋转键之后必须对查询施加对应变换以保持分数不变；论文在实现中把这一步融进解码内核，避免对键缓存再扫一遍。

旋转的代价必须在正确的层次上衡量：SAW-INT4 的内核剖析显示，融合后量化写入与反量化内核本身变慢 1.33 到 1.58 倍，但占总运行时仅 0.10% 到 0.28%；未融合的实现则多出约 1.5% 的独立旋转开销。这正是 [执行路径](../implementation/quantized-matmul-scaling-execution.md) 里「融合与否决定成败」的一个 KV 侧实例。

## 7. 怎样衡量 KV cache 量化

四个容易被混用的口径：

**压缩率的三种说法。** 每元素位宽、KV 缓存自身的字节数、以及含模型权重的整机峰值显存，是三个不同的量。KIVI 报告的「2.6 倍」是含权重的整机峰值口径；残差窗口与元数据都会影响后两者。

**一个可核算的存储模型（整理者推导）。** 设 L 层、B 个等长请求、T 个有效 token、$H_{kv}$ 个 KV head、每个 head 维度 d。未量化缓存大小为 $2LBTH_{kv}d\times 2$ 字节，其中第一个 2 来自 K/V，第二个来自 FP16/BF16。GQA/MQA 要用 KV head 数，不是查询 head 数。若 K、V 分别有 $r_K,r_V$ 个浮点 token，整数码位宽均为 b，忽略对齐时大小为

$$M=LBH_{kv}d\left[\frac b8(2T-r_K-r_V)+2(r_K+r_V)\right]+M_{\rm metadata}.$$

元数据还要加每组尺度/偏移、页表和分配碎片；实际峰值显存还包含权重与临时张量。该式解释了短序列时全精度窗口占比高，也解释了“2 bit = 整机省 8 倍显存”为何不成立。

**误差指标的层次。** 重构误差不足以判断好坏。KIVI 的表显示值的逐 token 与逐通道重构误差几乎相同，输出误差却相差约 14 倍；因此至少要看键到注意力分数的误差、值到输出的误差，最后才是任务指标。

**任务选择。** KIVI 指出闭式任务（如 MMLU）只有一次解码步、直接取 logits，不适合研究压缩缓存的影响，因此改用生成与长上下文任务。SAW-INT4 的评测集中在思考模式推理与代码任务，其朴素 INT4 完全崩溃也说明该设定对低比特极不友好。

**吞吐指标的选择。** SAW-INT4 的核心方法学提示是：在显存受限时，逐请求输出速度（TPS$_{\mathrm{req}}$）会误导——KV 占用更大的配置被迫用更小批量，反而抬高了单请求速度，同时首 token 延迟急剧恶化（该论文测得 BF16 在并发 128 时首 token 延迟达 113 秒，INT4 为 57 秒）。跨不同显存占用的配置应当比较系统吞吐（总输出 token 除以墙钟时间），并同时报告首 token 延迟。

## 8. 与权重、激活量化的关系

KV cache 量化与权重量化正交、可以叠加，这一点在两篇论文中都被明确（KIVI 说明与 weight-only 兼容；SAW-INT4 的评测在既有权重格式之上进行）。但三者的预算必须分开：

- 权重与激活的位宽决定计算路径与权重占用；
- KV cache 的位宽与粒度决定缓存占用与注意力访存，并受批量和上下文长度放大；
- 残差窗口、尺度/零点元数据、页内布局是独立的开销项。

[混合精度分配](mixed-precision-allocation.md) 讨论的按层选择位宽属于第一类；本页讨论的对象是第二类。把两者合并成一个「平均位宽」会掩盖 KV cache 随序列长度增长这一结构差异。

### 在训练中适应 KV 量化

[LLM-QAT](../methods/llm-qat.md) 提供另一种补偿来源：训练前向同时量化权重、线性层输入及 K/V，以浮点教师的输出分布监督学生。K/V 都按 token 量化，推理时当前 token 连同尺度追加；训练时则对整段 K/V 张量施加同一粒度的量化。流式追加是推理条件，不能据此说训练也是逐 token 解码。（LLM-QAT v1 §2.2.2、图 2/3。）

这与冻结模型后改变粒度或施加等价旋转的路线不同：模型参数本身参与适应误差。因此比较时除位宽、布局、窗口，还要记录训练数据、教师和训练成本。LLM-QAT 的 v1 不含低比特硬件实现，不能用其质量结果证明分页缓存或融合注意力性能已验证。

## 9. 未验证与边界

- 本页的框架来自 KIVI（已发表）与 SAW-INT4（预印本）两篇的全文研读，不构成对 KV cache 量化领域的综述；Kitty、KVQuant、AKVQ-VL 等本地存在的材料本轮未研读。
- 两篇论文的硬件、模型、任务与测量口径不同，本页不给出跨论文的方法排序，也不把某一篇的结论外推到其它模型族。
- 未运行任何实验，本页所有模型与性能数值均转引自对应方法页，其原始出处与条件以各方法页为准。
