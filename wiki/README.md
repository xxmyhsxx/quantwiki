# 量化研究 Wiki

本 Wiki 是项目的长期研究基础，围绕神经网络量化积累可理解、可追溯、可验证的知识。它既支持从基础开始的系统学习，也支持针对具体模型、算法、实现与实验问题的深入研究，并为硕士论文提供支撑。

数值表示、量化网格、校准、误差与整数运算等基础共用一套解释；卷积网络和大模型的区别在相应结构、数据分布、量化对象与执行场景中展开。补基础按理解缺口推进，不以平衡两个子领域的页面数量为目标。

主要研究路径是：**基础概念 → 理解研究对象 → 识别量化问题 → 研究方法与原理 → 理解实现与加速 → 通过证据验证 → 形成或修正研究问题。** 这条路径约束内容的完整性，不要求每一步都成为一个文件夹。

Wiki 的搭建目标见 [Wiki 搭建目标](../docs/wiki/目标.md)：既支撑量化科研研究，也支撑量化代码的编写、部署与加速。

这是已确定的目录架构，不是要求一次建立所有空目录。按照实际研究内容逐步创建分支。卷积网络量化、大语言模型量化是“量化”下面的子领域，不另设“模型量化研究”层。

**覆盖优先级（2026-09-17 确认）：** 当前研究重点是端云协同下基于模态感知的多模态大模型量化，因此大语言模型与视觉语言模型方向持续补强；**卷积网络量化不是当前重点**，其目录只保留作为共通机制来源的少量页面（[[adaround|AdaRound]]、[[brecq|BRECQ]]），不按子领域逐方法扩展。目标与覆盖口径见 [Wiki 搭建目标](../docs/wiki/目标.md)。

每个子领域不预先复制一套“问题、方法、实现、实验”目录。先建立有实质解释的研究总览和实际主题页，内容增多且职责需要区分时再分组。新增研究子领域或实质改变分类方式前，先与用户讨论。

### 基础知识

解释数值、运算与硬件执行的共通基础，不预先绑定某个量化方法。

| 分支 | 主要内容 | 需要支持的理解 |
|---|---|---|
| 数学与数值 | 所需的线性代数、概率与优化基础；整数、浮点数、位宽、范围、精度、舍入、溢出与误差 | 数怎样表示，误差怎样描述，后续公式在什么条件下成立 |
| 张量算子与计算图 | 张量形状、维度与布局；卷积、矩阵乘法、归约、归一化、非线性等运算；算子、计算图与 kernel 的区别 | 模型在计算什么，数学表达怎样对应程序中的数据和运算 |
| 硬件与计算基础 | 存储层次、并行执行、计算量、内存访问量、带宽、计算能力及基本性能分析 | 时间与资源消耗来自哪里，哪些约束影响实现选择 |

基础页应从定义、数学表达和小例子讲起，说明适用条件与后续用途，不能只有术语和链接。按研究所需展开，不追求与当前问题无关的完整数学或硬件百科。

### 量化

量化的共通知识和不同模型对象的量化研究统一放在此处。

| 分支 | 主要内容 | 与其他分支的边界 |
|---|---|---|
| 量化基础 | 量化与反量化、scale、zero-point、数值格式、粒度与分组、误差度量、校准与裁剪的基本定义、PTQ/QAT、静态/动态量化、模拟量化与实际低比特计算 | 说明量化的基本对象和计算过程；某种搜索或优化方法的深入分析进入通用机制或具体方法 |
| 通用方法与机制 | 范围选择、裁剪与舍入策略、等价变换、误差重构与补偿、精度分配等可复用思想 | 说明共有问题、推导、方法差别与适用范围；不把单个案例提升为普遍规律 |
| 卷积网络量化 | 卷积网络的结构、计算与任务特点，量化困难、具体方法、实现要求、实验与未解问题 | 当前不是研究重点，只保留作为共通机制实例的少量页面；如方向调整再扩展 |
| 大语言模型量化 | 模型结构和推理特点，权重、激活、KV cache 等具体量化目标，方法、实现、质量与性能证据 | 先说明模型与运行场景，再细分量化目标；不能直接套用其他模型领域的实验结论 |

模型类别、量化目标、训练/校准范式、方法机制与硬件场景是不同的分析维度。物理目录保持上述主线，其余维度通过页面说明、主题导航、比较表或必要属性表达，不为每种组合复制正文。

一个方法可能同时涉及多个对象或机制。选择主要研究背景作为正文归属，其他主题提供带解释的引用。通用机制也可能仅适用于若干方法或模型，应写明范围，不强求覆盖所有模型。

### 实现与加速

集中保存可被多个量化方法或子领域复用的实现知识。

- **数据格式与存储**：量化参数、权重与元数据的组织、打包、布局、序列化和加载。
- **算子与内核**：数值过程、输入输出约束、累加与输出转换、反量化、融合、并行组织和性能分析。
- **框架与部署**：模型接入、图变换、后端选择、运行路径、部署与不同模块间的配合。

基础知识解释执行原理，本目录解释怎样实现及其取舍。某个算法、模型或固定版本代码独有的实现与实验，跟随对应量化主题保存；只有形成可复用内容时，才提取到这里。不能因为存在代码或低比特文件就宣称实际加速。

### 评测与验证

集中解释怎样合理判断方法和实现是否有效，包括数值正确性、模型质量、性能与资源指标、测试协议、基线、消融、稳健性、复现与不确定性分析。

具体实验结果保存在相关量化主题或实现主题中，并绑定完整条件。评测方法与单次结果分开：通用页说明“怎样测”，具体结果说明“测到了什么、支持什么结论”。负面结果、失败案例和未解释现象同样保留。

## 页面怎样组织

### 研究总览与主题入口

子领域的研究总览应解释：对象怎样计算，量化问题怎样产生，有哪些方法路线，路线之间有什么关系，实现与验证受什么约束。它应给出有顺序、有目的的阅读路径，不能只是页面清单或长期待办表。

专题可以围绕一个问题比较多种方法。具体方法页负责完整解释方法本身；两者分工不意味着把理解方法所需的关键内容全部外移。

### 具体方法的完整性

每个具体方法有唯一主页面，并保留以下内容。可以按方法特点调整章节或合并表达，但不能为了简短而省略核心环节。

| 内容 | 必须回答 |
|---|---|
| 对象、问题与动机 | 方法面向什么模型、任务和场景，解决什么困难，已有方法有什么不足 |
| 前置知识与符号 | 输入输出、变量含义与维度、数值格式、量化粒度及关键假设是什么 |
| 数学机制与推导 | 优化目标是什么，关键关系如何得到，哪些是恒等式、近似或经验观察 |
| 算法流程 | 步骤、中间状态、参数选择和必要的停止条件是什么；流程怎样对应公式 |
| 实现要求 | 数据怎样处理、参数怎样保存和消费、实际代码与论文有什么差别、哪些限制影响运行 |
| 实验与消融 | 选择能说明机制、组件作用、适用边界、代价或方法选择的证据，保留比较条件，不逐项转录排行榜 |
| 局限与待验证 | 哪些情况不适用，哪些材料未覆盖，哪些结论只来自作者报告或代码阅读 |

长推导或实现细节可以独立成页，但主页面保留关键公式、解释、条件、主要证据和明确的深入入口。允许为独立阅读保留必要解释，不重复维护整套推导、代码分析或实验结果。

### 防止过度凝练

- 不用“保护重要通道”“降低误差”“显著加速”等结论替代机制和证据。
- 公式必须解释符号、维度、假设和用途；分析中的简化公式与实际实现分别说明。
- 关键结果就近保留影响解释的条件，不能把它们全部移到其他页面。来源未报告的条件明确记录，不能用代码默认值补作论文实验事实。
- 重要反例、失败结果、消融和实现限制不能在摘要、合并或压缩时消失。
- 缺失、未核验与不适用分开说明，并交代影响；不为填齐模板编造内容。
- 不以字数、标题数量、链接数量或目录完整性代替内容质量判断。
- 方法的 strong / weak 要说明原因与成立条件；重复展示领先的实验可合并或省略。疑点仅保留影响核心理解、方法评价或实现的部分，无关紧要的笔误与琐碎排查不必写入或另建长记录。

## 从原始资料形成知识

### 重新 ingest

原项目的 `raw/` 完整复制并保持原始内容不变。新 Wiki 从原始论文、代码和其他证据重新研读与组织，不复制旧 Wiki，不以旧正文为底稿改写，不继承旧页面的完成或验证状态。

旧 Wiki 可以在用户要求时用于只读架构参考；新知识中的事实与结论必须回到原始证据核对。

### 研读成果的落位

不设置强制的独立“资料研读”层，也不要求每篇论文先生成完整读书报告。研读成果直接承接到相关知识中：基础定义进入基础页，共有机制进入通用机制页，具体算法进入相应子领域，实现和实验按其通用性与对象归属保存。

完整复现、逐节评审或复杂论文确有需要时，可以在相关主题下建立独立研读页。方法页本身已承担深度研读时，不再复制一份同样内容。

新证据若改变已有认识，应更新受到影响的页面，记录条件、分歧或修正理由。这里的反馈是更新 Wiki 知识，不是改写 `raw/` 原件。下载完成不等于研读完成，资料可以处于未研读或部分研读状态。

## 知识链接与页面身份

### 稳定命名与链接语法

知识页文件名使用全 Wiki 唯一的英文 kebab-case slug，frontmatter 至少包括 `title`、`slug`、`sources`、`updated`；`slug` 与文件名去掉 `.md` 后完全一致，`title` 和正文标题保留中文。目录仍按上述中文研究分类组织。`README.md` 是导航或规范元文件，不参与知识页身份与孤立页检查。

知识页之间统一使用无目录路径的 wikilink：`[[gptq]]` 或 `[[gptq|GPTQ]]`。显示名称应让读者知道目标内容；需要精确定位时使用实际存在的标题，如 `[[gptq#3. 单步补偿如何成立|GPTQ 的单步补偿]]`。Markdown 表格中的别名分隔符须转义为 `\|`。只链接已存在的知识页和章节，不用空链接代表待建页面。

无路径链接按文件名解析，不依赖自定义 frontmatter 解析器。适用于支持 wikilink 的阅读器；普通 Markdown 渲染器可能显示为原始文本。README 的知识入口也采用同一语法；Wiki 外的覆盖记录、规范与工具文档使用相对路径 Markdown 链接，以便直接定位文件。

移动目录时保持 slug；重命名 slug 时同步更新所有实际引用、导航、覆盖记录和工具中的路径，并在 Wiki 外留下旧名到新名的映射。不会为了建立不同主题的入口复制方法正文。

### 链接要解释知识关系

链接放在相关论述中，告诉读者目标页会补充什么；页尾“相关页面”仅作补充导航，不能代替正文关联。核心概念首次实质使用时，若进一步解释由已有页面承担，应给出简释与链接；不要求每次出现都重复链接。

| 关系 | 写法要求 |
|---|---|
| 前置知识 | 说明后续哪一步依赖该定义、符号或推导，当前页保留理解主线所需的解释 |
| 共同机制与方法实例 | 方法页链接通用机制的展开；机制页在相关论述中链接具体应用，并保留适用条件 |
| 实现与验证 | 从算法链接实际存储、算子或评测原理，说明它们如何影响方法能否落地 |
| 方法比较、边界与反例 | 写清比较维度、共同条件或分歧，再链接具体证据的知识承接页 |

按问题选择关联，不做全互链，不以链接数量验收，不为陌生术语机械建页。拆出页面须有独立解释价值；链接不能替代关键公式、成立条件和实验条件。

### 写入后回看相关页面

新建或实质更新知识页前，定位现有前置概念、共用机制、相关方法与实现页，复用唯一主页面。写入后检查这些页面是否需要增加实例、修正概括或补充边界；有实际阅读价值时，在相应段落增加指向新页的链接，不机械要求每条链接都有反向链接。

检查新页能否从相关知识的论述中进入。只有 README 入口但与其他知识没有语义联系，应作为待审查问题；确实独立的主题允许说明原因，不靠无意义互链消除告警。缺少必要概念页时，先保留本页所需解释并记录缺口，不创建空页或越过本轮授权扩展研究。

### 来源与覆盖记录

知识页必须以 frontmatter 的 `sources:` 保存直接支撑正文的原始资料路径，使用项目根目录下的 `raw/` 相对路径。聚合页只登记直接使用的证据，不照搬所有子页面的来源清单。

非目标参考资料中实际读懂并采用的知识同样进入 Wiki，并就近注明直接来源及章节；局部阅读范围记入 ingest 记录，不冒充全文研读，也不强制建立该参考论文的完整方法页。

知识页正文不放指向 raw 的超链接、嵌入或文件路径。重要主张就近用纯文本标明论文版本或快照、章节、公式、图表，或者代码 commit、仓库内文件与函数/行号；例如“（GPTQ v2，§4，算法 1）”。同页可在首次出现时定义论文和固定代码版本简称，后文复用。代码定位保留仓库内路径，不写 raw 存储路径；保留来源定位与事实区别，不把原始资料名称误改成知识页引用。

单独列出论文名称或仓库地址不足以支持精确核对。区分作者报告、代码阅读、我们的解释或推导、实际实验；教学示例不能标成模型复现。

每轮 ingest 先根据原件建立简短的核心内容覆盖记录，再检查它们在 Wiki 中的承接位置。记录原件位置、关键内容、承接页面或章节、覆盖状态及缺口影响。它是核对工具，不是另一份论文摘要。

自动抽取的 Markdown 仅是阅读入口。公式损坏、表格或图像丢失时，应回查作者源码或 PDF；未读附录、未核验图像和未运行代码明确说明，不宣称已经完整覆盖。

### 链接与来源检查

对本轮受影响页面合并检查：slug 与文件名一致且唯一、wikilink 目标及章节存在、表格转义正确、正文无 raw 跳转、`sources` 指向实际原件、受影响的导航和外部记录可定位。可从项目根目录运行 `python3 docs/wiki/check_links.py`（路径、链接、frontmatter 与表格转义）与 `python3 docs/wiki/check_citations.py`（正文 arXiv 号与来源元数据一致、正文 raw 引用是否登记、README 页数与收录、日期越界）；两者均为只读检查，通过只说明机械项通过，不代替内容判断与引用编号的人工回看。此只读检查不扫描整个 raw 库，仅核对登记的路径。

工具报告缺少知识入链或出链的页面，供人工判断。还需人工检查关键概念是否缺少关联、相关旧页面是否应回写、链接是否解释了关系，以及来源定位是否支持主张。自动检查通过不等于内容审查或论文复现通过。

## 研究与维护边界

- Wiki 保存可复用知识。论文当前方向记录在 [论文研究方向说明](../docs/thesis/研究方向.md)，开题报告作为可修订的研究起点；后续方案、章节和导师反馈按需放入 `docs/thesis/`，实验代码和日志的工作区按实际任务确定。
- Wiki 正文不依赖可变实验产物才能成立。需要长期引用的实验结论，应有稳定的数据、配置、版本和结果记录。
- 新研究议题、结构性调整与关键研究决策先讨论；已确认范围内执行前告知本轮目的与产出，完成后汇报结果与验证边界。遵守项目根目录的 [AGENTS.md](../AGENTS.md)。
- 新建、重命名、合并或拆分页面时维护实际存在的导航和引用；压缩或移除内容前，说明独特信息的承接位置或不再保留的依据。
- 按本轮改动做必要的内容、来源与链接检查，复用仍然有效的验证，不反复检查未改变的内容。
