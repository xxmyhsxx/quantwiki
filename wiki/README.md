# Wiki 维护规范

Wiki 是经过理解和组织的量化知识库。项目定位、来源范围、职责边界、当前画像与建设方向见项目根目录的 `SELF.md`；本文件规定知识页面的组织、表达、引用、维护与检查。阅读从 [INDEX.md](INDEX.md) 开始，资料研读范围与知识承接见 [READING.md](READING.md)，实际变动记入 [LOG.md](LOG.md)。

raw 按来源保存材料，Wiki 按知识对象和问题组织解释。一份来源可以更新多个页面，一个页面也可以综合多个来源。资料收录、论文研读、代码阅读和实际运行是不同工作，不能相互代替。

## 知识组织原则

- 按实际理解缺口逐步建设，依据正文判断需要补充什么，优先复用已有知识。
- Wiki 正文独立可读，必要解释、条件和来源身份随页面保留。具体研究计划、探索记录与实验代码放在项目的研究工作区，应用流程由相应工具或 Skill 承担；不为组织对称建立空目录。
- 来源中的特定结论保留模型、数据、配置和适用条件，不能直接写成普遍规律。当前研究问题不限定整个 Wiki 的知识范围。

## 目录与归属

```text
wiki/
├── README.md           维护规范
├── INDEX.md            知识地图与阅读入口
├── READING.md          资料研读范围与知识承接
├── LOG.md              变动记录
├── fundamentals/       公共基础
├── theory/             理论、机制与分析
├── methods/            具体量化方法
├── research/           对方法的进一步抽象
├── implementation/     工程实现与验证
└── assets/             图像及必要的配套材料
```

| 目录 | 主要回答的问题 | 边界 |
| --- | --- | --- |
| fundamentals/ | 进入量化领域需要理解什么 | 模型、推理、算子、数值格式、量化基础、数学与硬件基础；具体算法分析进入 methods |
| theory/ | 为什么成立、如何分析 | 可复用的误差、重构、敏感性、变换和预算分析；基本数学定义留在 fundamentals |
| methods/ | 某个量化方法怎样解决问题 | 问题、假设、机制、推导、流程、实现要求、主要依据与局限 |
| research/ | 方法之间揭示了什么更一般的问题 | 抽象问题结构、方法联系、技术路线与设计空间，保留条件和待检验假设；简单对照或排行榜不自动归入这里 |
| implementation/ | 如何在实际系统中执行和判断结果 | 存储与交换格式、kernel、runtime、部署、诊断和评测协议；理论机制由相应知识页承接 |

五类目录表达知识职责，不是固定的五级流水线。research 与 implementation 平级，分别承接研究抽象和工程落地。

fundamentals 的初始分类包括 `model/`、`inference/`、`quantization/`、`operators/`、`numeric-formats/`；有实际内容时可增加 `mathematics/`、`hardware/` 等。其他目录按内容需要建立二级分类，不创建空目录占位。

一个页面只有一个主归属。目录回答“放在哪里”，tags 表达跨目录属性，INDEX 提供学习路径、研究问题和工程链路等阅读视角。模型类型、量化对象和位宽不必同时变成目录层级。

## 页面身份与类型

知识页使用全库唯一的小写英文 kebab-case 文件名，中文标题便于阅读。方法保持唯一完整主页面；拆页须有独立解释职责或复用价值，拆分后主页面仍能连贯理解。比较和来源研读是页面类型，不单独决定目录。

最小 frontmatter：

```yaml
title: 页面标题
type: concept
tags:
  - ptq
  - weight-quantization
sources:
  - raw/papers/2026-09-21/awq/paper.pdf
```

| 字段 | 规则 |
| --- | --- |
| title | 必填，准确表达知识对象或问题 |
| type | 必填，选择本页主要解释职责 |
| sources | 必填，实际使用的来源文件；路径相对于项目根目录 |
| tags | 知识页必填，使用 YAML 列表，通常 2–5 个小写英文 kebab-case 标签；表达主要对象、机制或应用场景，同义标签合并 |
| aliases | 可选，常用中文名、英文全称或缩写 |
| updated | 可选，实质内容修订日期；目录迁移不冒充内容重新核验 |

优先复用已有标签，如 `ptq`、`vlm`、`weight-quantization`、`kv-cache`、`reconstruction`、`kernels`；只标注正文实际讨论的主题，不照抄目录名或 type，不用每页都有的泛标签。

文件名承担唯一身份，不再重复要求 slug 字段。README、LOG 是管理文件，不套用知识页模板；INDEX、READING 使用 `type: index`，纯导航允许 `sources: []`，不要求 tags。READING 记录资料处理情况，不计入五类知识页，也不代替独立有价值的 source 页。

| type | 解释职责 |
| --- | --- |
| concept | 定义、直觉、机制、必要公式、条件与相邻概念区别 |
| method | 方法目标、输入输出、步骤、成立原因、实现关系和限制 |
| implementation | 固定版本的入口、调用路径、布局、关键符号、运行条件和差异 |
| comparison | 同一问题下的对象与机制对照，明确共同口径、条件差异和不可比项 |
| recipe | 可执行步骤、前提、选择依据、检查点和失败边界 |
| question | 问题、已知事实、解释、缺口和可区分解释的验证方向 |
| source | 有独立价值的来源研读，说明问题、内容、版本与知识承接关系 |
| index | 主题结构、阅读顺序和有效入口 |

不要求每篇论文先建立 source 页，不机械复制空标题，也不为填满模板编造内容。

## 正文与解释深度

开头简明说明对象、核心机制和关键限制，正文按问题展开。相关内容应让读者理解：是什么、为什么需要、怎样工作、何时成立、依据是什么、怎样继续理解或使用。

- 前置知识已经充分解释时，说明与当前问题的关系并链接；核心解释不能只用链接代替。尚缺的必要知识在本页说明或补到适当页面。
- 公式解释符号、维度、假设和关键变形。原文公式、等价改写、整理者推导分别说明；近似与恒等式不能混用。
- 方法交代输入输出、步骤顺序、关键变量和参数选择。名称相同的损失应说明计算对象与归约方式。
- 实现说明保留固定版本及实际核对范围，按问题解释 dtype、shape、layout、packing、dispatch、fallback 和执行阶段。
- 正文引用的精度和性能数字保留决定含义的模型、任务、量化配置、硬件、batch、长度、测量口径与基线。局部 kernel 收益不能直接表示端到端收益，不同协议的数字不直接排名。
- 例子、反例和失败结果用于解释边界；教学计算不冒充模型实验。未读、部分覆盖、待核实与不适用分别说明。

页面类型、字数和标题数量不能代替解释质量。原文抽取损坏公式或图表时回查原件；摘要阅读不表述为全文研读。

## 来源与引用

`sources` 登记直接使用的原始材料：论文 PDF 或 TeX、干净文章正文、固定版本代码等。填写具体文件，不填目录、通配符、绝对机器路径或普通知识页；不为齐全罗列没有使用的载体。论文和文章的 README 用于辨识来源，不代替正文依据。

正文就近用纯文本标明版本、章节、公式、图表或仓库内文件与函数位置，例如“GPTQ v2，§4，算法 1”。本地 raw 路径留在 frontmatter，不在知识正文中链接或嵌入 raw。

Wiki 不依赖本地 raw 才能辨识来源：在页面的“来源身份”中保留标题、明确版本和外部 URL；正文中的来源 URL 用行内代码保存，避免渲染成外部链接。可变网页同时保留获取时间与快照标识。多个代码文件来自同一版本时可合并一行。已删除本地代码快照的历史引用允许在 `sources` 登记 GitHub 完整 40 位 commit URL；不得静默改指新版。去掉链接时保留来源身份与定位信息，不删除证据。

使用本地实验时，登记研究工作区中固定的记录或结果，保留实验条件。无公开来源应说明获取方式和核验限制，后续重跑不能悄然替换已引用结果。

区分作者报告、官方定义、代码核对、本地实验、整理者推导和待验证推测。代码阅读不能证明路径实际运行；评审意见与作者回应保留归属，不直接当作已证实结论。

发现冲突时先核对版本、术语、条件与范围；未能解释的差异并列保留。修正结论时检查依赖它的页面，不用统一的“已验证”标签掩盖不同主张的状态。

## 知识链接与页面身份

Wiki 所有页面（含导航和管理页）的正文可点击链接、图片与附件引用，只能指向 `wiki/` 内实际存在的文件或当前页章节。不得链接 `raw/`、项目根目录、研究工作区或外部网站；路径解析后越出 Wiki 的符号链接也不允许。`sources` 是来源登记，不是知识关系，不受正文点击边界限制；代码示例和行内代码中的来源地址也不作为知识链接。

正文统一使用标准 Markdown 相对链接，知识页目标包含 `.md`。链接和图片相对于当前文件，frontmatter 的 sources 相对于项目根目录；两种基准不能混用。章节锚点须对应实际标题，不使用 wikilink。静态锚点存在不保证客户端正确跳转；有兼容提示时定向验证实际跳转，再选择可靠的章节链接或整页链接。

链接放在具体论述中，使读者能从上下文理解为什么需要目标内容；目标页须实际承接所需解释。前置、机制、实现、比较、边界或证据关系都是可能用途，不是固定类别。核心解释在本页讲清，不靠链接替代。只因名称相近、目录邻近或想增加连线而建立的关系应去掉；上下文已有明确用途时不重复补一句说明。文末相关页面只作补充，不要求机械互链。文件名和显示标题可以不同，移动或改名后同步维护链接、锚点、索引和外部入口。

INDEX 只组织已经存在的知识，可按问题建立多种阅读路径。新的研究认识进入相应知识页，不藏在导航说明里。

图像与附件放在 `assets/<page-name>/`，正文使用相对路径。必要来源图可保存展示副本，注明出处、版本、图号及裁剪/重绘/翻译情况；示意图与测量结果分开。教学计算脚本及其历史结果可作为配套材料，不能替代正文解释。

## 如何进行链接 lint

链接 lint 是只读检查：先检查点击边界与目标有效性，再阅读链接上下文判断关系用途。机器通过不能证明关系合理，也不代替事实与来源审核。

1. **确定范围。** ingest 或链接修改后，检查本轮受影响页面；移动、删除文件或改标题时检索旧路径与锚点，纳入引用它们的页面。首次建立基线或明确维护全库时才做全 Wiki 检查；不扫描 raw 原件。
2. **运行机械检查。** 从项目根目录使用现有检查器的链接模式：

   ```bash
   # 全 Wiki 只读基线
   python3 -B .agents/skills/wiki-review/scripts/check_wiki.py --root . --links-only
   # 本轮页面或目录；多个路径用空格分隔
   python3 -B .agents/skills/wiki-review/scripts/check_wiki.py --root . --links-only --paths wiki/README.md
   ```

   输出 JSON，含文件范围、计数、问题位置和覆盖限制。检查内联与引用式 Markdown 链接、图片、自动链接、常见裸 URL，以及 HTML 的 `a[href]` 和 `img[src]`；排除 frontmatter、代码块、行内代码、注释和未使用的引用定义。越界与缺失目标报错；章节静态检查支持标题文字、GitHub 式 slug 与 HTML 显式锚点。中文标点被 slug 删除的已知兼容风险、可识别但无法解析的链接候选列为待核。其他 Markdown 扩展及客户端跳转未验证，不能声称语法全覆盖。

   默认有错误退出 `1`，仅有待核项退出 `0` 并标为 `needs_review`；加 `--strict` 时待核项也退出 `1`。非法参数退出 `2`。指定路径不存在、越出 Wiki 或未选中 Markdown 时明确失败，不能空跑通过。
3. **复核关系用途。** 对本轮新增或变更的知识关系，读取源段落与目标相关内容：读者此处需要什么、目标是否回答、去掉链接会损失什么。知识链接与导航入口分别按其用途判断，不以链接数量、连通度或标题相似代替内容判断。存量关系采用抽样时明确样本与未读范围；用途无法确认的保留为待核，不自动删除。
4. **报告与复查。** 分别报告机械结果、上下文复核范围、具体问题及理由、建议动作与待核项。获得修复授权后按范围修改，再复查受影响页面和回链。删除外部来源链接时保留标题、版本、URL 和具体定位。

本轮受影响范围内没有已知越界或确定失效的链接，新增或变更关系已经上下文复核，才可报告相应范围完成；待核项仍需明确列出。全 Wiki 机械基线不等于逐条审过全库知识关系。

## 维护、记录与检查

修改前阅读目标及相关页面，优先复用已有知识。迁移、合并、拆分或删除时保留独特内容的承接位置，并同步引用、索引与资源。新证据改变认识时更新相关页面。

实质修改改变主线的覆盖、解释深度、缺口或下一步时，同步更新项目根目录 `SELF.md` 的“当前知识画像”部分，保留判断依据与日期。格式修订不要求重做全库画像；已解决的缺口不继续作为待办。

LOG 按日期记录新增、迁移、合并、删除和影响理解的重要修订；同批合并说明对象、原因、检查结果与遗留影响，不逐条记录命令或复制正文。具体主张的限制保留在相应页面。

READING 按确定来源版本记录实际研读范围、Wiki 处理结果与承接页面、尚未核查内容及有依据的研读日期。研读或代码核对后同步相关记录；已有知识充分、无需新增页面时也可记录。论文用明确版本，代码用完整 commit，网页用版本或快照身份。同一资料的部分研读不表述为全文核验，引用登记不自动等于完整研读。补历史记录时回看正文与 LOG；只有使用证据、范围或日期不明时如实标明。目录没有记录只表示暂无确认记录，不直接认定未读。raw 的完整性检查不等于来源内容研读。

按改动范围核对目录、元数据、链接、资源、来源和导航；复用仍有效的检查结果。缺少本地 raw 时明确说明来源文件未核验。

检查通过只表示所列机械项通过。事实、推导、数值、归因、解释深度和跨页一致性仍按实际任务回看来源；不把目录整理或链接通过写成全面内容审查、模型复现或性能验证。
