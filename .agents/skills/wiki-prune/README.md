# Wiki 精简

## 1. 任务与设计目标

保留有效知识，删去重复和空泛内容，合并不必要的碎片页。以关键问题仍能回答、独有内容得到保留、阅读更顺畅为目标，不设字数或页面压缩比例。

## 2. 使用边界

用于用户指定的页面、主题或全库精简，无需先做完整 wiki-review。按授权修改；只分析时给出具体位置、理由和内容去向。

## 3. 输入设计

目标 Wiki 入口、精简范围、用户指出的问题及已有改动。

## 4. 原则设计

判断一段内容是否提供必要的定义、机制、推导、条件、证据、例子或反例。措辞相似不等于知识相同；方法旧、内容基础、近期未使用或篇幅长，都不能单独作为删除理由。

## 5. 工作流程设计

公共机制可集中维护，各页仍需保留理解当前问题所需的概述和联系。合并时先确定独有内容放在哪里，再处理旧页；没有合适位置时保留原文。整个研究方向是否退出 Wiki，另行讨论。

## 6. 输出设计

交付精简后的内容，说明重要取舍、独有内容去向、检查结果和遗留问题。

## 8. 校验设计

从原入口重读，确认合并后的内容仍回答原问题。重点防止两类误删：把条件不同的相似表述合并；删掉长推导中独有的反例。链接有效还需检查跳转是否造成多余往返。
