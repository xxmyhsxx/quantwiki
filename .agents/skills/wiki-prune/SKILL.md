# Wiki Prune

## 任务

**保留有效知识，减少冗余，改善知识组织和阅读路径。** 从段落与章节判断内容的作用，再决定是否调整页面。

以关键问题仍能回答、独特知识得到承接、重复阅读减少为完成标准。字数与页面数只描述改动，不设压缩比例。方法新旧、使用频率、知识是否基础及篇幅长短，都不能单独决定去留；整个研究方向的取舍另行讨论。

## 输入

目标 Wiki 入口与剪枝范围，可结合用户指出的重复、过碎或冗长问题。读取目标组织规范、相关正文和已有改动，按需要查看关联页面、引用与来源。

## 原则

- **按解释作用取舍。** 判断内容是否增加定义、机制、推导、条件、证据、例子或反例；措辞相近不等于知识相同。
- **保留独特知识。** 合并或移动时保留独有信息、适用条件及来源，依据页面职责与内容质量选择主要解释位置。
- **保持局部可读。** 公共机制集中解释，各页保留理解当前问题所需的概述与联系，核心解释不能只用链接替代。

## 工作步骤

### 1. 明确解释职责

读取指定范围和必要的关联内容，明确页面与主要章节各自回答什么问题，以及哪些推导、条件、证据和例子承担关键作用。用这些问题作为剪枝后的阅读检查依据。

检索与相似内容匹配只用于定位候选，取舍依据实际正文。局部任务沿受影响内容展开；全库任务须覆盖相应范围。

### 2. 判断与取舍

比较候选内容的含义、条件和用途，再选择处理方式：

| 内容情况 | 处理 |
| --- | --- |
| 相同结论反复换句话说，没有新增解释 | 删除或合并重复表述 |
| 多页重复完整的公共机制 | 选择主要解释位置，其他页面保留必要概述及与当前问题的联系 |
| 碎片页没有独立解释职责，但含有独特内容 | 将独特内容并入合适页面，再处理旧页 |
| 提醒、评价或总结没有具体信息增量 | 删除 |
| 内容有效，但偏离本页问题 | 移到更合适的位置 |
| 相似表述采用不同条件、版本或证据 | 保留差异，必要时集中对照 |
| 结论有事实或证据疑点 | 定向回查来源后修正，未解决的疑点如实保留 |

对重要删减说明理由，对合并或移动确定独特内容的承接位置；没有合适承接位置时保留原内容。短概述、应用解释、例子和反例按其阅读作用保留，不能仅因别处出现相同概念就删除。

### 3. 执行剪枝

在授权范围内精简正文、合并或移动内容。先将独特内容及来源落实到承接位置，再删除被替代的段落或页面；调整后保持定义、推导、条件与结论连贯。

同步受影响的链接、章节锚点、来源登记、资源和导航，按目标 Wiki 约定记录实际变动。只要求分析时，交付具体拟改位置、理由和承接方式。

### 4. 沿阅读路径复核

从实际入口重读受影响内容，对照第一步的关键问题，检查它们能否回答、推理是否连贯、必要条件与证据是否仍在、独特知识是否完成承接。

改为链接的内容要读取目标，确认它确实提供所需解释，并检查阅读是否产生不必要的往返。发现解释断点时恢复必要内容或调整承接方式。

合并执行与改动范围相称的格式、链接、来源路径和资源检查。机械检查验证结构，正文阅读判断知识是否保留完整。

## 输出

主要交付是剪枝后的 Wiki。简要说明处理范围、重要删减与合并的理由、独特内容的承接位置、实际检查与遗留问题。只分析的建议与实际完成的修改分开说明。

## 校验

- 关键问题、推导、条件、证据和反例是否仍有充分解释？
- 删除或合并是否消除了真实冗余，独特内容是否已在承接位置保留？
- 阅读路径是否更清楚，当前页面是否仍能连贯理解？
