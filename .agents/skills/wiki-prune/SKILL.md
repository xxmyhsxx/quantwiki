# Wiki 精简

按用户指定范围与授权处理；只要求分析时给出拟改位置、理由和内容去向。字数、页面数、方法新旧、使用频率和内容是否基础，都不能单独决定去留。整个研究方向的取舍另行讨论。

## 1. 弄清内容在回答什么

读取目标规范、正文、已有改动和必要关联页，明确页面及主要章节回答的问题，找出必须保留的推导、条件、证据、例子和反例。局部任务沿受影响内容展开，全库任务覆盖相应范围。

检索与相似匹配只用于找候选，取舍依据实际含义、条件和用途。

## 2. 决定保留、合并或删除

| 内容情况 | 处理 |
| --- | --- |
| 重复结论或空泛提醒，没有新增信息 | 删除或合并 |
| 多页重复公共机制 | 选一个主要解释位置，各页保留必要概述和与当前问题的联系 |
| 碎片页无独立用途，但有独有内容 | 先将独有内容及来源并入合适页面，再处理旧页 |
| 内容有效，但偏离本页问题 | 移到更合适的位置 |
| 看似相同，实际条件、版本或证据不同 | 保留差异，必要时对照说明 |
| 事实或证据有疑点 | 定向查证，修正可确认问题，保留未解决部分 |

重要删减说明理由，合并或移动明确内容去向；没有合适位置时保留。短概述、应用解释、例子与反例按当前阅读需要保留，不能只因别处也有同一概念就删除。

## 3. 修改并复核

先落实独有内容和来源，再删除被替代内容。公共机制可以集中，当前页面的核心解释不能全部换成链接。同步受影响的链接、锚点、来源、资源与导航，按目标约定记录变动。

从实际入口重读，对照第 1 步的问题检查解释是否连贯、条件和证据是否保留。改成链接的内容须读目标，确认能回答问题且不造成多余往返；有断点时恢复必要解释或调整位置。

合并执行与改动相称的格式、链接、来源及资源检查。正文阅读判断知识是否保留，机械检查验证结构。

交付处理范围、重要取舍及理由、独有内容位置、实际检查和遗留问题，区分建议与已完成修改。
