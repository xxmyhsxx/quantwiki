# Wiki Query

## 任务

在 Wiki 中定位真正处理某个问题、主题或方法的知识位置，交付可核对的定位结果：**要理解这个问题该读哪里，这些位置各自处理什么。** 交付定位而非解释——机制解释、推导、评价与研究建议由用户或调用方完成。

## 输入

待查的问题、主题、方法名或一段待定位的表述。可选：范围限定（子领域、目录、页面集）与粒度（一页／位置集）。未限定时检索全部知识页；未指定时给足以支撑理解该问题的最小位置集。

## 原则

1. **命中不等于覆盖。** 标题、搜索片段与导航只用于定位；是否处理该问题依据读过的正文，不是是否出现同一个词。
2. **定位可核对。** 只给实际存在且已读到的文件与章节，不编造文件名、章节号或标题。
3. **未找到与未核实分开。** 保留检索词与覆盖范围；检索失败、正文不可读记为未核实，不写成「Wiki 没有」。
4. **只读且只定位。** 不改页面、不启动 ingest 或审查；不展开机制、不做推导、不给研究建议。

## 工作步骤

1. **定知识点。** 从待查对象抽出核心术语；问题含糊时按最可能的核心概念试查再收敛。
2. **两路检索。** `rg --files wiki` 查英文文件名，`rg -n "关键词" wiki` 查中文标题、术语与机制描述。不中时补查中英文名、别名、方法名、机制特征、相邻方法名；需要目录背景时读 `wiki/INDEX.md` 的阅读入口。
3. **读正文判定。** 标准是这一处能否回答该问题；相关但不等价的内容不当作命中，说明概念边界。
4. **按需补相邻位置。** 直接命中不足时沿正文链接 追前置、共同机制、比较、实现与验证。链接按 [Wiki 链接规范](../../../wiki/README.md#知识链接与页面身份) 解析：Markdown 链接按当前文件目录解析，`#` 后为标题锚点，显示文字不是文件名。只纳入实际存在且读到所需内容的章节。
5. **交付。** 按与问题的关系分组或排序（直接回答／前置／机制／比较／实现验证）；未找到时说明检索词、范围，指出更像知识缺口还是定位失败。用户要求核验原文时按 `sources` 定向回查并说明范围，不扫描 `raw/`。

## 输出

每条定位 = 可点击的绝对路径 Markdown 链接 + 实际章节 + 一句「该处处理什么」；结尾交代检索范围与未核实部分。

```text
[wiki/量化/大语言模型量化/smoothquant.md](/Users/xiao/Desktop/量化/wiki/量化/大语言模型量化/smoothquant.md) §3 缩放如何在两侧分配难度 → 处理「为什么可以把激活的量化难度迁移到权重」
```

不落盘检索日志、覆盖矩阵或状态文件。

## 校验

- 每条定位都来自实际读过的正文，路径与章节可直接打开；
- 未找到的结论带有检索词与范围，未核实没有被写成「Wiki 没有」；
- 没有修改任何文件，也没有代用户解释、推导或给建议。
