# 使用 Wiki 回答问题

围绕当前问题定位和使用知识，给出有解释、有依据、有适用边界的回答。默认只读，不因查询发现缺口就自动修改页面、下载资料或开始 ingest。

## 定位与阅读

- 从问题、已知页面或方法名开始，用 `rg --files wiki` 和定向全文搜索定位实际知识页；需要目录背景时才读 Wiki README 的相关部分。不固定阅读页数，不预读全套规范、历史记录或旧 Wiki。
- 阅读支撑回答的正文，不能仅凭标题、导读或搜索片段下结论。按实际需要沿前置概念、机制、方法比较、实现与验证的链接继续阅读。
- 按 [Wiki 链接规范](../../../wiki/README.md#知识链接与页面身份) 解析链接：目标 slug 对应唯一文件名，别名只是显示名称，`#` 后为目标章节。不要把中文显示名当成文件名；不依赖旧项目的检索工具或目录布局。
- 找不到时，先检查同义词、方法名、关联页和已有导航，再区分知识缺失与定位失败。找到足够证据或确认具体缺口后停止扩展。

## 回答与证据

- 先回答问题，再解释必要机制和条件，引用实际读过的知识页。对话中使用可点击的绝对文件路径 Markdown 链接；知识页内部的 wikilink 规范不强制用于对话展示。
- 区分论文报告、代码阅读、教学推导和实际复现；保留相关版本、公式、实验条件与未验证事项。需要计算或额外推导时明确标为本次解释，不冒充 Wiki 已有结论。
- 默认依据 Wiki 回答。用户要求核验原文，或具体争议需要回查证据时，只定位相关 sources 与原文片段，说明核验范围；不自动扫描 raw，也不以局部回查声称完成全文研读。
- 无法回答的部分明确说明。确有缺口时，简述是缺知识、解释太浅、导航困难还是证据冲突，并给出最小补充建议；不为每次正常查询生成反馈报告或启动全库审查。

仅要求创建或修改本 Skill 时，处理 Skill 本身，不执行示例查询。若用户同时授权补写或修复，继续完成明确范围内的工作，沿用项目规范和已有授权，不因跨 Skill 重复确认。
