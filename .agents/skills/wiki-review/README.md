# Wiki 审核

## 1. 任务与设计目标

审核指定页面、主题、一次变更或整个 Wiki，找出事实、证据、解释、结构和页面关系中的问题，并提出有依据的修改建议。默认只读；用户要求修复时处理已授权范围。

## 2. 使用边界

从用户指定范围和现行规范开始，按具体疑点补读。全库结论需要相应覆盖，抽样说明样本和未覆盖部分；工具输出不能自动扩大修复范围。

普通查询和写入后的例行自检不触发完整审核。只要求链接检查时，不扩展为科学主张核验。

发现缺口不自动开展入库或全库整理。

## 3. 输入设计

用户指定的审核范围与重点、Wiki 正文、项目规范、来源记录及仍有效的检查结果。

## 4. 原则设计

深度取决于页面要回答的问题，不以篇幅、标题数或链接数判断。领域知识用于提出待核问题，不能代替实际阅读。未核实不等于错误，合理差异不应被抹平；无问题时据实报告。

## 5. 工作流程设计

结构、证据和解释分别检查：工具发现路径、锚点和登记问题，原件核对主张，正文阅读判断对象的作用、整体方法和步骤关系是否讲清。任何一项通过都不能代替其他两项。

从理解断点补读关联页，必要时沿来源登记查原件；既检查已有文字是否错误，也检查回答当前问题所需的知识是否缺失。先查候选正文，避免把没找到链接误判为全库没有知识。

## 6. 输出设计

报告围绕发现组织，给出位置、依据、影响和最小建议，说明实际阅读、原件核验与机械检查范围。规范违规、内容问题和可选写法分别处理；修复结果仅在实际修改时报告。

## 8. 校验设计

发现必须能定位到正文或证据，结论不能超出实际覆盖范围。重点防止流畅措辞掩盖错误、有效链接被当作充分解释，以及将未核实判成错误。
