# Wiki 审核

审核指定页面、主题、一次变更或整个 Wiki，找出事实、证据、解释、结构和页面关系中的问题，并提出有依据的修改建议。默认只读；用户要求修复时处理已授权范围。

## 怎样判断质量

| 检查对象 | 判断依据 |
| --- | --- |
| 事实、公式、数字和归因 | 与来源原件及适用条件对照；核心主张主动核验，其余按疑点或说明过的抽样范围检查。 |
| 来源与引用 | 登记、路径和编号正确只是起点，还需确认来源内容支持该项主张。 |
| 解释是否充分 | 依据正文能否说明对象是什么、起什么作用、整体怎样工作，以及关键部分如何配合。 |
| 页面关系 | 读取源段落和目标内容，判断链接是否补足读者当前需要的解释。 |
| 跨页差异 | 先核对对象、术语、版本和条件，再判断是否矛盾。 |
| 必要知识缺口 | 说明缺少什么及影响，再搜索相关名称、别名和机制，区分知识缺失与连接不足。 |

深度取决于页面要回答的问题，不以篇幅、标题数或链接数判断。领域知识用于提出待核问题，不能代替实际阅读。未核实不等于错误，合理差异不应被抹平；无问题时据实报告。

## 范围与分工

从用户指定范围和现行规范开始，按具体疑点补读。全库结论需要相应覆盖，抽样说明样本和未覆盖部分；工具输出不能自动扩大修复范围。

普通查询和写入后的例行自检不触发完整审核。只要求链接检查时，完成机械检查与链接用途判断，不扩展为科学主张核验。代表问题的阅读检查用于定位解释断点，不等于正式对照评测。

发现缺口后交付建议，不自动开展入库或全库整理。合并、压缩和删除建议要说明独特知识、条件、证据与有用链接如何保留。

## 工具与证据

[scripts/check_wiki.py](scripts/check_wiki.py) 是只读结构检查器，输出 JSON，覆盖格式、路径、锚点、来源登记与导航等机械项目。具体调用和覆盖限制见 [SKILL.md](SKILL.md)；链接规则以目标 Wiki 为准。已有结果仍适用时复用，工具无法运行时完成可做的直接检查并说明限制。

来源按页面登记定向读取，不把整个 raw 作为输入。核验事实、引用编号与主张支持关系仍需阅读原件，机械通过不能替代这些判断。

## 结果与维护检查

报告围绕发现组织，给出位置、依据、影响和最小建议，说明实际阅读、原件核验与机械检查范围。规范违规、内容问题和可选写法分别处理；修复结果仅在实际修改时报告。

维护时重点检查：流畅但错误的主张、有效链接却无对应解释、来源不可得、版本差异、未提及的必要知识、局部修复与限定链接任务。根据改动选择场景，静态走查和实际审核分别报告。

本目录包括设计与执行文档、检查器及其测试、展示配置与图标；没有独立 references。详细规则放在执行规范或项目规范中，不在这里再维护一套。
