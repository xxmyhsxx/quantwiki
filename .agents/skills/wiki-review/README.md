# Wiki 审核

## 1. 任务与设计目标

审核指定 Wiki 内容是否让目标读者理解对象的用途、整体工作方式和关键依据。仅审核时给出有依据的发现；用户要求改善时，交付经过重写、整理和复核的正文。

## 2. 使用边界

从用户指定范围和现行规范开始，按具体疑点补读。全库结论需要相应覆盖，抽样说明样本和未覆盖部分；工具输出不能自动扩大修复范围。

普通查询和写入后的例行自检不触发完整审核。只要求链接检查时，不扩展为科学主张核验。

发现缺口不自动开展入库或全库整理。

## 3. 输入设计

用户指定的审核范围与重点、Wiki 正文、项目规范、来源记录及仍有效的检查结果。

## 4. 原则设计

深度取决于页面要回答的问题，不以篇幅、标题数或链接数判断。领域知识用于提出待核问题，不能代替实际阅读。未核实不等于错误，合理差异不应被抹平；无问题时据实报告。

## 5. 工作流程设计

先从读者理解出发检查解释，再核对事实与证据、结构与链接。每句话都正确，读者仍可能不知道为什么需要这个方法，或怎样把局部机制接成整体；因此解释问题不以事实出错为前提。

从理解断点补读关联页，必要时沿来源登记查原件；既检查已有文字是否错误，也检查回答当前问题所需的知识是否缺失。先查候选正文，避免把没找到链接误判为全库没有知识。

已授权改善时，依据这些断点重组解释顺序、补清因果、合并重复内容，并保留有用细节。事实核验保证重写准确，不能取代重写；完成判断落在正文是否更易理解，而非报告列了多少问题。

## 6. 输出设计

审核交付发现与依据，改善交付修改后的正文及简短说明。分别说明实际阅读、原件核验与修改范围，保留未解决问题；过程记录不代替知识成果。

## 8. 校验设计

从改后正文复述用途、整体过程与取舍，检查读者能否独立接上解释，再核对事实和条件是否保留。发现必须能定位到正文或证据，结论不超出覆盖范围；既防止流畅措辞掩盖错误，也防止细节正确掩盖整体难懂。
