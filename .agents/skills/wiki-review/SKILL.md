# 审核 Wiki 质量

## 任务

审核 Wiki 当前的页面内容、结构和页面关系，发现并核实具体问题，主动提出指定范围内的必要知识缺口，交付有依据的结论与最小修改建议。

运用当前主题所需的专业知识提出检查问题、识别可疑主张和知识依赖；通过实际读取 Wiki 与来源材料确认发现。审核者知道某个机制，不代表页面已经解释了它。

默认只读。用户同时要求修复时，直接处理已授权、低风险且范围明确的问题；重要取舍按已确认的项目约定处理。仅要求创建或修改本 Skill 时，不开始实际 Wiki 审核。

## 输入

从用户请求和项目现状取得审核范围、重点及修复要求，不要求固定表单。以实际项目根目录解析项目路径：

- 先读指定范围内的 Wiki 正文，再按具体问题补读必要关联页。
- 复用已读且未变化的项目规则；规则不清楚时，只补读 `wiki/README.md` 等规范的相关章节。
- 根据页面 `sources:` 定向读取原件，以及来源条目的 `README.md`。原件可包括论文、LaTeX、代码文件和实验材料。
- 已有检查结果、变更信息存在且仍适用时复用。变更记录不是审核前提。

不以整个 `raw/` 库作为前置输入，不自行要求独立来源页、能力自述页、固定日志或全套模板。必要材料不可得时，完成不依赖这些材料的检查，并说明核验限制。

## 原则

1. **依据材料判断。** 不凭记忆断言知识已存在或缺失；来源登记、有效路径和工具通过都不证明事实正确。
2. **区分问题与核验状态。** 分别说明事实错误、证据缺口、解释不足、结构问题或可选优化，以及相关主张已核验到什么程度。未完成查证不能直接判为幻觉。
3. **依据当前职责判断质量。** 深度与完整性取决于当前内容需要讲清什么。不能按篇幅、标题数或链接数判断，也不能把个人写法偏好当作项目规范。
4. **有范围地发现缺口。** 主动检查未提及但必要的知识；领域知识形成候选缺口，实际查找确认承接情况。仅仅相关不足以构成缺陷。
5. **保留知识价值。** 压缩、合并或删除建议先说明机制、独特证据、条件、反例和链接用途的保留与承接。基础知识不能因“常见”被判为低价值；无法证明承接完整时保留原内容。
6. **结论与覆盖相称。** 抽样结果只覆盖实际样本，全库结论需要相应覆盖。无问题时据实报告，不凑缺陷，不输出没有评分依据的总分。

## 工作步骤

按本轮范围和内容适用性执行以下步骤。用户限定审核维度时遵从其要求，补查材料只服务于当前判断；无法完成的检查明确说明限制。

### 1. 确定范围和审核依据

确认用户指定的入口、重点、修复授权及适用规范，阅读范围内页面，识别它们承担的内容和需要核对的来源。

将内容阅读范围、机械检查范围和原件核验范围分别记清。主题或全库审核采用抽样时，说明选取依据和未覆盖部分；不预设固定比例。

从当前范围沿相关链接及具体待核问题定向扩展。围绕概念、别名、方法或来源检索其他位置时，只补读与当前判断直接相关的命中内容。范围不明确且会影响工作时再澄清，不重复询问已明确的信息。

### 2. 检查格式、路径和结构

判断现有机械检查结果是否仍适用。需要新增检查时，先确认项目脚本可用及实际检查范围，再在项目根目录合并安排：

```bash
python3 .agents/skills/wiki-review/scripts/check_wiki.py --root .
```

从项目根目录运行随包工具 [scripts/check_wiki.py](scripts/check_wiki.py)。工具只读，仅依赖 Python 3.9+ 标准库，检查目录、frontmatter、标签、链接与锚点、表格结构、来源路径、arXiv 登记一致性和导航；输出 JSON，发现错误时返回非零退出码。缺少 `raw/` 时明确跳过本地来源核验，要求来源完整时加 `--require-raw`。只在需要相应机械检查时运行，不要求每次维护都做全库检查。

脚本不核实科学主张或引用编号，也不覆盖所有来源登记和内容问题；按本轮范围补充直接核对，不另建同功能工具。

检查范围内的输出，并结合页面用途确认是否构成问题。孤立页等提示不自动等同于内容缺陷；全库工具输出不扩大本次局部处理范围。工具缺失或不能运行时，采用可完成的直接检查并报告限制，不另建同功能工具。

同时阅读段落上下文，检查公式、表格、列表与引导句是否正确衔接。机械检查通过后，仍继续核对内容、引用编号和证据支持关系。

### 3. 核验事实、证据和引用

在实际审核范围内，主动围绕核心结论、关键数字、公式和重要归因回查来源，不只回查读起来可疑的内容。其他内容结合疑点与抽样检查；范围较大时说明选择依据，未覆盖主张保留为未核验。

对每项待核主张，读清上下文、对象和条件，再按 `sources:` 定位相应原件，检查：

- 数字、公式、对象、因果或归因是否与原件相符。
- 来源是否提供对应支持，是否把缺乏依据的内容写成确定事实或作者结论。
- 作者报告、教学解释、代码阅读、计划验证和实际实验是否混用。
- 精度、存储、算子性能和端到端收益是否被混淆或作出未经支持的推导。
- 假设、适用条件、反例或限定是否被省略，导致结论扩大。

核验引用时落实以下动作：

1. **读取来源标识。** 从来源条目的 `README.md` 读取论文编号、版本和 commit，不凭 PDF 水印、记忆或二次来源补猜。记录缺失、记录与原件冲突时报告来源元数据问题，不直接猜改知识页；正文与记录一致只证明登记一致。
2. **回查具体编号。** 章节、附录、表、图和算法编号回到 LaTeX 或 PDF 核对。抽取文本未包含内容，不代表原件没有该内容或编号。内容已核实而编号无法确认时，建议按内容定位；内容本身未核实则保留待核状态。
3. **检查来源登记。** 按项目规范在 `sources:` 登记直接使用的原始材料具体文件；本地 `raw/` 路径留在 frontmatter，不在知识正文中链接或嵌入。正文就近以版本、章节、图表或代码位置定位证据，并在“来源身份”保留标题、版本和外部 URL。核对引用是否由登记材料承接，纯举例与实际来源引用分开。
4. **区分检查结论。** 机械登记一致不等于来源、引用编号或正文正确；需要逐项核对的编号仍由原件查证。

根据回查结果说明确认的错误、证据不足的主张和未核验内容。原件不可得或暂时找不到依据时，不直接判为已确认幻觉；来源之间存在冲突时，说明冲突发生在哪一层及尚未解决的部分。

### 4. 检查深度、关联和跨页一致性

按当前内容的职责，检查核心问题、符号、公式、机制、推导和算法步骤是否连贯，必要的假设、反例、消融和实现条件是否被遗漏或过度压缩。只检查适用项目，不要求每页齐备全部栏目。

发现解释断点时，读取相关前置页，确认它是否真的提供所需内容。已有内容能够承接的，提出连接或定位建议；目标页也有缺失的，指出具体补充位置。必要时选少量代表性问题沿正文与链接进行阅读检验，将无法解释之处定位到具体断点；这不构成正式对照评测。

比较相关页面的术语、定义和结论，先核对对象、版本、条件和证据层级。合理差异需要明确边界；无法由这些差异解释的矛盾，才作为跨页一致性问题。根据实际发现判断相关旧页是否需要增加实例、修正概括或补充条件。

### 5. 主动发现并提出关键知识缺口

依据领域知识，检查当前页面或主题是否缺少理解机制、支撑结论、判断适用条件或使用知识所必要的内容，包括现有页面完全没有提及的知识。

对每个候选缺口依次处理：

1. 说明缺少什么，它与当前内容存在什么依赖，缺失会造成什么具体影响。
2. 围绕概念、别名、方法或来源定向检索 Wiki，补读直接相关的命中内容。不能仅凭当前页没有链接就判断知识不存在。
3. 根据实际结果，区分已有内容但连接不足、已有内容深度不足、相关内容缺失，以及查找不足以确认的情况。
4. 给出补充建议：需要补充的内容与程度、建议由哪个现有页面承接，或为什么需要新增页面。查找范围有限时，使用“本次查找范围内未找到”等与证据相称的表述。

依据必要性提出关键缺口，普通延伸内容列为可选建议。交付缺口、依据、查找范围、影响和建议位置，不因发现缺口自动启动论文 ingest、正式评测或全库整理。

### 6. 整理发现，按授权修复

合并同一问题的重复发现，保留各受影响位置。违反现行规范时指出对应条款；其他问题给出事实、证据或知识依赖上的依据，将可选优化分开说明。

提出压缩、合并或删除时，先列出必须保留的内容、链接用途和承接位置，确认没有丢失机制、独特证据、条件或反例。

已授权修复时，处理范围明确的问题；重要取舍按已确认的项目约定处理。插入段落后回看前后各一行，必要时扩展到完整段落，确认没有截断“引导句—公式／表格／列表”的关系。涉及编号或来源的修改重新核对相应依据。

合并修改后，只对直接受影响的内容进行必要验证，按需运行相关机械检查，避免逐处重复运行。

## 输出

默认在对话中交付审核报告，用户要求文件时再落盘。按实际工作提供：

- **范围与核验情况：** 已读页面、补读范围、抽样依据、机械检查及复用结果、实际回查的主张数量和类型，以及未读和未核验部分。
- **已有可用内容：** 简要说明本次确认可用或无需修改的内容，不逐页凑评价。
- **审核发现：** 每项说明具体页面／章节／段落或页面组合、问题及依据、核验状态、影响和最小修改建议；区分规范违规与可选改进。
- **关键知识缺口：** 说明所属范围、必要性、查找情况、当前承接、影响和补充建议，可并入对应发现，避免重复报告。
- **修复结果：** 仅在实际修复时说明修改范围、必要验证和保留内容的承接情况。

这些是报告应表达的信息，不强制固定表格或独立日志。没有发现问题时直接说明实际范围和结果，未核验部分仍如实保留。

## 校验

交付前按本轮范围及适用条件确认；不适用项目不强制执行，无法核验的项目明确限制，不视为已经通过：

- [ ] 审核范围、实际覆盖与结论相称，范围外发现没有自动扩大任务。
- [ ] 范围内适用的关键主张已主动定向核验，或已列明未完成部分及原因；确认错误、证据不足和未核验没有混淆。
- [ ] 来源记录一致未被当作事实正确；涉及的具体引用编号已按原件核验，或已明确哪些仍待核。
- [ ] 深度问题指出具体缺失及影响，相关页面的承接和条件差异经过实际核对。
- [ ] 已主动检查未提及的必要知识；候选缺口经过必要性判断与定向查找。
- [ ] 发现包含位置、依据、影响和最小建议，规范问题与可选优化分开。
- [ ] 如有修复，授权、修改范围、必要验证和知识承接均已说明。
- [ ] 未把机械检查或阅读检验表述成正式评测，未凑缺陷或给出无依据总分。
