# Skill Creator

## 1. 任务与设计目标

创建或修改 Skill，让执行者知道何时使用、怎样完成任务、怎样判断结果。

## 2. 使用边界

用于新建或修改 Skill；执行其业务任务不属于本 Skill。

## 3. 输入设计

修改前读取现有两份文档及相关材料。目标或流程存在无法从对话解释的冲突时，说明差异并询问；本轮已确认但尚未同步的改动按授权完成。缺少 README 时，先提出设计理解，不能把从实现反推的设计当成用户已经确认。

## 4. 原则设计

README、执行规范、辅助材料和交付说明都应直接、易懂：

- 先判断内容是否需要，再决定保留、合并、删除或移动，最后改措辞。只留影响任务理解或执行的信息，不复述通用常识。
- 同一要求放在最合适的位置；必要时简短引用，不在原则、步骤、输出和校验中反复展开。
- 用具体对象和动作说明要求。保留必要术语，首次出现时解释；不用抽象名词或英文包装简单意思。
- 按标准章节组织内容，各节各司其职，不为填充章节写空话。
- 新增限制应说明解决的需求或重要风险、预期改变的行为，以及是否已有其他规则或工具负责。迁移或删除权限、调用和写入规则前，核对实际实现。
- 简洁不能省掉关键条件、证据、失败处理或授权边界，也不设字数和压缩比例。

## 5. 工作流程设计

新建或改变设计时，先分析任务并与用户讨论，获准后写 README；用户确认当前 README 后，再实现 Skill。已有确认继续有效，不重走已完成阶段。用户明确要求的局部文字修改或实现修正，可在对应范围直接处理。

分析应回答：任务要解决什么问题，哪些动作决定结果，凭什么判断做得好。先给出判断和选择，再询问会改变目标、方法、成本或边界的问题。信息足够支持实现即可，不让用户填写设计问卷，也不编造量化阈值。

执行指令写清关键动作、判断依据和失败后的处理；例子用于解释难点，详细材料按需引用。格式与元数据要求见 [SKILL.md](SKILL.md)。

## 6. 输出设计

- `README.md` 说明任务、重要设计选择及理由，供讨论和维护使用。
- `SKILL.md` 提供完整执行指令，执行时无需先读 README。
- `references/` 保存只在特定步骤需要的材料；有实际用途才创建。

README 不逐步复述执行规范。两份文档可以保留各自读者需要的背景，但不维护两套完整流程。目录树仅在结构不易理解时提供。

README 按“任务与设计目标、使用边界、输入设计、原则设计、工作流程设计、输出设计、References 设计（可选）、校验设计、文件结构”组织；SKILL.md 按“任务、输入、原则、工作步骤、输出、校验”组织。章节固定，篇幅按需要安排；步骤可分小节。

## 8. 校验设计

完成后对照设计检查遗漏、矛盾、引用和范围，再逐段检查重复、含混术语与无用提醒。用与改动相关的代表性输入走查流程，尤其检查分支和停止条件。静态检查、场景推演、实际运行分别报告；文档写完整不代表真实任务已经通过。

本 Skill 的代表场景包括：只有模糊需求、只授权写 README、已确认设计后继续实现、局部修改、缺少 README、设计与实现冲突。按改动选择检查，不要求每次全部重跑。

## 9. 文件结构

本 Skill 包含 `README.md` 与 `SKILL.md`，没有独立辅助材料。
