# Skill Creator

## 1. 任务与设计目标

创建或修改 Skill，让执行者知道何时使用、怎样完成任务、怎样判断结果。

## 2. 使用边界

用于新建或修改 Skill；执行其业务任务不属于本 Skill。

## 3. 输入设计

任务需求、现有 README 与 SKILL.md、相关辅助文件，以及对话中已确认的设计和授权。缺少设计文档时，从实现中得出的设计只能作为待确认的理解。

## 4. 原则设计

README 供人理解设计取舍，SKILL.md 供模型执行；两者不各写一套完整流程。固定章节方便定位，不要求各节篇幅相同，也不要求换词重述同一内容。

内容取舍先于措辞润色。删去一段后仍能正确理解和执行，就不保留；必要的条件、证据和授权边界不能为了缩短而删掉。表达检查落实到执行规范中的写作与校验步骤。

## 5. 工作流程设计

新建或改变设计时，先分析任务并与用户讨论，获准后写 README；用户确认当前 README 后，再实现 Skill。已有确认继续有效，不重走已完成阶段。用户明确要求的局部文字修改或实现修正，可在对应范围直接处理。

设计先确定任务、关键动作和判断结果的依据，再编写执行步骤。新增或删除限制时核对现有规则和工具，避免重复约束或误删仍然必要的边界。

## 6. 输出设计

- `README.md` 说明任务、重要设计选择及理由，供讨论和维护使用。
- `SKILL.md` 提供完整执行指令，执行时无需先读 README。
- `references/` 保存只在特定步骤需要的材料；有实际用途才创建。

## 8. 校验设计

同时检查能否正确执行和是否容易读懂。授权分支重点覆盖只写设计、继续已确认实现及局部修改，防止越权或重复询问；文字检查逐段判断用途，不用字数代替质量。
