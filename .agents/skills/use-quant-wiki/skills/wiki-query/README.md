# Wiki 知识使用

## 1. 任务与设计目标

本能力属于 `use-quant-wiki` 包，保留内部名称 `wiki-query`。它直接阅读绑定的量化 Wiki，完成定位、解释、比较或分析，将已有知识用于当前应用问题。

主要交付是有正文依据、保留适用条件的答案。用户只需要位置时，交付最小充分的定位结果；需要理解或判断时，组织知识与推理，不停在页面清单。

| 关键问题 | 为什么影响结果 |
| --- | --- |
| 用有限上下文找到正文 | 预读全库索引会占用回答空间；按问题选主题 reference，再用文件名、别名和机制描述缩小范围。 |
| 读正文才能判定 | 标题与命中片段不能证明该页面回答了问题。 |
| 连接多页知识 | 前置、机制、比较、实现与验证可能分散在多页。 |
| 区分知识与当前应用条件 | 来源结论有模型、版本和配置边界，不能直接当成当前环境的测量结果。 |
| 区分未找到与未核实 | 检索失败、材料不可读与确认的知识缺口不能混淆。 |

质量目标是：读到实际处理问题的正文，形成所需答案，说明条件、关键依据和剩余未知，并向外层入口提供使用反馈材料。

## 2. 使用边界

用于使用已有 Wiki 知识完成定位、概念解释、机制说明、方法比较与分析。需要进一步研究实际问题、核验原始来源或验证方案时，由入口按需选择包内 [wiki-research](../wiki-research/SKILL.md)；明确的算子实现与优化使用包内 [wiki-kernel-writing](../wiki-kernel-writing/SKILL.md)。内部规范按显式相对路径读取，不依赖递归发现。

本能力按需读取 `/Users/xiao/Documents/Projects/quantwiki/wiki/` 的知识正文；SELF 只用于职责或覆盖判断，INDEX 不作为查询前置。不读取 `raw/`，不修改公共知识、来源、SELF 或源 Skill，不启动未随包下发的维护能力。原文核验需求与知识缺口交给入口处理，不能声称已经完成来源核查。

使用反馈由统一入口整合并写入 `/Users/xiao/Documents/Projects/quantwiki/query-feedback/`。本能力提供已读位置、结果、限制和改进依据，不自行再写一份反馈。

## 3. 输入设计

输入是当前问题、主题、方法或待分析表述，以及应用已知的模型、硬件、版本、配置、目标和约束。可限定子领域、页面集或回答粒度，不要求固定表单。

知识库位置固定为 `/Users/xiao/Documents/Projects/quantwiki`；应用目录不是知识库。入口传入本次所用包版本和快照位置，执行始终读取该快照中的内部规范。

## 4. 原则设计

1. **正文支持结论。** 标题、搜索片段和导航只用于定位；回答依据实际阅读的内容。
2. **条件随结论保留。** 区分来源报告、Wiki 整理、当前推理与应用已验证事实。
3. **逐步读取，按需连接。** 先定位文件和章节，再读足以判断的完整上下文；缺少哪层解释再补哪层，不为覆盖率扫描全库或加载全部 references。
4. **未找到与未核实分开。** 保留检索范围和访问限制，不用记忆补成 Wiki 的结论。
5. **反馈由入口负责。** 提供反馈材料，不修改公共知识，不重复写日志。

## 5. 工作流程设计

明确问题与绑定 → 直接定位或选择主题 reference → 检索文件和章节 → 阅读相关正文及必要关联 → 形成答案和反馈材料。

- 已知实际页面或章节时直接进入；只有主题或问题时，按 SKILL 中的简短选择表读取最相关的 reference。跨主题问题缺少另一部分时再补读，不遍历全部导航。
- Reference 提供适用问题、代表入口和检索线索，不是全库覆盖清单。先按文件名或限定目录搜索，只返回候选路径；再查候选页的标题与相关命中位置，读取包含定义、推理和条件的段落。
- 未命中时补查中英文名、别名、机制描述，再扩大到五类知识目录；不通过读取整份 INDEX、READING 或 LOG 寻找答案。路径失效时定向搜索并报告导航问题，不据此判定 Wiki 缺失。
- 已读且仍有效的段落直接复用；正文足以支持答案、条件和必要关系时停止扩展，不把整页读完作为完成要求。
- 按 [Wiki 链接规范](/Users/xiao/Documents/Projects/quantwiki/wiki/README.md#知识链接与页面身份) 解析正文链接，只使用实际存在且读到所需内容的页面与章节。
- 回答区分 Wiki 已支持的结论、当前条件下的推理及未核实部分；不能把代码分析或来源报告写成当前应用已运行验证。
- 知识不足时交代检索词与范围，形成供入口选择进一步研究的具体缺口。

## 6. 输出设计

围绕当前问题给出答案、比较或分析，保留关键来源条件和可点击的绝对路径依据。只请求定位时，每条结果包括实际文件、章节和该处处理的问题。

同时向统一入口提供任务摘要、已读位置、结果摘要、限制及有依据的改进建议；无缺口时如实说明。内部能力不单独保存检索日志、覆盖矩阵或反馈文件。

## 7. References 设计

`references/` 保存五份短导航：量化方法、模型与缓存、部署系统、GPU 算子、误差与评测。每份只给代表性正文入口、选择理由和检索词；不搬入知识正文、完整页面目录或全部阅读路径。SKILL 保留选择条件与相对路径，执行时只读当前需要的一份，必要时跨主题补充。

知识页面继续位于绑定 Wiki。新增普通页面无需同步扩充 references；只有代表入口、检索方式或主题边界发生变化时才维护相应导航。未列入的知识通过检索找到，不能据 reference 的覆盖判断整个 Wiki 是否有内容。references 随完整能力包发布与快照，不在使用端改写。

## 8. 校验设计

静态检查 README 与 SKILL 的边界、步骤和交付一致，外部知识使用绑定绝对路径，包内调用使用明确相对路径，不残留仅定位的限制或未下发能力依赖。

场景检查包括：已知页面跳过导航、宽泛问题选择相关 reference、导航未列出的方法通过别名检索找到、跨主题补读、材料不可读。检查实际读取路径是否绕过整份 INDEX，是否只加载必要导航和正文，以及答案是否仍有充分依据。实际知识使用需有已读正文及其支持的结果；场景推演不等于真实任务验证。
