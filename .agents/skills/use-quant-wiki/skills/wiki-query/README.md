# Wiki 查询

## 1. 任务与设计目标

根据应用问题找到并读懂量化 Wiki，交付定位、解释、比较或分析。只要求位置时给出入口；需要解释时不能只返回链接。

## 2. 使用边界

查询只读 Wiki 正文，不读取 raw 或修改公共内容。需要原始材料或进一步求解时，由入口选择研究能力。反馈交入口统一处理，本能力不另写日志。

## 3. 输入设计

当前问题、已知对象与条件；可以指定页面或回答深度。

知识库固定为 `/Users/xiao/Documents/Projects/quantwiki`。应用目录不是 Wiki；本能力使用统一入口准备的包快照。

## 4. 原则设计

标题和搜索结果用于定位，正文支持结论。保留来源条件，区分 Wiki 记载、当前推理和应用实测；未找到、不可访问与尚未核实分别说明。

## 5. 工作流程设计

已知页面直接读取。问题较宽泛时，先选一份主题 reference，再查文件、章节和必要正文。内容不足时才补关联页，足以支持回答和适用条件时停止。这样控制上下文开销，同时保留完整解释所需的前提。

## 6. 输出设计

交付所需答案和正文位置，向入口提供结果、限制与改进依据。

## 7. References 设计

五份 references 分别覆盖量化方法、模型与缓存、部署系统、GPU 算子、误差与评测。它们只给代表入口和检索词，不是完整目录，也不代表 Wiki 的全部覆盖。未列出的内容通过名称、别名或机制检索；普通新页面不必加入导航。

执行方法和导航入口见 [SKILL.md](SKILL.md)，references 随完整包发布。代表入口或检索方式改变时更新对应 reference，不复制整份 INDEX。

## 8. 校验设计

用实际问题检查：已知页面能否直达，宽泛问题能否选对入口，未列入导航的内容能否搜到，跨主题问题能否补足解释，材料不可读时是否保留限制。答案必须有已读正文支持；只走查流程不能证明查询效果。

## 9. 文件结构

设计见本 README，执行见 `SKILL.md`，五份主题导航位于 `references/`。
