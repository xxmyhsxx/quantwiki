# 算子编写

将参考实现写成 CUDA/Triton 算子，或优化已有算子。目标是交付当前探索中表现最好、且经过验证的实现。“最好”只针对本次硬件、输入和评测条件，不表示全局最优，也不保证超过基线。

## 关键设计

| 要解决的问题 | 方法及理由 |
| --- | --- |
| 实现是否保持算子语义 | 先读参考实现、调用和测试，确定输入输出、数值要求及必须支持的输入范围。高层代码的执行结构可以改变，语义不能擅自改变。 |
| 性能数字是否可信 | 每版先编译，再检查正确性，最后测速。基线也须正确、测量有效；所有比较使用相同协议。 |
| 下一轮该改什么 | 用当前结果提出具体假设；性能数据不足以解释瓶颈时再做 Profiling。每次主要改动要有可测的预期。 |
| 失败尝试是否破坏已有成果 | 分别记录最新尝试和当前最佳实现，保留失败、回退及其代码版本。 |
| 何时结束、怎样交付 | 根据目标、预算、收敛或阻塞停止探索；交付前对最佳实现的确切版本重新执行正式正确性检查和测速。 |

参考实现用于确定正确结果，基线用于性能比较，两者可以不同。基线符合交付要求时可作为初始最佳实现；否则最佳实现可以暂时为空。多个输入条件都重要时，按任务约定判断整体改进。

## 使用范围与材料

适用于实际算子开发、融合、布局和执行策略优化。概念解释、代码阅读、静态评审及纯框架层优化不自动进入开发流程。缺少环境或参考实现时，先判断任务是否包含补齐条件；无法补齐则报告阻塞。

本能力随 use-quant-wiki 发布，规范来自入口固定的包快照。代码、工具、GPU 和实验记录由应用项目提供。入口在执行前可整理 Wiki 知识；算子迭代中只使用已准备材料、项目内容和可用工具，不再查询外部 Wiki。

当前目录只有 README 和 SKILL，没有随附 references 或脚本。可复用的优化资料或工具以后按实际需要加入，并在相关步骤注明何时使用。材料缺失是否阻塞工作，取决于当前项目和工具能否支持继续推进。

## 记录与结果

沿用项目已有记录方式，保存任务条件、各版实现及结果、当前最佳实现。记录应能恢复代码并核对编译、正确性、性能和必要的 Profiling 证据；实验结束即记录，失败也保留。

最终结果包括实现、复核入口、相对基线的表现、关键实验、停止原因和限制。停止探索与最终验证通过分别说明；无法完成最终验证时交付已有代码和证据，不沿用历史最好数字冒充最终测量。

反馈材料交统一入口，本能力不修改公共 Wiki 或单独写反馈。完整动作、评测条件和失败处理见 [SKILL.md](SKILL.md)。

## 维护检查

重点检查：编译或正确性失败后是否阻止测速；回退版本是否覆盖最佳结果；输入条件或协议变化后是否重新验证；预算耗尽及最终评测失败时是否如实交付。

其他代表场景包括：首个合格实现慢于基线、基线不满足交付要求、需要 Profiling 但工具不可用、缺少随包材料、从非最佳版本探索。按改动选择场景，不要求每次重跑全部案例。文档走查与真实算子运行分别报告。
