# Wiki 研究

结合量化 Wiki 解决应用问题：解释现象、比较路线、设计或验证方法。交付有依据的答案、方案或进展；已有知识足够时直接使用，不要求每次产生新知识。

## 怎样推进问题

先明确要回答什么、条件是什么，以及什么结果足以回答问题。当前缺口决定下一步：

| 缺少什么 | 下一步 |
| --- | --- |
| 概念、机制或实现知识 | 定向查资料或源码 |
| 从已有知识到当前问题的推理 | 检查前提并推导 |
| 模型、配置、输入或现象信息 | 获取配置、观测和记录 |
| 假设或方案的效果证据 | 选择能检验它的对照或实验 |

缺口可以并存，先解决影响后续方向的一项。每次行动都应减少关键未知；根据结果继续、改方案或结束。效果改善不能自动证明所猜机制，多因素变化和局部收益需要分别判断。

## 与其他能力的分工

从入口固定的包快照读取 [wiki-query](../wiki-query/SKILL.md) 使用知识，或读取 [wiki-kernel-writing](../wiki-kernel-writing/SKILL.md) 开发算子。查询按需进入正文，不预读整份导航；原始核验按具体问题读取来源，保留版本。

Wiki 固定为 `/Users/xiao/Documents/Projects/quantwiki`。代码、环境和实验记录属于应用项目；服务器与 GPU 由当前任务确定。算子迭代开始前准备知识，执行中不追加外部 Wiki 查询。

用户只要求分析或方案时，研究到相应深度，不自动运行实验。公共知识与源 Skill 的修改交维护端；本能力向入口提供已读位置、结果和具体改进依据，由入口统一回传。

## 结果与检查

答案说明依据、条件、实际验证和剩余未知；需要复现时提供代码、配置和结果位置。猜想保留为开放问题，材料或环境受限时说明已有进展和恢复条件。

维护本 Skill 时，按改动选择代表场景：知识已经充分、配置未知、材料不可读、结果否定假设、存在混杂因素、实验受阻、需要算子开发。检查行动是否推进原问题、结论是否超出证据。执行步骤见 [SKILL.md](SKILL.md)，真实研究效果仍需真实任务验证。
