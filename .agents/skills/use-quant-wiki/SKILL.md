# 使用量化 Wiki

## 任务

你是量化 Wiki 能力包的统一入口。根据当前任务，直接使用原 Wiki 的知识和包内方法，完成应用问题，并向 Wiki 维护端回传一份使用反馈。用户要求外派时，实际安装完整能力包。

本包只发布一个统一版本。内部 Skill 通过明确文件路径读取，不要求使用环境将它们识别为独立入口。

## 输入

从当前对话、应用工作区及已有配置取得目标、约束、交付物和已有观察。信息明确时直接使用；只补充会影响任务执行的缺项。

读取本入口所在目录的 `package.json`，取得 `bindings`、版本、内容标识和内部能力路径。当前发布绑定为：

- 知识库：`/Users/xiao/Desktop/量化`。
- 源包：`/Users/xiao/Desktop/量化/.agents/skills/use-quant-wiki`。
- 反馈目录：`/Users/xiao/Desktop/量化/query-feedback`。

镜像保持发布绑定，不从应用当前目录猜测 Wiki 位置。应用代码、环境、模型、GPU、服务器与结果路径由当前应用任务确定。

用户提供外部项目地址并要求安装、接入或外派时，进入 Step 2。本机目录解析为实际绝对路径；仓库 URL 或服务器地址需要对应可读写的接收工作区。缺少接收路径或连接信息时，明确缺项，不把 URL 当成目录，不臆造服务器路径。

## 原则

1. **直接读知识。** 基于实际正文及必要关联形成回答，保留来源版本、适用条件和证据边界；标题命中与链接存在不能替代阅读。
2. **整个包核对。** 只有发布清单与完整内容一致的源包可供安装和更新，不下发正在修改的草稿。
3. **保留项目内容。** 安装只操作该包目录；同名其他来源或项目定制内容保留并报告，不直接覆盖。
4. **任务固定版本。** 开始前检查更新，后续入口、内部规范和随包材料均从完整任务快照读取。安装镜像更新不能改变既有任务快照。
5. **分清落点。** 应用代码和运行记录归应用；知识和共享方法的修改交 Wiki 维护任务，本入口只新增反馈。
6. **结果对应证据。** 区分文件已安装、Wiki 可访问、工具验证与实际能力运行。只列命令、只复制入口或创建空目录不能称为外派成功。

## 工作步骤

### Step 1：核对当前包和调用方式

同一任务已经记录完整快照时，读取原快照继续执行，不因续接重新同步或创建另一份快照。新任务才重新核对发布状态。

将 `quantwiki_package` 设置为本次入口文件所在目录的实际绝对路径。后续命令中的同名变量指这个目录，不能固定为源包而忽略正在使用的镜像。先读取包清单，再执行随包工具：

```sh
python3 -B "$quantwiki_package/scripts/package.py" --package "$quantwiki_package" status
```

查看 JSON 结果中的 `state`、`local_state`、`source_state` 及进程退出状态，分别判断本地包、安装记录和绑定源包是否有效。`status` 是状态查询，退出成功也可能表示观测到 `outdated` 或 `customized`，不能仅凭退出状态认为当前包可用：

- 本地和源端版本及内容一致：继续。
- 本地是干净旧镜像，源端为有效新发布：在已有接入约定授权保持同步时，按 Step 2 更新整个包，然后重新读取新入口与清单。
- 本地内容或清单已经修改：保留并交付差异，作为项目定制版处理。未经当前任务明确采用定制内容，不将其作为有效发布镜像继续执行。
- 不同来源、同版本不同发布身份或源版本倒退：保留原包，停止自动替换，说明具体差异，不宣称已确认最新。
- 本地内容有效但没有安装来源记录：按接入授权核对与有效源包完全一致后建立安装记录；无法核实时说明来源尚未确认。
- 源端未发布或清单与内容不符：不复制；已有有效安装可继续使用，说明本次未采用源端草稿。
- 源端不可访问：有效安装可继续使用，说明无法确认最新状态；绑定 Wiki 不可读时不能完成依赖知识的部分。
- 本地无有效发布或安装内容不完整：说明具体缺项，先修复接入；不能用损坏内容宣称正常执行。

源端改动由维护者验证后发布。本入口不能通过重新生成清单把未知修改变成已发布内容。

### Step 2：按明确请求外派或更新

用户仅要求知识使用时不安装外部项目。用户已提供清楚目标和外派要求时，读取接收项目已有协作约定，并在授权范围内实际创建和复制，无需再次询问相同授权。

将 `quantwiki_project` 设置为接收项目的实际绝对路径。执行：

```sh
python3 -B "$quantwiki_package/scripts/package.py" --package "$quantwiki_package" install --project "$quantwiki_project"
```

默认安装到项目的 `.agents/skills/use-quant-wiki/`。工具创建缺少的目录、复制完整已发布源包、生成该项目安装记录并核验；不初始化 Git 或改写应用说明。同内容重复安装应复用原包。明确授权干净旧镜像更新时加 `--allow-update`；这个参数不能用于覆盖项目定制内容或其他来源。

读取工具实际输出，再从目标目录重新读取入口和清单，检查各内部 `SKILL.md` 可读且包内路径正确。执行目标中的 `verify` 和 `status`，核对目标实际文件、版本、内容和安装来源。

分别报告包安装结果和绑定 Wiki 的可访问性。工具或权限失败时核对实际已完成部分，交付具体路径、错误与剩余缺项。不能仅因复制命令发出而宣称完成。

仅外派请求至此交付安装结果，不制造知识使用反馈。还需完成应用任务时，进入 Step 3。

### Step 3：建立本次任务快照

当前包有效且更新判断完成后，选择应用已有任务目录中的唯一快照位置；没有约定时使用应用下的 `.agents/skill-snapshots/use-quant-wiki/` 加唯一任务标识。将其实际绝对路径设置为 `quantwiki_snapshot`，该目录必须尚不存在：

```sh
python3 -B "$quantwiki_package/scripts/package.py" --package "$quantwiki_package" snapshot --output "$quantwiki_snapshot"
```

核对快照输出和完整文件，记录发布版本、内容标识、快照路径及本次是否确认源端最新。重新读取快照的入口、清单与所需内部规范，此后只使用快照中的方法和脚本。Wiki 正文仍从绑定位置直接读取；快照固定的是方法包，正文阅读范围和证据另外记录。

并行调用更新安装镜像后，不刷新当前任务快照，不从最新安装目录混读其他内部材料。下一个任务重新检查版本。

### Step 4：选择内部能力并完成应用任务

按实际需要读取以下规范，路径均相对于本次完整快照：

| 当前需要 | 读取的内部规范 |
| --- | --- |
| 定位、解释、比较或分析已有知识 | [wiki-query](skills/wiki-query/SKILL.md) |
| 解释现象、比较路线、设计或验证方法 | [wiki-research](skills/wiki-research/SKILL.md) |
| 实现或优化 CUDA/Triton 算子 | [wiki-kernel-writing](skills/wiki-kernel-writing/SKILL.md) |

知识使用读取绑定 Wiki 的根 `SELF.md`、`wiki/INDEX.md`、`wiki/README.md`，再按目标阅读相关正文和必要关联。普通知识使用不读取 `raw/`；研究确需核验来源时明确范围和版本。

研究按问题求解，必要时显式读取包内知识使用或算子规范。应用镜像没有 `wiki-ingest`、`wiki-review`、`wiki-prune` 和 `skill-creator`，不得调用未随包下发的兄弟目录。需要修改公共知识或共享方法时形成反馈，交维护任务处理。

算子任务可以在准备阶段按需使用 Wiki；进入编译、正确性、Benchmark 和假设迭代后，遵循完整算子规范及应用环境，不在执行循环中插入外部 Wiki 查询。缺少硬件或评测条件时交付具体阻塞和已有验证，不能把静态分析称为实测完成。

同一任务需要多项能力时按依赖组合，不默认加载全部材料。内部能力提供实际阅读、结果、限制和改进建议，由本入口统一整合反馈。

### Step 5：新增一份使用反馈

一次知识使用、研究或执行调用结束后，将反馈整理成 JSON 文件，存入应用已有任务目录。必需字段为 `task_id`、`task_summary`、`capabilities_used`（实际使用的包内能力名称数组）、`knowledge_locations`（已读知识绝对路径数组，可空）、`result_summary`；`limitations` 和 `suggestions` 使用数组。按实际需要附应用工作区和证据位置，实际实验保留代码版本及配置；没有发现知识缺口时如实记录，不复制业务代码或完整对话。

使用本次快照的工具提交：

```sh
python3 -B "$quantwiki_snapshot/scripts/package.py" --package "$quantwiki_snapshot" feedback --input "$quantwiki_feedback_input"
```

其中 `quantwiki_feedback_input` 是反馈 JSON 的实际绝对路径。工具在清单绑定的反馈目录唯一新建记录，附上本次包版本与内容标识；内部能力不分别写日志，不追加或覆盖既有反馈。反馈失败时交付原反馈文本和具体限制，说明未回传，不改写其他位置。成功后核对新增文件与内容。

反馈不自动修改正文、INDEX、SELF、共享 Skill 或包版本。

## 输出

应用任务交付实际答案、方案、实现或验证进展，说明 Wiki 知识的作用、包版本、所用能力、证据范围和剩余未知。算子等实际执行结果同时满足内部规范的交付要求。

外派交付实际项目根目录、安装路径、包版本、完整性核验、知识可访问性及安装记录。反馈交付实际新增路径；失败时交付文本和未回传状态。

## 校验

- 当前请求和接收位置明确，创建或更新均在已有授权范围内。
- 完整清单、内容和安装来源核对通过；定制或未知内容没有被覆盖。
- 任务使用完整快照，记录的版本与实际规范一致。
- 实际阅读了相关知识正文，应用环境没有被历史实验环境替代。
- 包内能力通过明确路径读取，没有依赖未下发维护 Skill。
- 一次调用至多新增一份反馈，结果和证据一致。
- 安装、知识访问、工具运行和应用实测分别核实与交付。
