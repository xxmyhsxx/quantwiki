# Wiki Research

## 1. 任务与设计目标

让 Wiki 参与真实研究：**判断已有知识是否够用，将知识转化为求解行动，根据证据修正判断，并反馈可复用的新认识。**

主要交付是问题的答案、有依据的方案或经过验证的结论。研究是否成功，取决于问题得到怎样的解决或推进；已有知识足够、无需新增页面，也可以完成研究。

本 Skill 需要保留三个核心能力：

- **判断缺什么。** 区分知识缺口、推理缺口、对象信息不足和证据不足，避免将所有问题都处理成继续读资料。
- **决定怎么做。** 用知识建立解释或方案，选择能解决关键未知的查证、推导或实验，并依据结果调整。
- **判断学到了什么。** 回到原问题评估结果，将可复用认识与特定实验记录分开处理。

## 2. 使用边界

用于结合 Wiki 研究具体问题、解释现象、比较技术路线、设计或验证方法。单纯定位、概念解释、指定论文入库、页面审查或明确的算子实现，使用其对应能力。

研究按本次要求完成到分析、方案或实际验证。理论问题可以通过推导回答，经验性主张需要相应观测或实验支持。知识回写按任务授权执行。

本 Skill 负责求解判断与结果整合。`wiki-query` 可用于定位，`wiki-ingest` 可承担论文知识整合，`wiki-kernel-writing` 可承担算子开发；按任务需要组合，具体执行规范由相应 Skill 承担。

## 3. 输入设计

从实际问题或现象，以及目标 Wiki 入口开始。按研究需要取得对象、已有观察、约束、比较基线、解决标准、材料、代码和可用资源。未知条件本身可能就是需要解决的缺口，不要求启动前备齐所有信息。

宽泛主题先收敛为能够由证据回答的问题。研究目标决定所需信息和验证深度。

## 4. 原则设计

- **以问题组织知识。** 阅读范围由求解需要决定，覆盖判断依据实际正文与适用条件。
- **让证据改变判断。** 关键假设应能被检验，负面结果也参与下一步决策。
- **区分效果与解释。** 方案达到目标，并不自动证明所猜机制；结论保留证据能够支持的范围。

## 5. 工作流程设计

| 环节 | 要形成的判断 | 设计理由 |
| --- | --- | --- |
| 明确问题 | 研究什么、条件是什么、怎样算回答了问题 | 为知识选择和结果判断提供共同标准 |
| 判断知识是否够用 | 已有知识能支持哪里，当前卡点属于哪类缺口 | 将不同缺口导向合适行动 |
| 求解与验证 | 解释或方案是否成立，下一步是否需要改变 | 将提出假设、采取行动、读取结果合成一个迭代过程 |
| 反馈知识 | 本次形成了什么值得复用的认识，应放在哪里 | 让研究经验改善知识，同时保留实验条件 |

### 缺口为什么要分四类

缺少机制或实现知识，需要查证；知识都有但尚未连接起来，需要推导；不知道当前模型、配置或现象，需要获取对象信息；知道原理但不清楚实际效果，需要验证。这些缺口可以并存，先解决决定后续方向的一项。

### 求解循环怎样保持有效

围绕关键假设和主要实验，说明依据、预期结果及可能推翻解释的观察；选择能够区分重要解释或验证方案的行动。普通检索和读取直接进行，无需逐次输出选择理由。

得到结果后，判断它支持或削弱什么，再决定继续、修改方案或结束。已达到本次解决标准时交付；仍有关键未知时继续有价值的行动；资源或材料阻塞时说明已取得的进展与恢复条件。

方案效果与机制归因分别判断。多个因素同时变化时，整体效果不能直接归因于单一因素。来源报告、推导、源码核对和实际实验也应保留各自的证据范围。

### 知识反馈保留什么

Wiki 承接可复用的机制、适用条件、方法联系、反例和有依据的修正；具体代码版本、配置和原始结果留在研究记录中。尚未成立的猜想如需保留，应作为开放问题说明依据与未知部分。

执行步骤和必要的验证要求集中在 [SKILL.md](SKILL.md)，本文件说明设计取舍。

## 6. 输出设计

交付原问题的答案或进展、关键依据与适用条件、实际验证范围、剩余未知，以及知识反馈状态。需要复现时提供对应实现、配置和结果的位置。

按任务复杂度组织结果，不设固定报告格式。

## 7. 校验设计

主要检查三件事：知识判断是否有正文依据，行动和证据是否推进了原问题，沉淀的结论是否超出验证范围。

修改 Skill 时，可用以下场景核对分支；它们是设计检查案例，不是每次研究的任务清单：

| 场景 | 应有的处理 |
| --- | --- |
| 知识充分，或知识分散在多页 | 直接组织答案，或补足推理连接 |
| 配置未知，或源码路径尚未确认 | 获取对象信息，区分代码存在与实际执行 |
| 材料不可读 | 保留未核实，不以访问失败断言知识缺失 |
| 实验改善效果但有混杂因素，或否定原假设 | 限定归因，依据结果修正解释 |
| 缺少实验环境或预算已到 | 交付实际进展、剩余未知和恢复条件 |
| 有新认识但只授权分析 | 提供具体拟补内容与位置 |

场景推演检查流程是否合理；实际研究效果需由真实任务验证。
